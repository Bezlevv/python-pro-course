Что такое run в MLflow?
- Один запуск эксперимента с логированием параметров, метрик и артефактов
- Папка с данными для обучения
- Версия Python
* Правильный ответ: Один запуск эксперимента с логированием параметров, метрик и артефактов
Run — это отдельный запуск обучения или инференса, в который MLflow записывает всё, что относится к этому запуску: параметры, метрики, артефакты, модель.

Чем параметры (params) отличаются от метрик (metrics) в MLflow?
- Параметры — это настройки модели, а метрики — результат её работы на данных
- Параметры — это числа с плавающей точкой, а метрики — целые
- Ничем
* Правильный ответ: Параметры — это настройки модели, а метрики — результат её работы на данных
Параметры (max_depth, learning_rate) задаются до обучения, а метрики (accuracy, r2) вычисляются по итогам и нужны для сравнения запусков.

Зачем нужен формат ONNX?
- Для переносимого представления модели, которое можно выполнять без исходного фреймворка
- Для хранения обучающих данных
- Для развёртывания веб-серверов
* Правильный ответ: Для переносимого представления модели, которое можно выполнять без исходного фреймворка
ONNX описывает модель как граф вычислений; onnxruntime исполняет этот граф быстро и без установки sklearn, PyTorch и т. д.

Какой тип данных ожидает вход модели в onnxruntime по умолчанию?
- float32 (np.float32)
- float64
- int64
* Правильный ответ: float32 (np.float32)
ONNX-модели почти всегда работают с float32 — это стандарт формата. Передача float64 часто вызывает ошибку, поэтому вход нужно приводить через .astype(np.float32).

Что вернёт FastAPI с Pydantic-моделью, если клиент передаст невалидные данные (например, age = 15 при ограничении ge=18)?
- HTTP 422 Unprocessable Entity с описанием ошибки
- HTTP 200 и предсказание
- Сервер упадёт с исключением
* Правильный ответ: HTTP 422 Unprocessable Entity с описанием ошибки
Pydantic автоматически валидирует тело запроса. Если данные не проходят ограничения, FastAPI возвращает 422 с деталями — без единой строчки твоего кода.

Что такое дрейф данных (data drift)?
- Изменение распределения входных данных модели после её запуска в продакшен
- Ошибка в коде сервиса
- Увеличение задержки ответа
* Правильный ответ: Изменение распределения входных данных модели после её запуска в продакшен
Данные в реальном мире меняются: пользователи, сезоны, рынок. Модель, обученная на старом распределении, начинает хуже работать — дрейф это фиксирует.

Какой порог PSI говорит о сильном дрейфе?
- PSI > 0.25
- PSI > 0.01
- PSI > 1.0
* Правильный ответ: PSI > 0.25
Классическая шкала: PSI < 0.1 — дрейфа практически нет, 0.1–0.25 — умеренный, > 0.25 — сильный дрейф, модель стоит проверить.

Что описывает DAG в Airflow?
- Порядок и зависимости выполнения задач пайплайна (ориентированный ациклический граф)
- Граф нейросети
- Схему базы данных
* Правильный ответ: Порядок и зависимости выполнения задач пайплайна (ориентированный ациклический граф)
Каждая задача — узел DAG, а стрелки показывают, что должно выполниться до чего. В DAG нет циклов: пайплайн всегда завершается.

Почему Airflow обычно «тяжелее» Prefect?
- Airflow требует отдельно работающих scheduler и webserver, а Prefect — это просто код с декораторами
- Airflow написан на C++
- Prefect не умеет запускать задачи
* Правильный ответ: Airflow требует отдельно работающих scheduler и webserver, а Prefect — это просто код с декораторами
Для Airflow нужен инфраструктурный «скелет» (scheduler + webserver + база), Prefect запускается из обычного скрипта и легче встраивается в проект.

Что означает p-value < 0.05 в A/B-тесте?
- Разница между группами статистически значима при уровне α = 0.05
- Модель переобучилась
- Выборка слишком маленькая
* Правильный ответ: Разница между группами статистически значима при уровне α = 0.05
p-value — вероятность получить такую разницу случайно, если на самом деле её нет. Если p < α, мы отклоняем нулевую гипотезу и считаем эффект значимым.

Что такое point-in-time (момент времени) в feature store?
- Значение фичи возвращается строго на момент запроса, а не из будущего, — это защищает от утечки данных
- Хранение фич только в памяти
- Отключение фич на время обучения
* Правильный ответ: Значение фичи возвращается строго на момент запроса, а не из будущего, — это защищает от утечки данных
Point-in-time корректность означает, что при обучении и инференсе фича берётся по состоянию на тот момент времени: никакой информации из будущего — иначе метрики будут завышены.
