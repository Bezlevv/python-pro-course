Языковые модели обучены на данных с фиксированной датой отсечки. Спроси «GPT-4o» про события вчерашнего дня — и она либо ошибётся, либо признается, что не знает. Но что, если дать модели _свои_ документы? Именно это делает **RAG** — Retrieval-Augmented Generation, генерация с дополнением контекстом.

## Проблема

База знаний LLM ограничена. У твоей компании есть свежие документы, базы знаний и внутренние инструкции, которые модель не видела. Решение — не переобучать модель, а подсовывать ей нужные фрагменты в момент запроса. Это дешевле, быстрее и всегда актуально.

## Схема RAG

Пайплайн состоит из трёх фаз:

1. **Индексация** — разбить документы на фрагменты (**чанки**), получить их эмбеддинги и положить в векторную базу;
2. **Поиск (retrieval)** — на запрос пользователя найти `k` самых близких чанков;
3. **Генерация** — отдать чанки модели как контекст вместе с вопросом.

Установим ChromaDB и sentence-transformers:

```bash
pip install chromadb sentence-transformers
```

## Фаза 1. Индексация

Чанкинг — разбиение текста на фрагменты. Делать это нужно по границам абзацев и предложений, иначе разрежешь мысль пополам. Минимальный вариант:

```python
def chunk_text(text, size=200):
    words = text.split()
    return [" ".join(words[i:i + size]) for i in range(0, len(words), size)]
```

Теперь индексация в ChromaDB:

```python
import chromadb
from sentence_transformers import SentenceTransformer

encoder = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
client = chromadb.Client()
collection = client.get_or_create_collection("docs")

chunks = chunk_text(doc_text)
collection.add(
    ids=[f"c{i}" for i in range(len(chunks))],
    embeddings=encoder.encode(chunks).tolist(),
    documents=chunks,
)
```

## Фаза 2. Поиск

ChromaDB умеет искать по векторам:

```python
query = "Как установить Python на Windows?"
results = collection.query(
    query_embeddings=encoder.encode([query]).tolist(),
    n_results=2,
)
for doc in results["documents"][0]:
    print(doc)
```

## Фаза 3. Генерация

Теперь соберём всё вместе — передадим найденные чанки модели как контекст:

```python
context = "\n".join(results["documents"][0])
prompt = f"""
Отвечай ТОЛЬКО на основе приведённого контекста.
Если в контексте нет ответа, скажи: «В контексте нет ответа».

Контекст:
{context}

Вопрос: {query}
"""
```

Системный промпт «отвечай только на основе контекста» — критически важен: без него модель начнёт фантазировать.

## Как улучшать RAG

- **Чанкинг умнее**: перекрывающиеся чанки, разбиение по абзацам.
- **Хайбридный поиск**: векторный + по ключевым словам (BM25).
- **Реранкинг**: пересортировка найденного более сильной моделью.
- **Метаданные**: храни источник и страницу, чтобы цитировать.
- **Проверка релевантности**: отбрасывай слишком далёкие чанки по порогу близости.

### Разбор 1
```python
def chunk_text(text, size=40):
    words = text.split()
    return [" ".join(words[i:i + size]) for i in range(0, len(words), size)]

text = ("Python — высокоуровневый язык программирования с динамической типизацией. "
        "Он поддерживает несколько парадигм: процедурную, объектно-ориентированную "
        "и функциональную. Благодаря простому синтаксису Python часто используется "
        "как первый язык для обучения программированию.")
chunks = chunk_text(text)
print("Чанков:", len(chunks))
print(chunks[0])
```

Функция берёт все слова и собирает их группами по `size`. Слова никогда не разрываются, потому что мы режем по пробелам, а не по символам. Для простого прототипа этого достаточно. В проде чанкинг сложнее: учитывают абзацы, предложения и делают перекрытие, чтобы мысль не «разрезалась» между чанками — иначе поиск может не найти нужный фрагмент.

### Разбор 2
```python
import chromadb
from sentence_transformers import SentenceTransformer

encoder = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
client = chromadb.Client()
collection = client.get_or_create_collection("my_docs")

chunks = [
    "Циклы for и while позволяют повторять действия несколько раз.",
    "Списки хранят много элементов в определённом порядке.",
    "Функции группируют код и позволяют переиспользовать его.",
]
collection.add(
    ids=["c0", "c1", "c2"],
    embeddings=encoder.encode(chunks).tolist(),
    documents=chunks,
)
print(collection.count())  # 3
```

`chromadb.Client()` создаёт встроенную (in-memory) базу — ничего устанавливать отдельно не нужно. `collection.add` принимает три параллельных списка: `ids`, `embeddings` и `documents`. Эмбеддинги мы считаем заранее через sentence-transformers и передаём как `.tolist()` — ChromaDB принимает списки Python, а не NumPy-массивы. `collection.count()` возвращает число элементов — полезно для самопроверки.

### Разбор 3
```python
def retrieve(query, k=2):
    results = collection.query(
        query_embeddings=encoder.encode([query]).tolist(),
        n_results=k,
    )
    return results["documents"][0]

print(retrieve("как перебирать элементы по одному"))
```

ChromaDB сам находит ближайших соседей по косинусной близости и возвращает `documents` — список текстов, отсортированный по убыванию близости. Первым будет чанк про циклы: «перебирать элементы по одному» — это буквально цикл. Вторым, скорее всего, списки. Так работает сердце RAG: поиск не по буквам, а по смыслу.

### Разбор 4
```python
import os
import requests

def rag_answer(query):
    hits = retrieve(query)
    context = "\n".join(hits)
    system = ("Ты — ассистент, отвечающий на основе документов. "
              "Отвечай ТОЛЬКО на основе приведённого контекста. "
              "Если в контексте нет ответа, скажи: «В контексте нет ответа».")
    user = f"Контекст:\n{context}\n\nВопрос: {query}"
    resp = requests.post(
        "https://api.openai.com/v1/chat/completions",
        headers={"Authorization": f"Bearer {os.environ['OPENAI_API_KEY']}"},
        json={
            "model": "gpt-4o-mini",
            "messages": [
                {"role": "system", "content": system},
                {"role": "user", "content": user},
            ],
            "temperature": 0.2,
        },
        timeout=60,
    )
    resp.raise_for_status()
    return resp.json()["choices"][0]["message"]["content"]

print(rag_answer("как перебирать элементы по одному"))
```

Ключевая строка — системный промпт с запретом отвечать вне контекста. Он превращает модель из «всезнайки» в аккуратного исполнителя, который не выдумывает. Температура 0.2 — чтобы ответы были стабильными. Такой пайплайн легко масштабировать: заменишь документы — сменится база знаний без переобучения модели.

### Разбор 5
```python
def plain_answer(query):
    resp = requests.post(
        "https://api.openai.com/v1/chat/completions",
        headers={"Authorization": f"Bearer {os.environ['OPENAI_API_KEY']}"},
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "user", "content": query}],
            "temperature": 0.2,
        },
        timeout=60,
    )
    resp.raise_for_status()
    return resp.json()["choices"][0]["message"]["content"]

q = "как перебирать элементы по одному"
print("БЕЗ КОНТЕКСТА:")
print(plain_answer(q))
print("С КОНТЕКСТОМ:")
print(rag_answer(q))
```

Ответ без контекста будет общим: «можно использовать цикл for...». Ответ с контекстом возьмёт формулировки из наших чанков, например «повторять действия несколько раз». Разница наглядно показывает ценность RAG: мы получили ответ, основанный на конкретном документе, а не на общем знании модели. Именно так строятся корпоративные чат-боты, которые «знают» внутренние регламенты компании.
