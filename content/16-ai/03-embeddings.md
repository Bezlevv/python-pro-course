Компьютер не понимает смысл слов. Но чтобы искать «по смыслу», а не по буквам, нужен способ превратить текст в числа, которые сохраняют семантику. Эту задачу решают **эмбеддинги** (embeddings).

## Что такое эмбеддинг

Эмбеддинг — это вектор из чисел (например, 384 или 1536 чисел), который кодирует смысл текста. Ключевое свойство: у близких по смыслу текстов векторы оказываются **близкими в пространстве** (маленькое расстояние), у разных — далёкими. Эмбеддинги получают специальные модели — энкодеры.

Устанавливаем библиотеку:

```bash
pip install sentence-transformers
```

## Первый эмбеддинг с sentence-transformers

Библиотека `sentence-transformers` даёт готовые модели, понимающие сотни языков:

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

texts = ["Я люблю Python", "Мне нравится программировать"]
vectors = model.encode(texts)
print(vectors.shape)  # (2, 384) — 2 текста по 384 числа
```

Каждый из 384 элементов вектора — координата в многомерном пространстве. Сама по себе координата ничего не значит, но их совокупность описывает позицию текста.

## Косинусная близость

Близость векторов измеряют **косинусной близостью** — косинусом угла между векторами. Значение от -1 до 1: 1 — одинаковое направление (очень похоже), 0 — перпендикулярны, -1 — противоположны:

```python
import numpy as np

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

print(cosine_similarity(vectors[0], vectors[1]))  # близко к 1
```

Чем ближе результат к 1, тем ближе смысл. Это и есть математическая основа семантического поиска.

## Поиск ближайших соседей

С простым списком текстов поиск делается вручную:

```python
def search(query, corpus, k=3):
    q_vec = model.encode([query])[0]
    scores = [(cosine_similarity(q_vec, model.encode([t])[0]), t) for t in corpus]
    scores.sort(key=lambda x: x[0], reverse=True)
    return scores[:k]
```

Для реальных объёмов такой перебор слишком медленный — нужны специализированные структуры.

## Векторные базы данных

**Векторная база данных** хранит векторы и умеет быстро находить ближайших соседей. Технологии оптимизируют поиск через специальные индексы (например, HNSW). Самые популярные варианты:

- **ChromaDB** — лёгкая, встраиваемая, удобна для Python-проектов;
- **FAISS** (Facebook AI Similarity Search) — высокопроизводительная библиотека от Meta;
- также: Qdrant, Weaviate, Milvus, pgvector для PostgreSQL.

Работа с ними в Python однотипна: добавляешь документы с эмбеддингами, затем запрашиваешь `query` и получаешь ближайшие элементы. Подробно поработаем с ChromaDB в уроке про RAG.

## Батч-обработка и нормализация

Кодируй тексты пакетами — это в разы быстрее, чем по одному: `model.encode(texts)` принимает список. Многие модели умеют **нормализовывать** векторы (длина = 1), что упрощает формулу косинуса до скалярного произведения — это ускоряет вычисления.

### Разбор 1
```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
texts = ["Я люблю программировать на Python", "Python — мой любимый язык"]
vectors = model.encode(texts)

print("Форма:", vectors.shape)

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

print("Близость:", cosine_similarity(vectors[0], vectors[1]))
```

Форма `(2, 384)` означает: два вектора по 384 измерения. Модель `paraphrase-multilingual-MiniLM-L12-v2` — компактная многоязычная (поддерживает русский), её векторы из 384 чисел. Фразы почти одинаковы по смыслу, поэтому косинусная близость будет выше 0.9. Если бы мы сравнили «Я люблю Python» и «Сегодня идёт дождь», близость была бы заметно ниже. Именно это свойство делает эмбеддинги инструментом поиска по смыслу.

### Разбор 2
```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
corpus = [
    "Кошка спит на диване",
    "Собака бегает в парке",
    "Я заказал пиццу",
    "Кот громко мяукает",
    "Птицы поют утром",
]
query = "домашнее животное"

q_vec = model.encode([query])[0]
vectors = model.encode(corpus)

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

scores = [(cosine_similarity(q_vec, v), text) for v, text in zip(vectors, corpus)]
best_score, best_text = max(scores)
print(best_text, best_score)
```

Мы кодируем корпус одним вызовом — это быстрее и аккуратнее, чем цикл с отдельными вызовами. Затем для каждого вектора считаем близость к запросу. Фразы «Кошка спит на диване» и «Кот громко мяукает» получат самые высокие баллы, потому что кошки — домашние животные. Обрати внимание: «Собака бегает в парке» тоже близка, но обычно чуть ниже — собака тоже домашнее животное, всё зависит от конкретной модели.

### Разбор 3
```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

corpus = [
    "Переменные хранят значения в памяти",
    "Циклы позволяют повторять действия",
    "Функции группируют код и переиспользуются",
    "Списки хранят много элементов по порядку",
    "Словари хранят пары ключ-значение",
    "Классы описывают объекты с данными и методами",
    "Исключения обрабатывают ошибки",
    "Декораторы изменяют поведение функций",
]

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

def semantic_search(query, corpus, k=3):
    q_vec = model.encode([query])[0]
    vectors = model.encode(corpus)
    scores = [(cosine_similarity(q_vec, v), text) for v, text in zip(vectors, corpus)]
    scores.sort(key=lambda x: x[0], reverse=True)
    return scores[:k]

for score, text in semantic_search("как хранить много данных в одной переменной", corpus):
    print(round(score, 3), text)
```

Фраза про списки и словари окажется в топе, поскольку оба «хранят много данных». Сортировка по убыванию легко делается `sort(key=lambda x: x[0], reverse=True)`. Это минимальная реализация семантического поиска: она работает на маленьких объёмах, но уже показывает идею. Для тысяч и миллионов документов такой перебор станет медленным — там на смену приходят векторные БД с индексами.

### Разбор 4
```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
a, b = model.encode(["Я люблю Python", "Мне нравится программировать"])

def normalize(v):
    return v / np.linalg.norm(v)

a_n, b_n = normalize(a), normalize(b)
cos_orig = np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
cos_normalized = np.dot(a_n, b_n)

print("Косинус (обычный):", cos_orig)
print("Скалярное произведение нормализованных:", cos_normalized)
```

После нормализации длина каждого вектора равна 1, поэтому знаменатель формулы косинуса превращается в 1, и остаётся только скалярное произведение. Две цифры совпадут с точностью до плавающей ошибки. Зачем это нужно? Векторные базы и поисковые движки хранят нормализованные векторы — тогда вместо деления достаточно одного умножения, что заметно ускоряет поиск на больших массивах.

### Разбор 5
```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")
corpus = [
    "Переменные хранят значения в памяти",
    "Циклы позволяют повторять действия",
    "Функции группируют код и переиспользуются",
    "Списки хранят много элементов по порядку",
    "Словари хранят пары ключ-значение",
    "Классы описывают объекты с данными и методами",
    "Исключения обрабатывают ошибки",
    "Декораторы изменяют поведение функций",
]
query = "машина для передвижения"

substring_hits = [t for t in corpus if query.lower() in t.lower()]
print("Подстрочный поиск:", substring_hits)

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

q_vec = model.encode([query])[0]
vectors = model.encode(corpus)
scores = [(cosine_similarity(q_vec, v), t) for v, t in zip(vectors, corpus)]
scores.sort(key=lambda x: x[0], reverse=True)
print("Семантический топ-3:", [(t, round(s, 3)) for s, t in scores[:3]])
```

Подстрочный поиск вернёт пустой список: в корпусе нет слов «машина» или «передвижения». А вот семантический поиск поймёт, что «машина для передвижения» по смыслу близка к «Циклы позволяют повторять действия» (машина — цикл, итерация) и к «Переменные хранят значения» (программа движется от переменной к переменной). Именно эта разница — главный аргумент в пользу эмбеддингов: они ловят смысл, а не буквальные совпадения.
