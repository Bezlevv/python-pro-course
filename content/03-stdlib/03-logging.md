Когда программа маленькая, для отладки хватает `print()`. Но в реальном проекте нужно знать не только «что произошло», но и когда, насколько это серьёзно, и куда записать событие. Для этого в Python есть модуль `logging` — встроенная система журналирования.

## Уровни логирования

Каждое сообщение имеет уровень важности. По возрастанию: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. По умолчанию выводятся сообщения от `WARNING` и выше — то есть `DEBUG` и `INFO` по умолчанию скрыты:

```python
import logging

logging.debug("Отладка")          # не выведется (уровень ниже WARNING)
logging.info("Программа запущена") # не выведется
logging.warning("Мало места на диске")
logging.error("Ошибка чтения файла")
```

Результат:

```
WARNING:root:Мало места на диске
ERROR:root:Ошибка чтения файла
```

## Настройка basicConfig

Функция `basicConfig` задаёт уровень, формат и место вывода. В формате используются плейсхолдеры: `%(asctime)s` — время, `%(levelname)s` — уровень, `%(message)s` — сам текст:

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)s | %(message)s",
)

logging.info("Старт программы")
logging.warning("Внимание: мало места")
```

Теперь `INFO`-сообщения видны, и у каждой строки есть временная метка.

## Логгеры и обработчики

Глобальная настройка удобна в маленьких скриптах, но в больших проектах используют именованные логгеры — по одному на модуль:

```python
import logging

logger = logging.getLogger("my_app")
logger.setLevel(logging.DEBUG)

handler = logging.FileHandler("app.log", encoding="utf-8")
handler.setFormatter(logging.Formatter("%(asctime)s | %(levelname)s | %(message)s"))
logger.addHandler(handler)

logger.info("Это уйдёт и в файл app.log")
```

Обработчик (`handler`) решает, куда писать: в консоль (`StreamHandler`), в файл (`FileHandler`) или куда-то ещё. Можно добавить несколько обработчиков — например, в файл и на консоль одновременно.

## Логирование ошибок

В блоке `except` используй `logger.exception(...)` — он запишет сообщение с уровнем `ERROR` и добавит полный след исключения (traceback):

```python
logger = logging.getLogger("my_app")

try:
    1 / 0
except ZeroDivisionError:
    logger.exception("Деление на ноль")
```

Ещё один нюанс: не подставляй значения в текст через f-строки, если в этом нет необходимости. Лучше передавать их аргументами: `logger.info("Пользователь %s зашёл", user)` — форматирование произойдёт только если сообщение действительно будет выведено, а это быстрее.

### Разбор 1
Одно из возможных решений:

```python
import logging

logger = logging.getLogger("calc")
logger.setLevel(logging.INFO)

formatter = logging.Formatter("%(asctime)s | %(levelname)s | %(message)s")

console = logging.StreamHandler()
console.setFormatter(formatter)

file_handler = logging.FileHandler("calc.log", encoding="utf-8")
file_handler.setFormatter(formatter)

logger.addHandler(console)
logger.addHandler(file_handler)

logger.info("Калькулятор запущен")

while True:
    line = input("Введи выражение (например, 10 + 5) или 'выход': ").strip()
    if line.lower() == "выход":
        logger.info("Работа завершена")
        break

    parts = line.split()
    if len(parts) != 3:
        logger.warning(f"Непонятный ввод: {line!r}")
        continue

    try:
        a, op, b = float(parts[0]), parts[1], float(parts[2])
        if op == "+":
            result = a + b
        elif op == "-":
            result = a - b
        elif op == "*":
            result = a * b
        elif op == "/":
            result = a / b
        else:
            logger.warning(f"Неизвестная операция: {op}")
            continue
        logger.info(f"Вычисление: {a:g} {op} {b:g} = {result:g}")
        print(f"Результат: {result:g}")
    except ZeroDivisionError:
        logger.exception("Деление на ноль")
    except ValueError:
        logger.warning("Не удалось разобрать числа")
```

Пример сессии:

```
Введи выражение (например, 10 + 5) или 'выход': 10 + 5
2024-01-15 12:00:01,123 | INFO | Калькулятор запущен
2024-01-15 12:00:05,456 | INFO | Вычисление: 10 + 5 = 15
Результат: 15
Введи выражение (например, 10 + 5) или 'выход': 5 / 0
2024-01-15 12:00:12,789 | ERROR | Деление на ноль
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
Введи выражение (например, 10 + 5) или 'выход': выход
2024-01-15 12:00:20,000 | INFO | Работа завершена
```

Разбор шагов. Логгер `calc` получает уровень `INFO` — значит, сообщения `INFO` и выше будут записываться. Ему добавлены два обработчика с одинаковым форматом: один пишет в консоль, другой — в файл `calc.log`, поэтому история сессии сохраняется. Ввод разбивается на три части; если частей не три — это `WARNING` (не настолько серьёзно, чтобы прерывать программу). Сами вычисления обёрнуты в `try/except`: `ZeroDivisionError` логируется через `logger.exception`, который добавляет к сообщению полный трейсбек, а `ValueError` от `float()` — через `logger.warning`. Так по файлу лога можно восстановить весь ход сессии — это главное преимущество перед `print`.

### Разбор 2
Одно из возможных решений:

```python
import logging

logger = logging.getLogger("app")
logger.setLevel(logging.DEBUG)

formatter = logging.Formatter("%(asctime)s | %(levelname)s | %(message)s")

console = logging.StreamHandler()
console.setLevel(logging.WARNING)
console.setFormatter(formatter)

file_handler = logging.FileHandler("app.log", encoding="utf-8")
file_handler.setLevel(logging.DEBUG)
file_handler.setFormatter(formatter)

logger.addHandler(console)
logger.addHandler(file_handler)

logger.debug("Отладка")
logger.info("Информация")
logger.warning("Предупреждение")
logger.error("Ошибка")
logger.critical("Критично")
```

Консоль:

```
WARNING:Предупреждение
ERROR:Ошибка
CRITICAL:Критично
```

Файл `app.log` содержит все пять строк.

Разбор шагов. Уровни действуют на двух этапах: логгер фильтрует сообщения «снизу» (мы поставили `DEBUG` — пропускаются все), а каждый обработчик фильтрует повторно на своём выходе. Консольному обработчику задан уровень `WARNING`, поэтому `DEBUG` и `INFO` до консоли не доходят, а вот файловый обработчик с уровнем `DEBUG` принимает всё. Итог: в консоли три строки, в файле — пять. Один логгер с двумя обработчиками — стандартный паттерн: в файл пишут подробный журнал, а на экран выводят только важное. Обрати внимание и на то, что один и тот же объект `formatter` можно смело назначать нескольким обработчикам.

### Разбор 3
Одно из возможных решений:

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s | %(levelname)s | %(message)s",
)

logger = logging.getLogger("reader")

try:
    with open("input.txt", encoding="utf-8") as f:
        for line in f:
            if line.strip():
                logger.info(f"Строка: {line.strip()}")
            else:
                logger.warning("Пустая строка")
except FileNotFoundError:
    logger.exception("Файл input.txt не найден")
```

Пример вывода:

```
2024-01-15 12:00:01,123 | INFO | Строка: Первая строка
2024-01-15 12:00:01,124 | INFO | Строка: Вторая строка
2024-01-15 12:00:01,125 | WARNING | Пустая строка
2024-01-15 12:00:01,126 | INFO | Строка: Третья строка
```

Разбор шагов. `basicConfig` один раз настраивает корневой логгер: уровень `INFO` и формат с временем и уровнем. Дальше мы работаем с именованным логгером `reader` — он унаследует настройки корневого. Файл открывается через контекстный менеджер `with`, поэтому он гарантированно закроется, даже если случится ошибка. Для каждой строки проверяем `line.strip()`: если после удаления пробелов строка непустая — логируем её содержимое на `INFO`, иначе предупреждаем. Если файла нет, `open` бросит `FileNotFoundError`, и мы зафиксируем его через `logger.exception` — в лог попадёт и сообщение, и полный трейсбек. Такой «журналируемый» разбор файлов удобен для импорта данных: всегда видно, какая строка обработана, а какая вызвала проблему.

### Разбор 4
Одно из возможных решений:

```python
import logging

parent = logging.getLogger("app")
parent.setLevel(logging.INFO)
parent.addHandler(logging.StreamHandler())

child = logging.getLogger("app.db")

child.info("Подключение к базе данных")

print(f"Имя родителя: {parent.name}")
print(f"Имя ребёнка: {child.name}")
print(f"Обработчиков у ребёнка: {len(child.handlers)}")
print(f"propagate = {child.propagate}")
```

Результат:

```
Подключение к базе данных
Имя родителя: app
Имя ребёнка: app.db
Обработчиков у ребёнка: 0
propagate = True
```

Разбор шагов. Имена логгеров образуют иерархию через точки: `app.db` — потомок `app`. Дочерний логгер не имеет собственных обработчиков (`len(child.handlers) == 0`), но сообщение всё равно попало в консоль — потому что у логгеров включён `propagate` (передача родителю), и обработчик родителя `app` обработал сообщение. Это очень важное поведение: в большом проекте каждый модуль заводит свой логгер вида `myapp.db`, `myapp.api`, и все они направляют события в единую точку — обработчики родительского `myapp`. Вложенность также влияет на уровень: если у ребёнка уровень не задан, используется уровень ближайшего родителя с установленным уровнем.

### Разбор 5
Одно из возможных решений:

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")
logger = logging.getLogger("lazy")

user = "Аня"

logger.info("Пользователь %s вошёл в систему", user)
logger.debug("Отладка для %s", user)

print("DEBUG-сообщение отфильтровано: форматирование не выполнялось")
```

Результат:

```
INFO: Пользователь Аня вошёл в систему
DEBUG-сообщение отфильтровано: форматирование не выполнялось
```

Разбор шагов. Сообщения логируются в формате printf: в строке формата стоят плейсхолдеры `%s`, а значения передаются аргументами после неё. Ключевое преимущество такого подхода — ленивое форматирование: строка форматируется только если сообщение реально пройдёт фильтр уровня. Здесь уровень логгера — `INFO`, поэтому `DEBUG`-сообщение отбрасывается, и `%s` для него даже не подставляется. Если бы мы написали `logger.debug(f"Отладка для {user}")`, f-строка была бы собрана всегда — даже когда сообщение выброшено, — что в горячих циклах с тяжёлыми преобразованиями заметно замедляет программу. Поэтому для логов принято передавать аргументы, а не использовать f-строки. Обрати внимание, что для `INFO`-сообщения подстановка, наоборот, выполнилась: в выводе имя «Аня» на месте.

- Сообщение обработается обработчиком родителя благодаря передаче (propagate)
- Будет ошибка
- Создастся новый обработчик сам
* Правильный ответ: Сообщение обработается обработчиком родителя благодаря передаче (propagate)
По умолчанию propagate=True: дочерние логгеры передают сообщения родителям.
