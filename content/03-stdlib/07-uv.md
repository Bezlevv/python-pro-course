До сих пор ты устанавливал пакеты через `pip`, а виртуальные окружения создавал командой `python -m venv`. Это классика, но у неё есть слабые места: `pip` скачивает пакеты по одному, долго разрешает зависимости и не хранит единый lock-файл — список точных версий всех пакетов. Проект **uv** (название произносится «ю-ви») решает эти проблемы.

## Почему uv

uv — это менеджер пакетов и окружений, написанный на языке Rust. Он решает те же задачи, что `pip` и `venv`, но в десятки раз быстрее за счёт параллельной загрузки, агрессивного кэширования и грамотного разрешения зависимостей. Вот что умеет uv:

- создавать проекты и управлять их зависимостями через `pyproject.toml`;
- генерировать lock-файл `uv.lock` — точные версии всех пакетов, включая транзитивные;
- создавать виртуальные окружения (`uv venv`) и синхронизировать их с lock-файлом (`uv sync`);
- запускать команды внутри окружения без ручной активации (`uv run`);
- устанавливать глобальные инструменты в отдельное окружение (`uv tool`);
- управлять самими интерпретаторами Python (`uv python install`).

Один инструмент вместо четырёх, и он заметно быстрее. Давай попробуем.

## Установка

Проще всего установить uv как обычный Python-пакет через pip:

```bash
pip install uv
```

Проверь, что всё получилось:

```bash
uv --version
```

Ты увидишь строку вроде `uv 0.6.x`. Есть и другие способы установки (например, официальный установщик или `winget install astral-sh.uv` на Windows), но `pip install uv` универсален — он работает везде, где есть Python.

## Первый проект: uv init

Создадим новый проект. Перейди в папку, где хранишь учебные проекты, и выполни:

```bash
uv init hello_uv
```

uv создаст папку `hello_uv` с готовой структурой:

- `pyproject.toml` — описание проекта и его зависимостей;
- `main.py` — стартовая программа;
- `README.md`, `.python-version`, `.gitignore` — стандартное наполнение.

Загляни в созданный `main.py`:

```python
def main():
    print("Hello from hello-uv!")


if __name__ == "__main__":
    main()
```

Запусти его:

```bash
cd hello_uv
uv run main.py
```

При первом запуске uv сам создаст виртуальное окружение `.venv`, установит всё необходимое и выполнит программу. На экране появится `Hello from hello-uv!`. Никаких `pip install` и `activate` — всё уже сделано за тебя.

## pyproject.toml

Файл `pyproject.toml` — современный стандарт описания Python-проектов. Вот что создал uv:

```toml
[project]
name = "hello-uv"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.10"
dependencies = []
```

Ключевые секции: `[project]` описывает сам проект, `requires-python` задаёт минимальную версию Python, а `dependencies` — список зависимостей. Сейчас он пуст, но скоро наполнится.

## Добавляем зависимости: uv add

Чтобы добавить в проект внешний пакет, используй `uv add`:

```bash
uv add requests
```

Что произошло? Команда скачала пакет `requests`, добавила его в `dependencies` в `pyproject.toml`:

```toml
dependencies = [
    "requests>=2.32.0",
]
```

...и создала lock-файл `uv.lock`, в котором зафиксированы точные версии всех пакетов — и прямых, и транзитивных. Благодаря lock-файлу каждый участник проекта получит в точности те же версии.

Для тестовых зависимостей (например, pytest) есть флаг `--dev`:

```bash
uv add --dev pytest
```

Такие пакеты попадают в отдельную секцию `[dependency-groups]` и не будут установлены в «боевом» окружении.

## Запуск: uv run

`uv run` — волшебная команда: она запускает любую программу внутри окружения проекта, автоматически создавая его и подтягивая зависимости, если их не хватает:

```bash
uv run python main.py
uv run pytest
```

Попробуй теперь сам:

```python
import requests

response = requests.get("https://api.github.com", timeout=10)
print(response.status_code)
```

Если сохранить это в файл `github_status.py` и выполнить `uv run github_status.py`, ты увидишь `200` — сервер ответил. Обрати внимание: пакет `requests` уже доступен, хотя ты не активировал окружение вручную.

## Виртуальные окружения: uv venv

uv умеет создавать окружения и явно, как классический `venv`:

```bash
uv venv
```

Появится папка `.venv`. Её можно активировать как обычно:

```bash
# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\activate
```

Внутри активированного окружения привычный `pip` тоже доступен: uv предоставляет его как `uv pip install`, полностью совместимый с `pip install`. Но в проектах с `pyproject.toml` лучше пользоваться `uv add` и `uv sync` — они работают на уровне проекта, а не отдельного окружения.

## Синхронизация: uv sync

`uv sync` приводит окружение в точное соответствие с `uv.lock`:

```bash
uv sync
```

Это главная команда для командной работы: ты клонировал репозиторий, запустил `uv sync` — и получил окружение с теми же версиями, что у коллег. Можно даже удалить `.venv` и восстановить его одной командой — uv всё пересоздаст.

## Глобальные инструменты: uv tool

Иногда нужно установить инструмент не для проекта, а глобально — например, линтер `ruff` или форматтер `black`:

```bash
uv tool install ruff
```

Инструмент поставится в отдельное «инструментальное» окружение, а его команда станет доступна в терминале:

```bash
ruff --version
```

Если ставить инструмент не хочется, а запустить один раз — нужно, есть `uv tool run`:

```bash
uv tool run ruff check main.py
```

Глобальные инструменты не попадают в зависимости проекта — они изолированы и не конфликтуют с `pyproject.toml`.

## Итог урока

Мы познакомились с uv — современной заменой связки pip + venv. Главные команды: `uv init` (новый проект), `uv add` (зависимости), `uv run` (запуск), `uv venv` (окружение), `uv sync` (синхронизация), `uv tool` (глобальные инструменты). Всё это строится вокруг `pyproject.toml` и lock-файла `uv.lock` — теперь закрепим практикой.

### Разбор 1
Команды:

```bash
pip install uv
uv --version
uv init hello_uv
cd hello_uv
# правим main.py:
# def main():
#     print("Привет из uv!")
# if __name__ == "__main__":
#     main()
uv run main.py
```

Результат:

```text
Привет из uv!
```

Разбор шагов. `pip install uv` ставит uv как обычный пакет и добавляет команду `uv` в PATH. `uv init hello_uv` генерирует проект: `pyproject.toml`, `main.py`, `README.md`, `.python-version` и `.gitignore`. Первый запуск `uv run main.py` делает три вещи: находит подходящий интерпретатор Python, создаёт виртуальное окружение `.venv` (если его нет), устанавливает зависимости из `pyproject.toml` и генерирует `uv.lock`. Затем uv выполняет программу внутри этого окружения. Тебе не пришлось вручную вызывать `python -m venv`, `pip install` и `activate` — uv сделал всё одной командой. Обрати внимание на сообщения при первом запуске: uv честно пишет, что создаёт окружение и синхронизирует зависимости; после этого запуски становятся быстрыми, ведь окружение уже готово.

# github_status.py

Может показаться, что lock-файл избыточен, но именно он гарантирует воспроизводимость: завтра `uv sync` установит те же версии у тебя и у коллеги. Программа использует `requests.get` для GET-запроса к GitHub API; `timeout=10` страхует от бесконечного ожидания. Код `200` означает, что сервер ответил успешно. Если подключения к интернету нет, ты увидишь `requests.exceptions.ConnectionError` — это не ошибка кода, а отсутствие сети; в таком случае просто убедись, что `requests` установлен и импортируется.

### Разбор 3
Команды:

```bash
uv venv
# Linux / macOS:
source .venv/bin/activate
# Windows (PowerShell):
.venv\Scripts\activate
python -c "import sys; print(sys.prefix)"
deactivate
uv run python -c "import sys; print(sys.executable)"
```

Результат (примерно):

```text
/home/anya/hello_uv/.venv
...
/home/anya/hello_uv/.venv/bin/python
```

Разбор шагов. `uv venv` создаёт папку `.venv` — полностью изолированное окружение, в которое ставятся пакеты проекта. Активация (`source / .venv\Scripts\activate`) подменяет команду `python` так, чтобы она указывала на интерпретатор из окружения: поэтому `sys.prefix` показывает путь внутрь `.venv`. `deactivate` возвращает системный Python. Затем `uv run python -c "..."` запускает тот же интерпретатор, но без ручной активации: uv сам «подмешивает» окружение проекта в момент запуска. Для тебя это означает: можно вообще не активировать окружения, если пользоваться `uv run`. А вот глобально установленный инструмент (вроде `ruff`) в `.venv` не попадает — для него существует отдельный механизм `uv tool`, к которому мы перейдём ниже.

### Разбор 4
Команды:

```bash
uv add rich
rm -rf .venv          # Linux / macOS
rmdir /s .venv        # Windows
uv sync
uv run python main.py
```

Разбор шагов. `uv add rich` добавляет библиотеку `rich` (красивая консоль) в `pyproject.toml` и обновляет `uv.lock`. Затем мы намеренно удаляем окружение целиком — жёсткая проверка воспроизводимости. `uv sync` читает `uv.lock` и заново создаёт `.venv`, устанавливая ровно те версии, которые в нём записаны. Это ключевая команда в командной работе: после `git clone` достаточно выполнить `uv sync`, чтобы получить идентичное окружение. Заметь: мы не выполняли `uv add` повторно — вся информация о зависимостях уже была в lock-файле. Такой подход исключает ситуацию «у меня работает, а у тебя нет» из-за разных версий пакетов. Если в будущем захочешь обновить зависимости, есть `uv lock --upgrade` — но будь осторожен: обновление версий может изменить поведение программы.

### Разбор 5
Команды и файлы:

```bash
uv tool install ruff
ruff --version
```

```python
# unused.py — до исправления
import os

print("hi")
```

```bash

```

Результат до исправления:

```text
unused.py:1:8: F401 [*] `os` imported but unused
```

После удаления строки `import os`:

```bash

Разбор шагов. `uv tool install ruff` устанавливает `ruff` в изолированное «инструментальное» окружение и делает его команду доступной глобально. Линтер сразу находит проблему: код `F401` — импортированный, но неиспользуемый модуль. Такие «висячие» импорты засоряют код и вводят в заблуждение читателей, поэтому линтеры их ловят. После удаления `import os` проверка проходит чисто. И главное: открой `pyproject.toml` — `ruff` там нет. Инструменты вроде линтеров нужны для разработки, но не являются зависимостями проекта, и uv честно держит их отдельно. Аналогично работает `uv tool run` — он запускает инструмент однократно, ничего не устанавливая навсегда.
