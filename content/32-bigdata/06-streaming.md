## Пакетная и потоковая обработка

До сих пор мы читали данные целиком или частями из файлов. Это **пакетная** (batch) обработка: данные уже лежат, мы их прочитали, посчитали, получили результат. Но есть класс задач, где данные приходят непрерывно: логи сервисов, телеметрия датчиков, клики в веб-приложении, финансовые транзакции. Ждать «конца файла» бессмысленно — его нет. Так появляется **стриминг** (streaming): обработка потока событий по мере их поступления.

## Поток как генератор

В Python поток — это любой итерируемый объект, часто бесконечный генератор:

```python
import itertools, random

def sensor_stream():
    while True:
        yield {"sensor": random.choice(["t1", "t2"]), "temp": random.uniform(15, 30)}

stream = sensor_stream()
for event in itertools.islice(stream, 5):
    print(event)
```

Мы не знаем и не хотим знать, сколько будет событий. `itertools.islice` берёт первые 5 — и поток не «утекает» в память.

## Обработка событий

Событие — обычно словарь. Типовые операции:

- **map** — преобразовать событие (добавить поле, округлить);
- **filter** — отбросить ненужные;
- **aggregate** — накопить статистику;
- **window** — группировать по временному окну.

Простейший процессор:

```python
def parse_event(line: str) -> dict:
    ev = {}
    for part in line.split("|"):
        key, _, value = part.partition("=")
        ev[key] = value
    return ev

print(parse_event("ts=2024-01-01T00:00:01Z|city=moscow|temp=23.5"))
# {'ts': '2024-01-01T00:00:01Z', 'city': 'moscow', 'temp': '23.5'}
```

## Оконные агрегаты

Самый частый вопрос стриминга: «а какая средняя температура за последние 10 секунд?» Для этого нужны **окна** — скользящие отрезки. Классическая реализация на `collections.deque`:

```python
from collections import deque

class WindowAvg:
    def __init__(self, size: int):
        self.size = size
        self.window = deque()

    def push(self, value: float):
        self.window.append(value)
        if len(self.window) > self.size:
            self.window.popleft()
        if len(self.window) == self.size:
            return sum(self.window) / self.size
        return None

avg = WindowAvg(3)
for v in [10, 20, 30, 40]:
    print(avg.push(v))   # None, None, 20.0, 30.0
```

`deque` держит в памяти ровно `size` последних элементов, поэтому память не растёт с длиной потока.

## Kafka: распределённый брокер сообщений

Когда событий много и процессоров несколько, нужна система доставки. Стандарт индустрии — **Apache Kafka**. Базовые понятия:

- **Топик** (topic) — именованный поток сообщений;
- **Партиции** — топик режется на части; каждая партиция — упорядоченная очередь;
- **Офсет** (offset) — номер сообщения внутри партиции;
- **Консьюмер-группа** (consumer group) — набор процессов, которые вместе читают топик: каждое сообщение обрабатывает ровно один участник группы;
- **Семантика доставки**: at-most-once (можем потерять), at-least-once (можем продублировать), exactly-once (ровно один раз — самая дорогая).

Клиент для Python — `confluent_kafka`:

```python
from confluent_kafka import Producer, Consumer

producer = Producer({"bootstrap.servers": "localhost:9092"})
producer.produce("events", value=b'{"temp": 23.5}')
producer.flush()
```

```python
consumer = Consumer({
    "bootstrap.servers": "localhost:9092",
    "group.id": "analytics",
    "auto.offset.reset": "earliest",
})
consumer.subscribe(["events"])
while True:
    msg = consumer.poll(1.0)
    if msg is None:
        continue
    if msg.error():
        print("Ошибка:", msg.error())
        continue
    print(msg.value().decode())
```

Для запуска такого кода нужен работающий брокер — в песочнице его нет, поэтому здесь мы моделируем потоки локально, а Kafka-код используем как схему для реальной инфраструктуры.

### Разбор 1
Решение:

```python
import itertools
import random

def event_stream():
    i = 0
    while True:
        yield {"id": i, "city": random.choice(["moscow", "spb", "kazan"]),
               "temp": round(random.uniform(15, 30), 1)}
        i += 1

stream = event_stream()
for e in itertools.islice(stream, 10):
    print(e)

with_fahrenheit = ({"fahrenheit": round(e["temp"] * 9 / 5 + 32, 1), **e}
                   for e in event_stream())
for e in itertools.islice(with_fahrenheit, 3):
    print(e)
```

Вывод: десять событий-словарей, затем три события с дополнительным полем `fahrenheit`. Что здесь происходит? `event_stream` — бесконечный генератор: память не расходуется на хранение всех событий. `itertools.islice` «обрезает» поток. Генераторное выражение трансформирует каждое событие на лету — это аналог map в стриминге. Обрати внимание на порядок `{"fahrenheit": ..., **e}`: так `fahrenheit` попадёт в словарь первым полем.

### Разбор 2
Решение:

```python
from collections import deque

class WindowAvg:
    def __init__(self, size: int):
        self.size = size
        self.window = deque(maxlen=size)

    def push(self, value: float):
        self.window.append(value)
        if len(self.window) == self.size:
            return sum(self.window) / self.size
        return None

avg = WindowAvg(5)
for v in range(1, 11):
    print(avg.push(v))
```

Вывод: `None, None, None, None, 3.0, 4.0, 5.0, 6.0, 7.0, 8.0`. Что здесь происходит? `deque(maxlen=5)` автоматически выбрасывает самый старый элемент при переполнении — код упрощается. Окно «разогревается»: пока не набралось 5 значений, среднего нет, возвращается `None`. С 5-го элемента мы видим скользящее среднее последних пяти чисел. Такой класс — типовой фрагмент любого оконного агрегатора.

### Разбор 3
Решение:

```python
class CityAggregator:
    def __init__(self):
        self.stats = {}

    def handle(self, event: dict):
        if "city" not in event or "temp" not in event:
            return
        city = event["city"]
        s = self.stats.setdefault(city, [0.0, 0])
        s[0] += event["temp"]
        s[1] += 1

    def result(self) -> dict:
        return {city: total / n for city, (total, n) in self.stats.items()}

agg = CityAggregator()
agg.handle({"city": "moscow", "temp": 20.0})
agg.handle({"city": "moscow", "temp": 30.0})
agg.handle({"city": "spb", "temp": 10.0})
print(agg.result())
```

Вывод: `{'moscow': 25.0, 'spb': 10.0}`. Что здесь происходит? Агрегатор накапливает сумму и количество по каждому городу. `setdefault(city, [0.0, 0])` создаёт запись при первом появлении города. `result()` считает средние на момент вызова. Это пример stateful-обработки: состояние живёт в объекте и обновляется с каждым событием.

Такие тесты ловят регрессии при рефакторинге парсера.

### Разбор 5
Решение:

```python
import pytest
from stream_utils import CityAggregator

def test_aggregator_basic():
    agg = CityAggregator()
    agg.handle({"city": "moscow", "temp": 20.0})
    agg.handle({"city": "moscow", "temp": 30.0})
    agg.handle({"city": "spb", "temp": 10.0})
    assert agg.result() == {"moscow": 25.0, "spb": 10.0}

def test_aggregator_empty():
    assert CityAggregator().result() == {}

def test_aggregator_updates():
    agg = CityAggregator()
    agg.handle({"city": "moscow", "temp": 20.0})
    agg.handle({"city": "moscow", "temp": 30.0})
    agg.handle({"city": "moscow", "temp": 35.0})
    assert agg.result()["moscow"] == pytest.approx(28.333, abs=0.01)

def test_aggregator_ignores_bad_event():
    agg = CityAggregator()
    agg.handle({"city": "moscow"})   # нет temp
    agg.handle({"temp": 10.0})       # нет city
    assert agg.result() == {}
```

Что здесь происходит? Первый тест — эталон из задачи 3. Второй — пустое состояние. Третий проверяет пересчёт среднего при добавлении новых событий: `(20 + 30 + 35) / 3 = 28.333...`, и для плавающей точки используем `pytest.approx`. Четвёртый убеждается, что «битые» события игнорируются, а не роняют исключение — важно для устойчивости потоковых процессоров к грязным данным. Запуск: `pytest test_stream_utils.py -v`.
