Ты уже знаешь, что в Python есть числа с плавающей точкой — `float`. Но есть одна ловушка: если ты попробуешь сложить `0.1 + 0.2`, результат тебя удивит. Разберёмся, почему так происходит и как правильно считать деньги.

## Проблема float

Набери в Python:

```python
print(0.1 + 0.2)
```

Ты увидишь `0.30000000000000004`, а не `0.3`. Почему? Компьютер хранит числа в двоичной системе, а `0.1` и `0.2` в ней не выражаются точно — как `1/3` в десятичной даёт бесконечную дробь. Поэтому `float` хранит приближение, и при вычислениях ошибки накапливаются.

Для большинства задач это не страшно: `round(0.1 + 0.2, 2)` даст `0.3`. Но для денег приближения недопустимы: неверная копейка в каждой операции превращается в реальные потери.

## Decimal: точные десятичные числа

Модуль `decimal` даёт тип `Decimal`, который хранит десятичные числа точно:

```python
from decimal import Decimal

print(Decimal("0.1") + Decimal("0.2"))  # 0.3
```

Обрати внимание: **всегда передавай строки**. `Decimal(0.1)` сначала создаст неточный `float` и только потом превратит его в `Decimal` — ошибка останется. `Decimal("0.1")` — точная десятичная запись.

```python
print(Decimal(0.1))          # 0.1000000000000000055511151231257827021181583404541015625
print(Decimal("0.1"))        # 0.1
```

## Операции с Decimal

С `Decimal` работают обычные операторы:

```python
price = Decimal("199.90")
count = 3
print(price * count)         # 599.70
print(Decimal("10") / Decimal("4"))  # 2.5
```

Важно: `Decimal` можно умножать на целое число, делить на `Decimal`, а вот смешивать с `float` напрямую нельзя — получится `TypeError`. Если нужно, преврати `float` в строку: `Decimal(str(0.1))`.

## Точность и округление

У `Decimal` есть настраиваемая точность — по умолчанию 28 значащих цифр. Она задаётся в контексте:

```python
from decimal import getcontext

getcontext().prec = 4
print(Decimal("1") / Decimal("3"))  # 0.3333
```

Для денег важнее округление до копеек. Метод `quantize` округляет до нужного разряда:

```python
from decimal import Decimal, ROUND_HALF_UP

price = Decimal("19.995")
rounded = price.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print(rounded)  # 20.00
```

`ROUND_HALF_UP` — «банковское» округление, знакомое со школы: 19.995 → 20.00. По умолчанию `quantize` использует `ROUND_HALF_EVEN` (округление к чётному), которое для денег часто не подходит.

## Деньги на практике

```python
from decimal import Decimal

def checkout(items):
    total = Decimal("0")
    for name, price in items:
        total += Decimal(str(price))
    return total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

basket = [("хлеб", "35.50"), ("молоко", "89.90")]
print(checkout(basket))  # 125.40
```

`Decimal` можно складывать, сравнивать, форматировать. Недостаток один — такие числа медленнее `float`, но для денег скорость почти никогда не важна.

## Итог

- `0.1 + 0.2` — не `0.3` из-за двоичного представления.
- Для денег используй `Decimal` и передавай значения строками.
- Округляй через `quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`.
- Не смешивай `Decimal` с `float` в одной операции.

### Разбор 1
```python
from decimal import Decimal

print("float:", 0.1 + 0.2)  # float: 0.30000000000000004
print("decimal:", Decimal("0.1") + Decimal("0.2"))  # decimal: 0.3
```

`float` хранит числа в двоичной системе: `0.1` и `0.2` не представимы точно, поэтому сумма даёт маленькую погрешность. `Decimal("0.1")` хранит десятичную запись точно, и сумма получается ровно `0.3`. Для денег выбираем `Decimal`.

### Разбор 2
```python
from decimal import Decimal

price = Decimal("99.99")
count = 3
print(price * count)  # 299.97

# Ошибка: Decimal * float -> TypeError
# print(price * 0.5)

print(price * Decimal("0.5"))  # 49.995
```

`Decimal` умножается на целое число и на другой `Decimal`, но не на `float` — Python бросает `TypeError`, чтобы ты случайно не смешал точные и неточные числа. Если `float` пришёл извне, преврати его в строку: `Decimal(str(0.5))`.

### Разбор 3
```python
from decimal import Decimal, ROUND_HALF_UP

def round_cash(amount):
    return Decimal(amount).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

print(round_cash("19.995"))  # 20.00
print(round_cash("10.004"))  # 10.00
print(round_cash("7.777"))   # 7.78
```

`quantize` округляет до разряда `0.01`. `ROUND_HALF_UP` работает как школьное округление: `19.995` → `20.00`, `10.004` → `10.00`, `7.777` → `7.78`. Без параметра `rounding` Python использовал бы `ROUND_HALF_EVEN`, который для `19.995` дал бы `19.99` — неожиданно для кассы.

### Разбор 4
```python
from decimal import Decimal, ROUND_CEILING

def split_bill(total, people):
    share = (Decimal(total) / people).quantize(Decimal("0.01"), rounding=ROUND_CEILING)
    return share

total = Decimal("100.00")
people = 3
share = split_bill(total, people)
print("Доля:", share)                        # 33.34
print("Остаток:", total - share * people)    # 0.02
```

`total / people` даёт `Decimal`; `quantize` с `ROUND_CEILING` округляет вверх, чтобы никто не заплатил меньше своей честной доли. `100.00 / 3` — это `33.333...`, вверх даёт `33.34`. Сумма трёх долей — `100.02`, значит, образовался остаток `0.02`, с которым сервис может разобраться отдельно.

### Разбор 5
```python
from decimal import Decimal, ROUND_HALF_UP

items = [("хлеб", "35.50"), ("молоко", "89.90"), ("яблоки", "120.25")]

total = Decimal("0")
for name, price in items:
    total += Decimal(price)

subtotal = total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
discount = (total * Decimal("0.10")).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
final = (total - discount).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

print("Сумма без скидки:", subtotal)   # 245.65
print("Скидка 10%:", discount)          # 24.57
print("Итог:", final)                    # 221.08
```

Каждая цена — строка, поэтому `Decimal(price)` точен. Сумма `245.65`; скидка 10% — `24.565`, округление до копеек даёт `24.57`; итог — `221.08`. Обрати внимание: мы округляем каждый расчёт отдельно — так касса выдаёт те же числа, что и бумажный чек.
