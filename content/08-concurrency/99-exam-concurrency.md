Что такое GIL?
- Библиотека для создания потоков
- Глобальная блокировка интерпретатора CPython: в каждый момент времени байт-код исполняет только один поток
- Механизм кэширования импортов
- Режим отладки многопоточности
* Правильный ответ: Глобальная блокировка интерпретатора CPython: в каждый момент времени байт-код исполняет только один поток
GIL защищает внутренние структуры интерпретатора, но из-за него настоящая параллельность потоков невозможна.

Почему потоки не ускоряют вычислительные (CPU-bound) задачи?
- Потоки запрещены на большинстве платформ
- Из-за GIL одновременно выполняется только один поток, поэтому суммарное время почти не меняется
- Потоки ускоряют только ввод-вывод
- У потоков нет доступа к процессору
* Правильный ответ: Из-за GIL одновременно выполняется только один поток, поэтому суммарное время почти не меняется
Потоки лишь быстро переключаются, а накладные расходы на переключения даже добавляют время.

Какой инструмент выбрать, чтобы по-настоящему задействовать несколько ядер процессора?
- threading.Thread
- multiprocessing.Process
- asyncio.create_task
- queue.Queue
* Правильный ответ: multiprocessing.Process
Каждый процесс — отдельный интерпретатор со своим GIL, поэтому процессы исполняются на разных ядрах параллельно.

Почему процессы не могут просто использовать общие глобальные переменные?
- Переменные в процессах не существуют
- Каждый процесс имеет собственную память, и изменения в одном процессе не видны другим
- Глобальные переменные доступны только в главном процессе
- Процессы видят только копии глобальных переменных
* Правильный ответ: Каждый процесс имеет собственную память, и изменения в одном процессе не видны другим
Для обмена данными нужны специальные средства: Value, Array или Queue.

Зачем нужна конструкция if __name__ == "__main__": в скриптах с multiprocessing?
- Чтобы запускать программу быстрее
- Чтобы при перезапуске интерпретатора (spawn на Windows) код создания процессов не исполнялся заново в каждом дочернем процессе
- Это синтаксическое требование всех программ на Python
- Чтобы избежать переполнения стека
* Правильный ответ: Чтобы при перезапуске интерпретатора (spawn на Windows) код создания процессов не исполнялся заново в каждом дочернем процессе
Без этой защиты дочерний процесс создавал бы новые процессы рекурсивно.

Что делает метод t.join()?
- Запускает поток t
- Останавливает поток t навсегда
- Блокирует вызывающий поток, пока поток t не завершится
- Удаляет поток t из памяти
* Правильный ответ: Блокирует вызывающий поток, пока поток t не завершится
join() позволяет дождаться окончания работы потока, например перед печатью итогового результата.

Зачем нужен ThreadPoolExecutor?
- Чтобы ограничить количество одновременно работающих потоков и переиспользовать их для множества задач
- Чтобы создать процессы вместо потоков
- Чтобы отключить GIL
- Чтобы превратить последовательный код в асинхронный
* Правильный ответ: Чтобы ограничить количество одновременно работающих потоков и переиспользовать их для множества задач
Пулы (executor.submit и executor.map) берут на себя создание и управление потоками: задачи ставятся в очередь и выполняются свободными работниками.

Как защитить общую переменную от гонки данных?
- Объявить её как global
- Обернуть изменение в with lock: с объектом threading.Lock
- Использовать print() для вывода
- Увеличить число потоков
* Правильный ответ: Обернуть изменение в with lock: с объектом threading.Lock
Мьютекс делает критическую секцию взаимоисключающей, а контекстный менеджер гарантированно освобождает блокировку даже при исключении.

Как объявляется корутина в asyncio?
- def coro(): ...
- async def coro(): ... с await внутри
- with coro(): ...
- await def coro(): ...
* Правильный ответ: async def coro(): ... с await внутри
Корутина объявляется через async def, а в точках ожидания используется await: там она отдаёт управление циклу событий.

Что делает asyncio.gather?
- Запускает корутины последовательно
- Запускает несколько корутин параллельно и возвращает результаты в порядке их передачи
- Ограничивает время выполнения корутин
- Останавливает цикл событий
* Правильный ответ: Запускает несколько корутин параллельно и возвращает результаты в порядке их передачи
Если порядок не важен, используют asyncio.as_completed, который отдаёт результаты по мере готовности.

Что произойдёт при превышении тайм-аута, заданного asyncio.wait_for?
- Задача продолжит выполняться в фоне
- Будет возбуждено исключение asyncio.TimeoutError, а задача будет отменена
- Программа зависнет навсегда
- Результат станет равным None
* Правильный ответ: Будет возбуждено исключение asyncio.TimeoutError, а задача будет отменена
Тайм-аут не даёт ждать медленный сервис вечно: ожидание прерывается, а задача получает запрос на отмену.
