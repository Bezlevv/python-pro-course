До сих пор мы считали градиенты вручную и выписывали формулы. Для простых задач это терпимо, но уже для двухслойной сети производные превращаются в громоздкие цепочки. PyTorch решает эту проблему: он умеет автоматически считать градиенты любой функции — это называется autograd. Сегодня мы познакомимся с основным типом данных PyTorch — тензором — и с автоградом.

## Что такое тензор

Тензор — это многомерный массив чисел. Скаляр — тензор нулевой размерности, вектор — первой, матрица — второй, а пакет изображений — четвёртой (количество, каналы, высота, ширина). По устройству тензоры близки к массивам NumPy, и многие операции повторяют numpy-версию один в один.

## Создание тензоров

Проще всего — из списка через `torch.tensor`. Есть фабрики: `torch.zeros`, `torch.ones`, `torch.randn` (нормальное распределение), `torch.arange`. Важные атрибуты: `shape` — форма (кортеж размерностей), `ndim` — число осей, `dtype` — тип чисел (`torch.float32` по умолчанию для дробных), `device` — где лежит тензор: на CPU или видеокарте. Перевести список в тензор можно через `torch.tensor(x, dtype=torch.float32)`.

## Операции

Над тензорами работают обычные знаки: `+`, `-`, `*`, `/`, `**`, а также функции вроде `torch.sin`, `torch.exp`. Умножение матриц — через `@` или `torch.matmul`. Важная особенность — широковещание (broadcasting): если формы не совпадают, PyTorch растягивает оси меньшей формы, как это делает NumPy. Например, к матрице размера (3, 4) можно прибавить вектор длины 4.

## Изменение формы

`reshape` и `view` позволяют менять форму, сохраняя число элементов: тензор размера (2, 3) можно превратить в (6,) или (3, 2). Часто это нужно, чтобы скормить данные слою сети. Индексация работает знакомо: `x[0]`, `x[:, 1]`, `x[1:, :2]`.

## Автоград

Создадим тензор с `requires_grad=True` — теперь PyTorch будет запоминать все операции над ним. Когда скалярная функция полностью посчитана, вызов `backward()` вычислит производные по всем тензорам, помеченным `requires_grad`, и сложит их в атрибут `grad`.

Главные правила:

1. `backward()` вызывается только от скаляра (или тензора из одного элемента);
2. между шагами градиент надо обнулять через `zero_()`;
3. обновлять параметры нужно внутри блока `torch.no_grad()`, иначе PyTorch начнёт строить граф вычислений для самих обновлений.

```python
import torch

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = torch.tensor([[1.0], [2.0], [3.0]])

z = x @ y          # 1*1 + 2*2 + 3*3 = 14
z.backward()
print("z =", z.item())
print("dx =", x.grad)   # должно быть [1., 2., 3.]
```

Аналитически `z = x₁·1 + x₂·2 + x₃·3`, поэтому `dz/dx = [1, 2, 3]` — autograd выдал ровно это.

Теперь решим простейшую регрессию `y = 2x` методом градиентного спуска, доверив производные PyTorch:

```python
import torch

xt = torch.arange(1.0, 6.0)
yt = 2 * xt                    # истинный вес равен 2

w = torch.tensor(0.0, requires_grad=True)
lr = 0.05

for step in range(100):
    loss = ((w * xt - yt) ** 2).mean()
    loss.backward()

    with torch.no_grad():
        w -= lr * w.grad
    w.grad.zero_()

print(f"w = {w.item():.4f}")   # близко к 2.0
```

### Разбор 1
Полное решение:

```python
import torch

a = torch.tensor(3.0, requires_grad=True)
b = torch.tensor(2.0, requires_grad=True)
c = torch.tensor(0.0, requires_grad=True)

g = a ** 2 * b + torch.sin(c)
g.backward()

print("dg/da =", a.grad.item())
print("dg/db =", b.grad.item())
print("dg/dc =", c.grad.item())
```

Мы создаём три скалярных тензора с `requires_grad=True` — PyTorch запоминает каждую операцию над ними в вычислительном графе. Выражение `a ** 2 * b + torch.sin(c)` переводится в граф из узлов: возведение в степень, умножение, синус, сложение. Когда мы вызываем `g.backward()`, PyTorch проходит по графу в обратном порядке и применяет цепное правило, накапливая производные в атрибуте `.grad` каждого листа. Проверим результат вручную. Частная производная по a: `∂g/∂a = 2ab = 2·3·2 = 12`. По b: `∂g/∂b = a² = 9`. По c: `∂g/∂c = cos(c) = cos(0) = 1`. Автоград выдал ровно эти числа. Обрати внимание: `backward()` здесь вызван от скаляра, поэтому дополнительный аргумент не нужен. Мы печатаем `.item()`, чтобы достать обычное число float из тензора; сам `.grad` — это тензор той же формы, что и исходный. Если бы мы захотели ещё раз вызвать `backward()`, пришлось бы обнулять градиенты через `zero_()` — иначе значения накопятся. Этот шаблон — «backward, no_grad, step, zero_» — ровно тот, который будет использоваться во всех следующих уроках.

### Разбор 2
Решение:

```python
import torch

x = torch.tensor(1.0, requires_grad=True)
y = torch.tensor(2.0, requires_grad=True)

f = x ** 3 * y + y ** 2 + 2 * x
f.backward()

print("df/dx =", x.grad.item())
print("df/dy =", y.grad.item())
```

Выражение `x ** 3 * y + y ** 2 + 2 * x` содержит квадратичные и кубические члены, но autograd вычисляет производные по тем же правилам, что и для простых функций. Аналитически: `∂f/∂x = 3x²y + 2 = 3·1·2 + 2 = 8`, `∂f/∂y = x³ + 2y = 1 + 4 = 5`. Оба значения совпадают с выводом. Если запустить этот код дважды подряд в одной сессии, второй вызов `backward()` добавит новые градиенты к старым — поэтому в реальных циклах обучения между шагами обязателен `zero_()` или `optimizer.zero_grad()`. Это правило мы уже упоминали в теории, и здесь оно проявляется на практике: накопление градиентов — частая причина «непонятных» больших шагов обновления.

### Разбор 3
Решение:

```python
import torch

A = torch.tensor([[1, 2, 3], [4, 5, 6]])
v = torch.tensor([10, 20, 30])

C = A + v
D = A.sum(dim=1)

print("Форма A:", A.shape)
print("Форма C:", C.shape)
print("C =", C)
print("D =", D)
```

Тензор `A` имеет форму (2, 3). Вектор `v` имеет форму (3,), и при сложении PyTorch применяет широковещание: вектор «растягивается» по строкам матрицы, и к каждой строке прибавляется один и тот же вектор. Поэтому `C[0] = [1+10, 2+20, 3+30] = [11, 22, 33]`, а `C[1] = [14, 25, 36]`. Широковещание — это не копирование данных, а виртуальное расширение: PyTorch не создаёт лишних массивов, а просто повторяет ось при вычислении. `A.sum(dim=1)` суммирует элементы вдоль строк (по оси 1), поэтому получается вектор из двух чисел: `[6, 15]`. Если бы мы написали `A.sum(dim=0)`, сумма шла бы по столбцам и вернула бы вектор `[5, 7, 9]`. Понимание форм и осей — половина успеха при работе с PyTorch.

### Разбор 4
Решение:

```python
import torch

xt = torch.arange(1.0, 6.0)
yt = 2 * xt

w = torch.tensor(0.0, requires_grad=True)
optimizer = torch.optim.Adam([w], lr=0.05)

for step in range(100):
    loss = ((w * xt - yt) ** 2).mean()
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

print(f"w = {w.item():.4f}")
```

Мы передаём параметр в оптимизатор списком: `torch.optim.Adam([w], lr=0.05)`. Внутри цикла — каноническая последовательность: посчитать потерю, обнулить градиенты, вызвать `backward()`, затем `step()`. Оптимизатор сам выполняет обновление параметра с учётом адаптивной скорости обучения, поэтому ни `torch.no_grad()`, ни ручного `w -= lr * w.grad` не нужно. За 100 шагов Adam доводит w до значения, близкого к 2.0 — истинному коэффициенту зависимости y = 2x. Именно этот шаблон — «zero_grad → backward → step» — будет использоваться во всех следующих уроках при обучении настоящих нейросетей, только вместо одного параметра в оптимизатор попадёт `model.parameters()`.

### Разбор 5
Решение:

```python
import torch
import math

t = torch.tensor(1.0, requires_grad=True)
h = t * torch.exp(t)
h.backward()

analytic = 2 * math.e

print("autograd:", round(t.grad.item(), 4))
print("аналитика:", round(analytic, 4))
```

Через autograd мы получаем значение производной автоматически: `t.grad` ≈ 5.4366. Аналитически производная произведения `t·eᵗ` равна `1·eᵗ + t·eᵗ = (1 + t)·eᵗ`, а в точке t = 1 это `2e ≈ 5.4365637`. Оба значения совпадают с точностью до четырёх знаков. Эта задача показывает, что autograd — не «магия», а точное применение правил дифференцирования: если ты можешь посчитать производную руками, ты всегда можешь проверить вывод модели. Когда же формулы становятся слишком сложными (как у нейросетей), autograd остаётся единственным практическим способом получить градиенты — но проверка на простых функциях остаётся хорошей привычкой.
