В прошлом уроке мы научились предсказывать метки по соседям. Но у kNN есть слабое место: он не строит никакой внутренней модели и хранит все данные, а предсказание — это набор локальных усреднений. Линейная регрессия — другой подход: мы задаём форму зависимости заранее и подбираем её параметры по данным.

## Форма модели

Линейная регрессия предполагает, что метка y — это линейная комбинация признаков x1, x2, ..., xn плюс константа — сдвиг b (его называют ещё bias или свободный член):

```
y = w1·x1 + w2·x2 + ... + wn·xn + b
```

Числа wi — веса: они показывают, насколько сильно каждый признак влияет на ответ. Если вес положительный, рост признака увеличивает ответ, если отрицательный — уменьшает.

## Функция потерь

Задача обучения — найти такие веса, чтобы предсказания как можно меньше отличались от настоящих меток. Разницу меряют функцией потерь. Стандартный выбор для регрессии — средняя квадратичная ошибка, MSE: это среднее квадратов разностей между предсказанными и истинными значениями. Квадрат нужен, чтобы ошибки в обе стороны не гасили друг друга. Чем меньше MSE, тем лучше модель.

## Матричная форма

Удобно записать модель сразу для всех примеров одной формулой. Пусть X — матрица, где строки — примеры, а столбцы — признаки; w — вектор весов. Тогда предсказания для всей выборки — это векторное произведение `X @ w` (плюс сдвиг). Чтобы сдвиг тоже был в формуле, добавляем к X столбец из единиц и рассматриваем сдвиг как ещё один вес. В таком виде решение находится явно: `w = inv(XᵀX)·Xᵀy` — это нормальное уравнение. На практике чаще используют псевдообратную матрицу `np.linalg.pinv`.

## Реализация на NumPy

Сгенерируем искусственные данные: точки на прямой с шумом — будто зависимость на самом деле линейная, но измерения неточны. Затем составим матрицу X со столбцом из единиц и решим нормальное уравнение. Сравним найденные веса с истинными.

```python
import numpy as np

rng = np.random.default_rng(42)
n = 100

# Истинная зависимость: y = 2x + 1 + шум
x = rng.uniform(0, 10, n)
true_w, true_b = 2.0, 1.0
y = true_w * x + true_b + rng.normal(0, 1.0, n)

# Матрица признаков: столбец единиц + столбец x
X = np.column_stack([np.ones(n), x])

# Нормальное уравнение через псевдообратную матрицу
w = np.linalg.pinv(X) @ y
print("Сдвиг b =", round(w[0], 3))
print("Вес w =", round(w[1], 3))

y_pred = X @ w
mse = ((y - y_pred) ** 2).mean()
print("MSE =", round(mse, 3))
```

Запусти код — ты увидишь, что найденный сдвиг близок к 1.0, вес — к 2.0, а MSE близок к 1.0 (это дисперсия добавленного шума). Модель «угадала» настоящую зависимость.

## Интерпретация

Коэффициент при x — это наклон: на сколько в среднем меняется y при увеличении x на единицу. Сдвиг — значение y, когда все признаки равны нулю. После обучения полезно посмотреть и на качество: MSE сама по себе зависит от масштаба, поэтому её сравнивают с разбросом данных или считают долю объяснённой дисперсии — коэффициент детерминации R².

### Разбор 1
Полное решение:

```python
import numpy as np

def train_linear(X, y):
    return np.linalg.pinv(X) @ y

rng = np.random.default_rng(7)
n = 200
x1 = rng.uniform(0, 5, n)
x2 = rng.uniform(0, 5, n)
y = 3 + 2 * x1 - x2 + rng.normal(0, 0.5, n)

X = np.column_stack([np.ones(n), x1, x2])

w = train_linear(X, y)
print("Коэффициенты:", np.round(w, 3))

y_pred = X @ w
mse = ((y - y_pred) ** 2).mean()
print("MSE =", round(mse, 4))
```

Функция `train_linear` — это одна строка: псевдообратная матрица умножается на вектор меток. Почему `pinv`, а не точное `np.linalg.inv(X.T @ X) @ X.T @ y`? Псевдообратная матрица даёт решение методом наименьших квадратов даже тогда, когда X не квадратная или плохо обусловлена, и работает быстрее — её можно использовать всегда. Дальше мы строим данные: истинные коэффициенты 3, 2 и −1, шум со стандартным отклонением 0.5. Дисперсия шума равна 0.25, поэтому MSE обученной модели должен быть близок к 0.25 — это нижняя граница, дальше которой модель «подгоняться» не может, ведь часть разброса — неустранимый шум. Найденные коэффициенты отличаются от истинных на сотые: это статистическая ошибка оценки, которая уменьшается с ростом числа примеров n. Заметь: никакого обучения в смысле циклов здесь нет — ответ получен за одну операцию. Это главное преимущество нормального уравнения перед итерационными методами, но оно доступно только для линейных моделей.

```python
import numpy as np

def train_linear(X, y):
    return np.linalg.pinv(X) @ y

rng = np.random.default_rng(7)
n = 200
x1 = rng.uniform(0, 5, n)

X = np.column_stack([np.ones(n), x1, x2])

w = train_linear(X[:150], y[:150])

train_mse = ((X[:150] @ w - y[:150]) ** 2).mean()
test_mse = ((X[150:] @ w - y[150:]) ** 2).mean()
print("MSE на обучении =", round(train_mse, 4))
print("MSE на тесте =", round(test_mse, 4))
```

Мы нарезаем данные нарезкой `[:150]` и `[150:]` и обучаем модель только на первой части. MSE на обучении получается около 0.25, и важно, что на тестовой части ошибка такая же — значит, модель не «зазубрила» конкретные примеры, а выучила именно зависимость. Если бы тестовая ошибка была заметно больше обучающей, мы бы говорили о переобучении: модель подстроилась под шум конкретной обучающей выборки. Здесь этого нет, потому что данных достаточно много, а модель простая. Такой приём — обязательная проверка на новых данных — используется во всех реальных ML-проектах.

### Разбор 3
Решение:

```python
import numpy as np

def train_linear(X, y):
    return np.linalg.pinv(X) @ y

rng = np.random.default_rng(7)
n = 200
x1 = rng.uniform(0, 5, n)
x2 = rng.uniform(0, 5, n)
y = 3 + 2 * x1 - x2 + rng.normal(0, 0.5, n)

X = np.column_stack([np.ones(n), x1, x2])

w = train_linear(X, y)
y_pred = X @ w

ss_res = ((y - y_pred) ** 2).sum()
ss_tot = ((y - y.mean()) ** 2).sum()
r2 = 1 - ss_res / ss_tot
print("R² =", round(r2, 3))
```

Числитель `ss_res` — сумма квадратов ошибок модели: это та часть изменчивости, которую модель не смогла объяснить. Знаменатель `ss_tot` — сумма квадратов отклонений меток от их среднего: это полная изменчивость данных. Если бы модель предсказывала всегда среднее, отношение было бы равно 1 и R² = 0. У нас R² ≈ 0.976: модель объясняет 97.6% дисперсии, а оставшиеся 2.4% — это шум измерений. Именно поэтому R² удобнее, чем «сырой» MSE: он нормирован на разброс данных и сравним между разными задачами.

```python
import numpy as np

def train_linear(X, y):
    return np.linalg.pinv(X) @ y

rng = np.random.default_rng(7)
n = 200
x1 = rng.uniform(0, 5, n)
x2 = rng.uniform(0, 5, n)
y = 3 + 2 * x1 - x2 + rng.normal(0, 0.5, n)

X = np.column_stack([np.ones(n), x1, x2])

Xc = np.column_stack([np.ones(n), x1 - x1.mean(), x2 - x2.mean()])

w = train_linear(X, y)
wc = train_linear(Xc, y)
print("Без центрирования:", np.round(w, 3))
print("С центрированием:", np.round(wc, 3))

pred_plain = X[:5] @ w
pred_centered = Xc[:5] @ wc
print("Предсказания совпадают:", np.allclose(pred_plain, pred_centered, atol=1e-3))
```

Центрирование — это перенос начала координат: мы вычитаем средние из признаков, но не трогаем столбец единиц. Геометрически наклон плоскости не меняется, поэтому веса при x1 и x2 остаются 2 и −1. А вот свободный член становится равен среднему y, то есть примерно 5.5: в центрированных координатах точка «средний пример, средний ответ» лежит на плоскости, и сдвиг — это значение y в нуле координат. Предсказания обеих моделей совпадают с точностью до арифметики — это проверяется через `np.allclose`. Такой приём часто используют, чтобы улучшить устойчивость численных методов и интерпретацию коэффициентов.

### Разбор 5
Решение:

```python
import numpy as np

def train_linear(X, y):
    return np.linalg.pinv(X) @ y

rng = np.random.default_rng(7)
n = 200
x1 = rng.uniform(0, 5, n)
x2 = rng.uniform(0, 5, n)
y = 3 + 2 * x1 - x2 + rng.normal(0, 0.5, n)

X = np.column_stack([np.ones(n), x1, x2])
X_poly = np.column_stack([X, x1**2, x2**2, x1 * x2])

w = train_linear(X, y)
w_poly = train_linear(X_poly, y)

mse = ((X @ w - y) ** 2).mean()
mse_poly = ((X_poly @ w_poly - y) ** 2).mean()
print("Базовая модель MSE =", round(mse, 4))
print("Полиномиальная MSE =", round(mse_poly, 4))
```

Полиномиальная модель содержит шесть признаков и может описывать кривые, но истинная зависимость линейная, поэтому квадратичные члены не несут новой информации. MSE остаётся около 0.25 у обеих моделей, а из-за случайности на конкретной выборке расширенная модель может оказаться даже чуть хуже: лишние параметры обучаются в том числе на шуме. Это важный урок: «больше признаков» не значит «лучше». В реальных задачах полиномиальные признаки помогают, когда зависимость действительно нелинейная, но их добавляют осознанно, проверяя качество на тестовой выборке.
