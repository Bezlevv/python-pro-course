В этом уроке нет обычной подачи материала — перед тобой самостоятельная работа. Ты уже умеешь читать чужой код, запускать программы и пользоваться исключениями. Теперь попробуешь себя в роли ревьюера: получишь «чужую» программу, найдёшь в ней слабые места и оформишь профессиональный отчёт. Это навык из реальной работы: ревью проходит каждый pull request, и умение вежливо и точно указывать на проблемы ценится не меньше, чем умение их исправлять.

## Постановка задачи

Тебе дан код программы «Банковский счёт» в файле `account.py`. Она умеет открывать счёт, класть деньги, снимать их и печатать выписку. Программа запускается, но в ней спрятаны дефекты: баги, неряшливый стиль, проблемы с надёжностью и безопасностью. Твоя задача — провести полный code review: найти и воспроизвести проблемы, классифицировать их, оформить отчёт и предложить исправления.

```python
# account.py
import datetime

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
        self.transactions = []

    def deposit(self, amount):
        self.balance = self.balance + amount
        self.transactions.append((datetime.datetime.now(), "deposit", amount))

    def withdraw(self, amount):
        if self.balance >= amount:
            self.balance = self.balance - amount
            self.transactions.append((datetime.datetime.now(), "withdraw", amount))
        else:
            print("Недостаточно средств")

    def show(self):
        print("Владелец:", self.owner)
        print("Баланс:", self.balance)
        for t in self.transactions:
            print(t)

acc = BankAccount("Аня", 100)
acc.deposit(50)
acc.withdraw(30)
acc.show()
```

Что с этим кодом не так? Запусти его, поэкспериментируй, попробуй «сломать». Ты найдёшь как минимум: депозит отрицательной суммы, снятие отрицательной суммы, снятие всей суммы, потерянные деньги при дробных суммах (из-за float), необработанные исключения, несоответствие стилю PEP 8 и отсутствие защиты данных.

## Требования к работе

- Отчёт оформляется в файле `review.md` в формате Markdown.
- Каждое замечание — отдельная запись: номер пункта, серьёзность (`критично` / `важно` / `незначительно`), строка или функция, где проблема, описание, воспроизведение (что нужно сделать, чтобы увидеть) и рекомендация по исправлению.
- Все проблемы должны быть **воспроизведены**: ты обязан запустить программу и убедиться, что баг реально проявляется.
- В конце отчёта — вердикт и предложение исправленного кода (в файле `account_fixed.py`).
- Нельзя менять оригинальный `account.py`: он нужен для сравнения.


Базовые сценарии работают: `acc.deposit(50)` даёт баланс 150, `acc.withdraw(30)` — 120. На этом этапе главное — зафиксировать «как есть», чтобы дальше сравнивать с ожиданиями.

### Разбор 2
Проверки дают следующие результаты:

| Ввод | Что происходит | Оценка |
|---|---|---|
| `deposit(-50)` | Баланс уменьшается на 50 | Критично |
| `withdraw(-30)` | Баланс растёт на 30 | Критично |
| `withdraw(0)` | Ничего, но транзакция пишется | Незначительно |
| `withdraw(1000)` | Сообщение «Недостаточно средств» | Ок |
| `withdraw(100)` при балансе 100 | Баланс 0, снятие разрешено | Спорно |

Замечания: `deposit` и `withdraw` не проверяют знак суммы, поэтому отрицательные суммы «работают» наоборот. Условие `self.balance >= amount` позволяет снять всю сумму — это допустимое поведение, но стоит зафиксировать: `withdraw(0)` пишет бесполезную транзакцию, её стоит запретить.

### Разбор 3
```python
acc = BankAccount("Аня", 0)
for _ in range(10):
    acc.deposit(0.1)
print(acc.balance)  # 0.9999999999999999
acc.withdraw(0.3)
print(acc.balance)  # 0.6999999999999999
```

Причина: числа с плавающей точкой хранятся в двоичной системе, и `0.1` не представим точно. Для денег нужен `decimal.Decimal`:

```python
from decimal import Decimal

# в методах:
self.balance = Decimal(str(amount))  # или Decimal("0.1")
```

Рекомендация: хранить баланс как `Decimal`, все суммы принимать как `Decimal` или строки, а вывод форматировать через `quantize`.

### Разбор 4
```python
acc = BankAccount("Аня", 100)
acc.deposit("сто")  # TypeError: unsupported operand type(s) for +
```

Ошибка возникает при сложении `int` и строки; при этом транзакция уже добавлена — состояние частично сломано. Прямой доступ:

```python
acc.balance = 1000000      # работает
acc.transactions.append("фейк")  # работает
```

Замечания:
- **Отсутствие валидации типов** — методы должны проверять, что сумма — число.
- **Незащищённые атрибуты** — `balance` и `transactions` публичные; нужны приватные имена (`_balance`, `_transactions`) и геттеры.
- **Стиль**: длинные строки, нет пробелов вокруг `=` в `__init__` (например, `self.owner = owner` — ок, но `balance=0` в сигнатуре — PEP 8 рекомендует `balance=0` без пробелов, это допустимо), вывод через `print` вместо `logging`.

Исправленный код в `account_fixed.py`:

```python
from decimal import Decimal
import logging

logging.basicConfig(level=logging.INFO)

class BankAccount:
    def __init__(self, owner, balance="0"):
        self._owner = owner
        self._balance = Decimal(str(balance))
        self._transactions = []

    def deposit(self, amount):
        amount = Decimal(str(amount))
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        self._balance += amount
        self._transactions.append(("deposit", amount))
        logging.info("Депозит: %s", amount)

    def withdraw(self, amount):
        amount = Decimal(str(amount))
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        if amount > self._balance:
            raise ValueError("Недостаточно средств")
        self._balance -= amount
        self._transactions.append(("withdraw", amount))

    @property
    def balance(self):
        return self._balance

    def show(self):
        print("Владелец:", self._owner)
        print("Баланс:", self._balance)
        for t in self._transactions:
            print(t)
```

Теперь `deposit(-50)` бросает `ValueError`, `withdraw(-30)` — тоже, баланс хранится как `Decimal`, а приватные атрибуты защищены от прямого изменения; доступ к балансу — через свойство `balance`.
