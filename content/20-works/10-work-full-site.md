Это финальная самостоятельная работа курса: ты соберёшь полноценный сайт с нуля — от пустой папки до работающего приложения в Docker. Здесь соединяются все изученные темы: веб-фреймворк, базы данных и ORM, HTML-шаблоны Jinja2, CSS-вёрстка, клиентский JavaScript, автотесты и деплой. Работа рассчитана на 6 часов (можно разбить на несколько заходов), и каждый этап заканчивается работающей программой — не переходи к следующему, пока предыдущий не проверен.

## Постановка задачи

Нужно разработать **личный блог**: пользователь может зарегистрироваться, войти, создавать посты, редактировать и удалять свои записи. Другие пользователи могут читать посты и оставлять комментарии. Комментарии и «лайки» работают через JavaScript-запросы `fetch` без перезагрузки страницы. Все данные хранятся в SQL-базе данных через ORM. Проект покрывается pytest-тестами и упаковывается в Docker-контейнер с Gunicorn.

Чему ты научишься: выбирать стек под задачу и принимать архитектурные решения, проектировать схему базы данных и описывать её в ORM, реализовывать аутентификацию и защиту маршрутов, собирать интерфейс из шаблонов, верстать адаптивно, добавлять интерактивность на JS и доводить продукт до деплоя.

## Требования

- **Стек:** Flask + SQLAlchemy (или Django + собственный ORM). Выбор обоснуй в `README.md`: почему этот фреймворк, какие у него ограничения и что бы ты выбрал для другого проекта.
- **База данных:** SQLite для разработки; три таблицы (модели): `User`, `Post`, `Comment` с правильными связями (пользователь → посты, пользователь → комментарии, пост → комментарии).
- **Аутентификация:** регистрация, вход, выход; пароли хранятся в хэшированном виде; доступ к созданию/редактированию/удалению постов — только для автора.
- **Страницы и шаблоны Jinja2:** базовый шаблон с наследованием, главная страница со списком постов, страница поста, форма входа/регистрации, форма создания поста, панель автора (редактирование/удаление).
- **CSS:** переменные, гибкая шапка на flex, сетка карточек постов на grid, медиазапросы для мобильных устройств.
- **JavaScript (fetch):** отправка комментария и «лайк» поста без перезагрузки страницы, обновление DOM по ответу сервера (JSON).
- **Тесты pytest:** минимум 10 тестов: страницы, аутентификация, CRUD постов, работа API для комментариев/лайков.
- **Деплой:** Dockerfile, запуск через Gunicorn, `docker-compose.yml` (приложение + база данных), проверка, что контейнер стартует и сайт открывается.
- Только стандартные библиотеки и изученные в курсе инструменты; код читаемый, с комментариями, запускается по инструкции из `README.md`.

### Разбор 2
Схема БД: связи. Пользователь имеет много постов, пост принадлежит одному пользователю — связь один-ко-многим. Аналогично пользователь → комментарии. Пост имеет много комментариев, комментарий принадлежит одному посту. В SQLAlchemy:

```python
class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    email = db.Column(db.String(120), unique=True, nullable=False)
    password_hash = db.Column(db.String(200), nullable=False)
    posts = db.relationship("Post", backref="author", lazy=True)
    comments = db.relationship("Comment", backref="author", lazy=True)

class Post(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    content = db.Column(db.Text, nullable=False)
    created_at = db.Column(db.DateTime, default=datetime.utcnow)
    author_id = db.Column(db.Integer, db.ForeignKey("user.id"), nullable=False)
    comments = db.relationship("Comment", backref="post", lazy=True)

class Comment(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    text = db.Column(db.Text, nullable=False)
    created_at = db.Column(db.DateTime, default=datetime.utcnow)
    post_id = db.Column(db.Integer, db.ForeignKey("post.id"), nullable=False)
    author_id = db.Column(db.Integer, db.ForeignKey("user.id"), nullable=False)
```

`backref` позволяет писать `post.author.username` или `post.comments` — объекты достаются автоматически, без ручных запросов. Создай таблицы `db.create_all()` и проверь через `sqlite3 blog.db ".tables"` — должны появиться три таблицы.

### Разбор 3
Аутентификация. При регистрации, хэшируем пароль:

```python
password_hash = generate_password_hash(form.password.data)
user = User(username=form.username.data, email=form.email.data, password_hash=password_hash)
db.session.add(user)
db.session.commit()
```

При входе: `check_password_hash(user.password_hash, form.password.data)`. Хэширование важно, потому что база данных может попасть в чужие руки — а хэш невозможно превратить обратно в пароль. После успешного входа сохраняем `session["user_id"] = user.id`. Защита маршрутов: декоратор `login_required` проверяет, есть ли `user_id` в сессии; если нет — редирект на `/login`. Обрати внимание на порядок проверок: сначала проверь, существует ли пользователь с таким именем, затем — совпадает ли пароль. Так мы не раскрываем, какое именно поле было неверным.

  const response = await fetch(`/api/posts/${postId}/like`, { method: "POST" });
