Самая ценная возможность MicroPython — превращать дешёвую плату в «умное» устройство, которое живёт в интернете: отправляет данные датчиков на сервер и управляется с браузера. Этот урок — сердце IoT-разработки.

## Wi-Fi: модуль network

Плата (ESP32, Raspberry Pi Pico W) подключается к Wi-Fi как обычный ноутбук. За это отвечает модуль `network` и класс `WLAN`. Сначала создаём интерфейс в режиме клиента (STA_IF), включаем его и подключаемся:

```python
import network
import time

wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect("МояСеть", "пароль")

while not wlan.isconnected():
    time.sleep(1)
    print("Подключаюсь...")

print("IP-адрес:", wlan.ifconfig()[0])
```

`wlan.isconnected()` возвращает `True`, когда плата получила IP-адрес от роутера. `ifconfig()` возвращает кортеж: (IP, маска, шлюз, DNS). Если плата не может подключиться — проверь имя сети и пароль; ESP32 поддерживает только сети 2.4 ГГц.

## HTTP-клиент: urequests

Протокол HTTP — это то, через что браузеры разговаривают с сайтами. Из MicroPython можно делать HTTP-запросы с помощью компактного модуля `urequests` (аналог `requests` с компьютера):

```python
import urequests

r = urequests.get("http://example.com")
print("Статус:", r.status_code)   # 200 — успех
print("Текст:", r.text[:100])
r.close()
```

`urequests.get()` — GET-запрос: скачать страницу. Ответ — объект с полями `status_code` (код ответа, 200 = ОК), `text` (тело ответа), `json()` (если сервер ответил JSON). Не забывай `r.close()` — на плате мало памяти, и открытые соединения её съедают. Есть и `urequests.post()`, `put()`, `delete()`.

## Веб-сервер на плате: socket

Плата может и сама стать сервером: слушать порт и отвечать на запросы браузера. Для этого используется модуль `socket` — низкоуровневая работа с сетью.

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(("0.0.0.0", 80))   # слушать порт 80 на всех интерфейсах
s.listen(1)

while True:
    conn, addr = s.accept()       # ждать клиента
    request = conn.recv(1024)     # прочитать запрос
    print("Запрос от", addr)
    conn.send("HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n\r\n")
    conn.send("<h1>Привет с платы!</h1>")
    conn.close()
```

Что здесь происходит? `bind()` вешает «прослушку» на порт 80, `listen(1)` включает очередь, `accept()` ждёт, пока браузер подключится, и возвращает соединение `conn` и адрес клиента. `recv(1024)` читает запрос. Затем мы отправляем два пакета: заголовки ответа и тело страницы. Конец заголовков — пустая строка `\r\n\r\n`. После `conn.close()` цикл снова ждёт следующего клиента.

Открой в браузере `http://IP-платы` — увидишь свою страницу. Управление устройством с веб-страницы работает так же: браузер шлёт запрос, а сервер на плате читает его и, например, включает светодиод.

## Безопасность и аккуратность

Работа с сетью добавляет много неожиданностей: неверный пароль, нестабильная сеть, чужой запрос. Поэтому оборачивай сетевые операции в `try/except` и ставь таймауты. В реальных IoT-устройствах данные шифруют по HTTPS, а доступ к управлению защищают паролем — но для первых экспериментов достаточно локальной сети.

### Разбор 1
Программа:

```python
import network
import time
import sys

wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect("МояСеть", "пароль")

for _ in range(15):
    if wlan.isconnected():
        break
    time.sleep(1)
    print("Подключаюсь...")

if wlan.isconnected():
    ip = wlan.ifconfig()[0]
    print("Подключено! IP:", ip)
else:
    print("Ошибка подключения")
    sys.exit()
```

Что здесь происходит? Цикл `for` даёт 15 попыток по секунде, но выходит раньше, если соединение установлено. После цикла повторная проверка `isconnected()` определяет исход: IP берётся из `ifconfig()[0]`. Это важный приём — не вешать бесконечное ожидание: если сеть недоступна, программа должна честно сказать об этом и завершиться, а не зависать навсегда.

### Разбор 2
Программа:

```python
import urequests

try:
    r = urequests.get("http://example.com")
    print("Статус:", r.status_code)
    print("Текст:", r.text[:100])
    r.close()
except OSError as e:
    print("Ошибка:", e)

try:
    r = urequests.get("http://192.0.2.1/nope")
    print("Статус:", r.status_code)
    r.close()
except OSError as e:
    print("Ошибка:", e)
```

Что здесь происходит? Первый запрос успешен: `status_code` = 200, `text[:100]` — первые 100 символов HTML. Второй адрес (192.0.2.1 — зарезервированная для тестов сеть) недоступен: `urequests` бросит `OSError`, который мы ловим и печатаем, вместо того чтобы позволить программе упасть. `r.close()` освобождает сокет — на плате с сотнями КБ памяти каждое «потерянное» соединение — это утечка.

### Разбор 3
Программа:

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(("0.0.0.0", 80))
s.listen(1)

html = ("HTTP/1.1 200 OK\r\n"
        "Content-Type: text/html; charset=utf-8\r\n"
        "\r\n"
        "<h1>Моя IoT-плата</h1>"
        "<p>Работаю!</p>")

while True:
    conn, addr = s.accept()
    request = conn.recv(1024)
    print("Запрос от", addr)
    conn.send(html)
    conn.close()
```

Что здесь происходит? Строка `html` склеена из заголовков ответа и тела. `\r\n` — перевод строки в HTTP; пустая строка отделяет заголовки от тела. `SO_REUSEADDR` позволяет сразу перезапускать сервер после Ctrl+C, не ожидая, пока ОС освободит порт. `accept()` блокирует программу до прихода клиента — сервер «спит» в ожидании.

### Разбор 4
Программа:

```python
import socket
from machine import Pin

button = Pin(14, Pin.IN, Pin.PULL_UP)
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(("0.0.0.0", 80))
s.listen(1)

while True:
    conn, addr = s.accept()
    conn.recv(1024)
    state = "НАЖАТА" if button.value() == 0 else "НЕ НАЖАТА"
    html = ("HTTP/1.1 200 OK\r\n"
            "Content-Type: text/html; charset=utf-8\r\n"
            "\r\n"
            "<h1>Статус кнопки</h1>"
            "<p>Кнопка: " + state + "</p>")
    conn.send(html)
    conn.close()
```

Что здесь происходит? Кнопка читается в момент каждого запроса — то есть страница всегда показывает актуальное состояние. Тернарный оператор `a if условие else b` выбирает строку. Теперь у нас настоящее «умное устройство»: браузер — пульт, плата — прибор, и всё через HTTP.

### Разбор 5
Программа:

```python
import socket
from machine import Pin

led = Pin(2, Pin.OUT)
led.off()

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(("0.0.0.0", 80))
s.listen(1)

while True:
    conn, addr = s.accept()
    request = conn.recv(1024).decode()
    if "led=on" in request:
        led.on()
    elif "led=off" in request:
        led.off()
    state = "ВКЛ" if led.value() else "ВЫКЛ"
    html = ("HTTP/1.1 200 OK\r\n"
            "Content-Type: text/html; charset=utf-8\r\n"
            "\r\n"
            "<h1>Умный свет</h1>"
            "<p>LED: " + state + "</p>"
            "<a href='/?led=on'>Включить</a> "
            "<a href='/?led=off'>Выключить</a>")
    conn.send(html)
    conn.close()
```

Что здесь происходит? Браузер отправляет запрос вида `GET /?led=on HTTP/1.1` — и мы просто ищем подстроку `led=on` в тексте запроса. Ссылки в HTML ведут на те же адреса, поэтому управление работает прямо с отображаемой страницы. Это минимальный, но полностью рабочий IoT-паттерн: устройство слушает HTTP, реагирует на команды и отдаёт состояние.
