В прошлом уроке мы научились управлять выходами — подавать напряжение на светодиод. Теперь научимся читать входы: узнавать, нажата ли кнопка, какое напряжение на пине, какая температура в комнате. Это превращает плату из «мигалки» в устройство, которое реагирует на окружающий мир.

## Цифровой вход: кнопка

Кнопка — самый простой датчик. При нажатии она замыкает цепь, при отпускании — размыкает. Подключи кнопку между пином 14 и GND:

```python
from machine import Pin

button = Pin(14, Pin.IN, Pin.PULL_UP)
```

Обрати внимание на `Pin.PULL_UP` — это **внутренняя подтяжка к питанию**. Без неё, когда кнопка не нажата, пин «висит в воздухе» и читает случайное значение. Подтяжка фиксирует уровень: не нажата → на пине высокий уровень (1), нажата → пин замкнут на землю → низкий уровень (0):

```python
print(button.value())  # 1 — не нажата, 0 — нажата
```

Заметь перевёрнутую логику: нажатие даёт `0`. Это нормально для подтяжки вверх.

## Дребезг контактов

Реальные кнопки при нажатии «дребезжат»: контакт несколько миллисекунд замыкается и размыкается, и один «клик» может дать десятки срабатываний. Проверь сам:

```python
count = 0
while count < 10:
    if button.value() == 0:
        count += 1
        print("Нажато:", count)
        while button.value() == 0:
            pass  # ждём отпускания
```

Пока нажато, `print` выполнится один раз, но при отпускании контакт может «подпрыгнуть» несколько раз. Устраняют дребезг паузой — после фиксации нажатия ждут 20–50 мс, а затем читают снова:

```python
if button.value() == 0:
    time.sleep_ms(30)          # ждём, пока дрожание уляжется
    if button.value() == 0:    # проверяем повторно
        print("Точно нажато!")
```

Такой приём называется **антидребезг** (debounce). Он обязателен в любой реальной программе с кнопками.

## Аналоговый сигнал: ADC

Lнопка даёт только два состояния. А как измерить, например, напряжение с потенциометра или уровень света? Для этого нужен **АЦП** (ADC, analog-to-digital converter) — он превращает напряжение (0–3.3 В) в число. В MicroPython это делается так:

```python
from machine import Pin, ADC

adc = ADC(Pin(34))        # пин 34 (ESP32) поддерживает ADC
value = adc.read_u16()    # число от 0 до 65535
print(value)
```

Чем больше напряжение, тем больше число: 0 В → 0, 3.3 В → 65535. Обычный «цифровой» пин так не умеет — у ADC есть специальный входной каскад. У Raspberry Pi Pico ADC-пины — это 26–28.

## Цифровой датчик DHT22

Многие датчики общаются с платой по цифровому протоколу — например, DHT22 измеряет температуру и влажность:

```python
from machine import Pin
from dht import DHT22
import time

dht = DHT22(Pin(4))

while True:
    dht.measure()                        # запросить замер
    print("Температура:", dht.temperature(), "C")
    print("Влажность:", dht.humidity(), "%")
    time.sleep(2)
```

Датчику нужно время на замер, поэтому между `measure()` и чтением нельзя вставлять большие паузы, а сам опрос делают не чаще раза в 2 секунды. Иногда DHT22 «не отвечает» — тогда появится `OSError`, и такой сбой надо аккуратно обрабатывать через `try/except`:

```python
try:
    dht.measure()
    print(dht.temperature())
except OSError:
    print("Ошибка чтения, пробуем снова")
```

### Разбор 1
Программа:

```python
from machine import Pin
import time

button = Pin(14, Pin.IN, Pin.PULL_UP)

while True:
    if button.value() == 0:
        print("Нажато!")
    else:
        print("Отпущено")
    time.sleep(0.1)
```

Что здесь происходит? `Pin(14, Pin.IN, Pin.PULL_UP)` настраивает пин 14 как вход с внутренней подтяжкой к питанию: когда кнопка не нажата, пин читает `1`, при нажатии замыкается на землю и даёт `0`. Цикл опрашивает кнопку 10 раз в секунду (пауза 0.1 с) и печатает состояние. Если поставить паузу больше секунды — можно «пропустить» короткое нажатие, поэтому опрос делают чаще, чем возможное нажатие.

### Разбор 2
Программа:

```python
from machine import Pin
import time

button = Pin(14, Pin.IN, Pin.PULL_UP)
count = 0
pressed = False

while True:
    if button.value() == 0 and not pressed:
        pressed = True
        count += 1
        if count % 5 == 0:
            print("Счётчик:", count)
    if button.value() == 1:
        pressed = False
    time.sleep_ms(50)
```

Что здесь происходит? Флаг `pressed` запоминает, что кнопка уже «учтена», и не даёт счётчику расти, пока кнопка удерживается. Когда кнопку отпускают (`value() == 1`), флаг сбрасывается, и следующее нажатие будет засчитано. `count % 5 == 0` — остаток от деления на 5 равен нулю ровно для чисел 5, 10, 15… Это классический способ «срабатывать каждый пятый раз».

### Разбор 3
Программа с антидребезгом:

```python
from machine import Pin
import time

button = Pin(14, Pin.IN, Pin.PULL_UP)
count = 0

while True:
    if button.value() == 0:
        time.sleep_ms(30)                 # ждём, пока контакт уляжется
        if button.value() == 0:           # повторная проверка
            count += 1
            print("Нажато:", count)
            while button.value() == 0:
                time.sleep_ms(10)         # ждём отпускания
            time.sleep_ms(50)
```

Что здесь происходит? Первая проверка «ловит» возможное нажатие, а вторая — подтверждает его через 30 мс: если дребезг ещё «дрожит», к моменту второй проверки контакт мог разомкнуться, и ложное срабатывание отсеивается. В варианте без паузы один клик может дать 10–30 срабатываний, потому что электрический контакт замыкается и размыкается с частотой сотен герц. Антидребезг обязателен во всех «боевых» программах с кнопками.

### Разбор 4
Программа:

```python
from machine import Pin, ADC
import time

adc = ADC(Pin(34))

while True:
    value = adc.read_u16()
    percent = value * 100 // 65535
    print(value, "->", percent, "%")
    time.sleep(0.5)
```

Что здесь происходит? `adc.read_u16()` возвращает число от 0 до 65535, пропорциональное напряжению на пине: 0 В → 0, 3.3 В → 65535. `value * 100 // 65535` переводит это в проценты — целочисленное деление `//` отбрасывает дробную часть. При повороте ручки потенциометра напряжение меняется, и процент плавно идёт от ~0 до ~100. Такой же приём используется для считывания фоторезисторов, джойстиков и аналоговых датчиков.

### Разбор 5
Программа:

```python
from machine import Pin
from dht import DHT22
import time

dht = DHT22(Pin(4))

while True:
    try:
        dht.measure()
        print("Температура:", dht.temperature(), "C")
        print("Влажность:", dht.humidity(), "%")
    except OSError:
        print("Ошибка чтения")
    print("---")
    time.sleep(2)
```

Что здесь происходит? `dht.measure()` отправляет датчику запрос и ждёт ответа. Если датчик не успел ответить (питание нестабильно, слишком короткий кабель, сигнал помех), MicroPython бросит `OSError` — и без `try/except` программа упала бы. Мы перехватываем ошибку, печатаем `Ошибка чтения` и продолжаем цикл. Разделитель `---` делает вывод читаемым, а пауза 2 секунды соблюдает требование DHT22 не опрашивать его чаще раза в 2 секунды.
