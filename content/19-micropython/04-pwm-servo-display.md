Мы умеем включать и выключать светодиод, но часто нужно сделать больше: плавно менять яркость, поворачивать сервопривод на точный угол или показывать данные на маленьком экране. Всё это — следующий шаг в освоении железа, и сегодня мы сделаем его.

## PWM: ШИМ

Если просто подавать на светодиод то 0, то 3.3 В, он мигает. А если мгновенно переключать напряжение тысячи раз в секунду, глаз не замечает переключений: светодиод кажется просто тусклее или ярче. Именно это делает **ШИМ** (PWM, pulse width modulation) — он генерирует прямоугольный сигнал с изменяемой «скважностью»: долей времени, когда сигнал включён.

```python
from machine import Pin, PWM

pwm = PWM(Pin(2), freq=1000)   # частота 1000 Гц
pwm.duty_u16(32768)             # заполнение: 0..65535
```

`duty_u16` — «заполнение» (duty cycle) в диапазоне 0–65535: 0 — выключен, 65535 — полная яркость, 32768 — примерно половина. Изменяя его, плавно меняешь яркость:

```python
import time
for duty in range(0, 65536, 1000):
    pwm.duty_u16(duty)
    time.sleep_ms(3)
```

## Сервопривод

Сервопривод — это моторчик с обратной связью, который умеет поворачивать вал на заданный угол (обычно 0–180°). Управляется он PWM с частотой 50 Гц, а угол задаётся шириной импульса: 0.5 мс — 0°, 1.5 мс — 90°, 2.5 мс — 180°.

```python
from machine import Pin, PWM

servo = PWM(Pin(13), freq=50)   # серво любит 50 Гц

def set_angle(angle):
    # 0° => 0.5 мс, 180° => 2.5 мс при периоде 20 мс
    duty = int(1638 + (8191 - 1638) * angle / 180)
    servo.duty_u16(duty)

set_angle(90)   # повернуть на 90°
```

Числа 1638 и 8191 — это `duty_u16`, соответствующие 0.5 мс и 2.5 мс из периода 20 мс. Подключи серво: коричневый провод — GND, красный — 5В (или 3.3В для маленьких серво), оранжевый — сигнальный пин.

## OLED-дисплей по I2C

Маленькие OLED-экраны (0.96", 128×64) общаются по шине **I2C** — по двум проводам: SCL (тактовый) и SDA (данные). На ESP32 стандартные пины I2C — 22 (SCL) и 21 (SDA), на Raspberry Pi Pico — 1 и 0.

```python
from machine import Pin, I2C
from ssd1306 import SSD1306_I2C

i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
oled = SSD1306_I2C(128, 64, i2c)   # экран 128x64 пикселя

oled.fill(0)              # очистить экран (залить чёрным)
oled.text("Привет!", 0, 0)
oled.text("MicroPython", 0, 16)
oled.show()               # отправить буфер на экран
```

Всё, что ты рисуешь, попадает в память платы (буфер), а реально показывается только после `oled.show()`. Строки на экране имеют высоту 8 пикселей, поэтому удобно размещать их через каждые 8–10 пикселей по вертикали. Можно рисовать и фигуры: `oled.fill_rect(x, y, w, h, 1)` — закрашенный прямоугольник, `oled.hline(x, y, w, 1)` — линия.

### Разбор 1
Программа:

```python
from machine import Pin, PWM
import time

pwm = PWM(Pin(2), freq=1000)

while True:
    for duty in range(0, 65536, 300):
        pwm.duty_u16(duty)
        time.sleep_ms(2)
    for duty in range(65536, -1, -300):
        pwm.duty_u16(duty)
        time.sleep_ms(2)
```

Что здесь происходит? Первый цикл поднимает `duty_u16` от 0 до 65535, второй опускает обратно. Шаг 300 и пауза 2 мс дают сотни промежуточных значений — глаз не видит скачков, и светодиод плавно разгорается и гаснет. Это классический эффект «дыхания». Вместо `duty_u16` в новых прошивках есть и `duty_ns` — но `duty_u16` универсален на ESP32 и Raspberry Pi Pico.

### Разбор 2
Программа:

```python
from machine import Pin, PWM
import time

servo = PWM(Pin(13), freq=50)

def set_angle(angle):
    duty = int(1638 + (8191 - 1638) * angle / 180)
    servo.duty_u16(duty)

while True:
    for angle in range(0, 181, 5):
        set_angle(angle)
        time.sleep_ms(200)
    for angle in range(180, -1, -5):
        set_angle(angle)
        time.sleep_ms(200)
```

Что здесь происходит? Серво управляется импульсами частотой 50 Гц: угол 0° соответствует длительности импульса 0.5 мс, 180° — 2.5 мс. При периоде 20 мс это `duty_u16` 1638 и 8191. Формула интерполирует угол в этот диапазон: чем больше угол, тем шире импульс, тем дальше поворачивается вал. Шаг 5° и пауза 200 мс делают движение плавным — серво «доезжает» до каждой позиции, а не дёргается.

### Разбор 3
Программа:

```python
from machine import Pin, PWM
import time

melody = [(330, 300), (392, 300), (440, 300),
          (392, 300), (330, 300), (330, 150), (330, 150)]

while True:
    for freq, dur in melody:
        pwm = PWM(Pin(12), freq=freq)
        time.sleep_ms(dur)
        pwm.deinit()
        time.sleep_ms(50)
```

Что здесь происходит? Пассивный зуммер сам не умеет издавать звук — ему нужен сигнал нужной частоты, который и генерирует PWM. Каждая нота — это PWM с частотой, равной частоте ноты (330 Гц — «ми»). `deinit()` освобождает пин и останавливает сигнал — иначе нота звучала бы вечно. Пауза 50 мс между нотами делает мелодию разборчивой. С активным зуммером этот приём не сработает — ему достаточно просто уровня питания.

### Разбор 4
Программа:

```python
from machine import Pin, I2C
from ssd1306 import SSD1306_I2C
import time

i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
oled = SSD1306_I2C(128, 64, i2c)

while True:
    oled.fill(0)
    oled.text("Температура: 24 C", 0, 0)
    oled.text("Влажность: 45 %", 0, 16)
    oled.text("Дата: 01.11", 0, 32)
    oled.show()
    time.sleep(1)
```

Что здесь происходит? `oled.fill(0)` очищает буфер — без этого старые символы остались бы на экране. `oled.text()` рисует текст в буфер, но показывается он только после `oled.show()`, который целиком отправляет буфер по I2C в контроллер экрана. Расстояние 16 пикселей между строками удобно: шрифт имеет высоту 8 пикселей, плюс отступ. Во время `time.sleep(1)` экран сохраняет картинку — OLED не нужно постоянно обновлять.

### Разбор 5
Программа:

```python
from machine import Pin, ADC, I2C
from ssd1306 import SSD1306_I2C
import time

adc = ADC(Pin(34))
i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)
oled = SSD1306_I2C(128, 64, i2c)

while True:
    percent = adc.read_u16() * 100 // 65535
    oled.fill(0)
    oled.text("Уровень: " + str(percent) + " %", 0, 0)
    filled = percent * 20 // 100
    for i in range(filled):
        oled.fill_rect(0 + i * 6, 20, 5, 8, 1)
    oled.show()
    time.sleep(0.2)
```

Что здесь происходит? Мы объединили три модуля: ADC читает напряжение с потенциометра, `percent` переводит его в проценты, а OLED рисует и текст, и полоску-индикатор. `fill_rect(x, y, w, h, 1)` закрашивает прямоугольник 5×8 пикселей, и 20 таких прямоугольников рядом образуют шкалу. Число заполненных квадратиков пропорционально проценту. Так делаются настоящие приборы: датчик → логика → экран.
