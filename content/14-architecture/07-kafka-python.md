Apache Kafka — распределённая платформа потоковых сообщений. Она используется как «шина событий» между сервисами, надёжно храня сообщения и позволяя нескольким потребителям читать их.

## Основные термины

- Топик (topic) — именованный поток сообщений.
- Партиции (partitions) — физические сегменты топика, дают параллелизм.
- Продюсер — отправитель сообщений.
- Консьюмер — получатель; группа консьюмеров делит партиции между собой.
- Offset — позиция чтения в партиции.

## Продюсер

```python
from kafka import KafkaProducer

producer = KafkaProducer(bootstrap_servers="localhost:9092")
producer.send("orders", key=b"user-1", value=b"order-42")
producer.flush()
```

## Консьюмер в группе

```python
from kafka import KafkaConsumer

consumer = KafkaConsumer("orders", group_id="workers",
                         bootstrap_servers="localhost:9092")
for msg in consumer:
    print(msg.key, msg.value, msg.offset)
```

## Гарантии

- at-most-once — сообщение может потеряться;
- at-least-once — не потеряется, но может дублироваться;
- exactly-once — ровно один раз (транзакции).

## Итог урока

Kafka отделяет продюсеров от консьюмеров и масштабируется партициями. Для Python есть библиотеки kafka-python и confluent-kafka.

## Практическое применение

Kafka — стандарт для событийной архитектуры: интеграция микросервисов, сбор событий пользователей, потоковая обработка. Продюсеры и консьюмеры развязывают сервисы: источник не знает потребителей. Партиции позволяют масштабировать обработку горизонтально. Понимание гарантий доставки помогает проектировать надёжные системы.


Для отказоустойчивости топикам задают фактор репликации: копии партиций хранятся на разных брокерах. Потребители могут сохранять смещения (offsets) в Kafka, что позволяет перезапускать обработку без потери позиции. Планируя систему событий, важно выбирать число партиций заранее: увеличить его можно, а уменьшить — нет.

### Разбор 1
```yaml
services:
  zookeeper:
    image: confluentinc/cp-zookeeper:latest
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
  kafka:
    image: confluentinc/cp-kafka:latest
    ports: ["9092:9092"]
    environment:
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
```
Создание топика:
```bash
kafka-topics.sh --create --topic quickstart --partitions 2 --replication-factor 1 --bootstrap-server localhost:9092
```

### Разбор 2
```python
from kafka import KafkaProducer

producer = KafkaProducer(bootstrap_servers="localhost:9092")
for i in range(5):
    producer.send("quickstart", key=b"key", value=f"msg-{i}".encode())
producer.flush()
producer.close()
```
flush() дожидается отправки всех буферизованных сообщений.

### Разбор 3
```python
from kafka import KafkaConsumer

consumer = KafkaConsumer("quickstart", bootstrap_servers="localhost:9092")
for i, msg in enumerate(consumer):
    print(msg.key, msg.value, msg.offset)
    if i == 4:
        break
```
Offset — номер сообщения в партиции; чтение продолжается со следующего.

### Разбор 4
При одной группе и 2 партициях каждый консьюмер получает ровно одну партицию; если партиций больше, чем консьюмеров — некоторые читают по несколько; если меньше — часть консьюмеров простаивает.

### Разбор 5
```python
for user in (b"user-1", b"user-2"):
    for i in range(5):
        producer.send("orders", key=user, value=str(i).encode())
```
Хеш ключа определяет партицию: одинаковые ключи → одна партиция → порядок внутри неё сохраняется.

### Разбор 6
```python
from kafka import KafkaConsumer, TopicPartition

consumer = KafkaConsumer("quickstart", bootstrap_servers="localhost:9092",
                         enable_auto_commit=False)
for msg in consumer:
    try:
        process(msg)
        consumer.commit()
    except Exception as e:
        logging.exception(e)
```
Ручной commit после обработки гарантирует at-least-once; без commit сообщение будет перечитано.

### Разбор 7
```python
producer = KafkaProducer(bootstrap_servers="localhost:9092",
                         key_serializer=str.encode)
keys = ["a", "b", "c", "d", "e"]
for i, k in enumerate(keys):
    future = producer.send("users", key=k, value=str(i).encode())
    print(future.get().partition)
```
future.get() даёт метаданные (partition) — видно распределение ключей по партициям.
