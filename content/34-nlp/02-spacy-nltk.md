В предыдущем уроке мы делали предобработку вручную. Теперь посмотрим на две библиотеки, которые делают это за нас и дают гораздо больше: **NLTK** — классическая академическая библиотека с большим набором корпусов, и **spaCy** — современная промышленная библиотека с быстрыми обученными моделями.

## Установка и модели

NLTK ставится как обычный пакет, часть данных скачивается отдельно командами `nltk.download(...)`. spaCy требует ещё и языковую модель — для русского это `ru_core_news_sm`:

```bash
pip install nltk spacy
python -m spacy download ru_core_news_sm
```

Модель — это набор весов, которые определяют, как spaCy будет разбирать текст. Пока модель не загружена, `nlp(text)` не работает.

## NLTK: токенизация и части речи

NLTK умеет разбивать текст на предложения (`sent_tokenize`) и слова (`word_tokenize`), а также определять части речи:

```python
import nltk
nltk.download("punkt_tab")
nltk.download("averaged_perceptron_tagger_eng")

from nltk.tokenize import sent_tokenize, word_tokenize
from nltk import pos_tag

text = "Москва — столица России. Python популярен среди разработчиков."
sentences = sent_tokenize(text)
print(sentences)  # ['Москва — столица России.', 'Python популярен среди разработчиков.']

tokens = word_tokenize(text)
print(pos_tag(tokens))
```

`pos_tag` вернёт список пар `(слово, тег)`. Теги вида `NN` — существительное, `VB` — глагол, `JJ` — прилагательное. Важно: стандартный теггер NLTK обучен на английском, поэтому для русского он даёт неточные метки — это известное ограничение, и для русского текста лучше брать spaCy.

## spaCy: пайплайн «из коробки»

spaCy строит пайплайн: текст → токенизация → лемматизация → части речи → синтаксический разбор → именованные сущности. Всё это происходит в один вызов:

```python
import spacy

nlp = spacy.load("ru_core_news_sm")
doc = nlp("Москва — столица России. Python популярен среди разработчиков.")

for token in doc:
    print(token.text, token.lemma_, token.pos_, token.dep_)
```

Здесь `token.text` — исходная форма, `token.lemma_` — лемма (словарная форма), `token.pos_` — часть речи, `token.dep_` — роль в предложении (подлежащее, сказуемое и т.д.). Обрати внимание на лемматизацию: для русского она работает на порядок лучше, чем у NLTK, потому что spaCy использует словарь и морфологические правила русского языка. Это тот самый случай, когда мы обещали в прошлом уроке полноценную лемматизацию.

## Именованные сущности (NER)

NER — это поиск в тексте имён, организаций, дат, локаций. spaCy помечает их атрибутом `ent_`:

```python
doc = nlp("Стив Джобс основал компанию Apple в 1976 году в Купертино.")
for ent in doc.ents:
    print(ent.text, ent.label_)
```

Вывод: `Стив Джобс PERSON`, `Apple ORG`, `1976 году DATE`, `Купертино LOC`. Типы сущностей зависят от модели: для `ru_core_news_sm` это `PER`/`PERSON`, `ORG`, `LOC`, `DATE` и другие.

## Разбиение на предложения в обоих подходах

```python
# NLTK
sentences_nltk = sent_tokenize(text)

# spaCy
doc = nlp(text)
sentences_spacy = [sent.text for sent in doc.sents]
```

Оба способа рабочие, но spaCy дополнительно сохраняет связи между предложениями и токенами — это важно для суммаризации и вопросно-ответных систем, которые мы разберём позже.

## Когда что выбирать

- **NLTK** — когда нужны корпусы (stopwords, wordnet), обучение собственных теггеров, академические эксперименты, лёгкий вес.
- **spaCy** — когда нужно быстро и точно обработать много текста: лемматизация, POS, NER, зависимости, готовые пайплайны.

Часто их используют вместе: NLTK — для словарей и метрик, spaCy — для разбора. Так мы и будем делать в следующих уроках.

### Разбор 4
Решение:

```python
import spacy
from collections import Counter

nlp = spacy.load("ru_core_news_sm")

def pos_distribution(text):
    doc = nlp(text)
    return Counter(token.pos_ for token in doc)

text = "Красивая кошка быстро бежала по двору, а пёс громко лаял."
dist = pos_distribution(text)
for pos, count in dist.most_common(3):
    print(f"{pos}: {count}")
```

Файл `test_pos.py`:

```python
from pos_distribution import pos_distribution

def test_pos_counts():
    dist = pos_distribution("Красивая кошка быстро бежала по двору, а пёс громко лаял.")
    assert dist["NOUN"] > dist["ADJ"]
    assert "VERB" in dist
```

Запуск: `pytest -q` → `1 passed`.

Что здесь происходит? `Counter` собирает частоты меток частей речи. В тексте существительные: `кошка`, `двору`, `пёс` — 3, прилагательное одно: `Красивая`; глаголы: `бежала`, `лаял` — 2. Тест проверяет содержательное свойство: существительных больше, чем прилагательных, и глаголы присутствуют. Такие «инвариантные» тесты полезны, потому что не зависят от точного формата вывода.

### Разбор 5
Решение:

```python
import spacy
from collections import Counter

nlp = spacy.load("ru_core_news_sm")

def find_keywords(text, top_n=5):
    doc = nlp(text)
    lemmas = [
        token.lemma_ for token in doc
        if not token.is_stop and not token.is_punct and not token.is_space
    ]
    return Counter(lemmas).most_common(top_n)
```

Файл `test_keywords.py`:

```python
from find_keywords import find_keywords

def test_top_keyword():
    keywords = find_keywords("Машина едет по дороге, а вторая машина стоит на обочине.")
    assert keywords[0][0] == "машина"
    assert keywords[0][1] == 2

def test_no_stopwords_no_punct():
    tokens = [w for w, _ in find_keywords("Машина едет по дороге, а вторая машина стоит.")]
    for stop in ["по", "а"]:
        assert stop not in tokens

def test_top_n_bound():
    assert len(find_keywords("Машина едет по дороге.", top_n=3)) <= 3
```

Запуск: `pytest -q` → `3 passed`.

Что здесь происходит? `token.is_stop` отбрасывает стоп-слова, `token.is_punct` — знаки препинания, `token.is_space` — пробелы. Оставшиеся леммы считаются через `Counter.most_common(top_n)`. «машина» встречается в тексте дважды (оба раза — одна лемма), поэтому пара `("машина", 2)` гарантированно на первом месте. Тесты проверяют и топ, и чистоту результата, и ограничение длины.
