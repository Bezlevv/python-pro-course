Машины не читают текст так, как это делаем мы. Для модели «Привет!», «привет» и «приветствую» — три разные строки, пока мы сами не приведём их к общему виду. Предобработка — это первый этап любого NLP-пайплайна: превратить «грязный» текст из соцсетей, комментариев или отзывов в чистый, нормализованный набор токенов, с которым уже могут работать алгоритмы.

## Зачем это нужно

Представь, что ты собираешь статистику упоминаний бренда. Если просто считать вхождения подстроки, то `Nike`, `nike`, `NIKE!` и `nike_` будут считаться по-разному. Без нормализации модель «распыляет» сигнал по сотням почти одинаковых форм и обучается хуже. Предобработка решает несколько задач:

- убирает шум — ссылки, хэштеги, упоминания, лишние знаки препинания;
- приводит слова к единой форме — регистр, окончания, словоформы;
- отсекает мусорные слова — стоп-слова без смысловой нагрузки;
- сокращает словарь — вместо тысяч форм оставляет десятки тысяч уникальных смыслов.

## Пайплайн предобработки

Классическая цепочка выглядит так: **нормализация → очистка → токенизация → удаление стоп-слов → стемминг/лемматизация**. Конечно, для конкретной задачи порядок и состав шагов меняются, но базовый скелет один.

### 1. Нормализация регистра и очистка

Самый простой шаг — привести текст к нижнему регистру. Затем через регулярные выражения уберём ссылки, упоминания, хэштеги и знаки препинания:

```python
import re

text = "Привет!!! Я учу NLP в 2026 году. Пиши мне: https://example.com #python"
cleaned = re.sub(r"https?://\S+|#\w+|@\w+|[^\w\s]", "", text.lower())
print(cleaned)
```

Вывод: `привет я учу nlp в 2026 году пиши мне`. Обрати внимание: `[^\w\s]` удаляет всё, что не буква, не цифра и не пробел, а `\S+` — сами URL. Цифры часто оставляют — они могут нести смысл (годы, цены).

### 2. Токенизация

Токенизация разбивает текст на токены — слова, числа, иногда знаки препинания. Простой `text.split()` плохо работает: для `"Привет, мир!"` он вернёт `['Привет,', 'мир!']` с мусором. Лучше использовать `nltk.word_tokenize`:

```python
import nltk
nltk.download("punkt_tab")

from nltk.tokenize import word_tokenize

tokens = word_tokenize("Привет, мир! Это второй урок NLP.")
print(tokens)
```

Вывод: `['Привет', ',', 'мир', '!', 'Это', 'второй', 'урок', 'NLP', '.']`. Обрати внимание: знаки препинания стали отдельными токенами — их легко отфильтровать позже.

### 3. Стоп-слова

Стоп-слова — «и», «в», «на», «не», «что». Они встречаются часто, но не несут смысла для большинства задач. В `nltk` есть готовые списки:

```python
import nltk
nltk.download("stopwords")

from nltk.corpus import stopwords

sw = set(stopwords.words("russian"))
filtered = [t for t in tokens if t.lower() not in sw]
print(filtered)
```

### 4. Стемминг и лемматизация

Здесь мы приводим словоформы к основе. **Стемминг** просто обрезает окончания: `красивый → красив`, `бежал → бежал`. Он быстрый, но грубый и иногда режет не туда. **Лемматизация** приводит слово к словарной форме — лемме: `красивый → красивый`, `бежал → бежать`. Она точнее, но медленнее и требует словарь.

Для русского в `nltk` используем `SnowballStemmer("russian")`:

```python
from nltk.stem import SnowballStemmer

stemmer = SnowballStemmer("russian")
for w in ["красивый", "красивая", "красота"]:
    print(w, "->", stemmer.stem(w))
```

Вывод: `красивый -> красив`, `красивая -> красив`, `красота -> красота`. Для английского есть классический `PorterStemmer`:

```python
from nltk.stem import PorterStemmer, WordNetLemmatizer
import nltk

nltk.download("wordnet")
ps = PorterStemmer()
wnl = WordNetLemmatizer()

print(ps.stem("running"))              # run
print(wnl.lemmatize("better", pos="a"))  # good
```

Стемминг и лемматизация — не взаимозаменяемые шаги: обычно выбирают один из них. Лемматизация дороже, но качество выше, поэтому для русского текста её чаще предпочитают.

### Разбор 1
Решение:

```python
import re

def clean_text(text):
    text = text.lower()
    text = re.sub(r"https?://\S+|@\w+|#\w+", "", text)
    text = re.sub(r"[^\w\s]", "", text)
    return re.sub(r"\s+", " ", text).strip()

print(clean_text("Привет, @ivan! Смотри #NLP: https://example.com/learn"))
```

Вывод: `привет иван смотри nlp learn`.

Что здесь происходит? Первый `re.sub` убирает URL, упоминания и хэштеги — шаблон `\S+` жадно глотает всё до пробела, поэтому ссылка удаляется целиком вместе с хвостом. Второй `re.sub` стирает знаки препинания: класс `[^\w\s]` означает «всё, что не буква/цифра (`\w`) и не пробел (`\s`)». Третий схлопывает повторяющиеся пробелы (например, образовавшиеся после удаления хэштега) и `strip()` срезает края. Важно: `\w` в Python по умолчанию включает и русские буквы, поэтому текст на кириллице не пострадает.

### Разбор 2
Решение:

```python
import nltk
from nltk.tokenize import word_tokenize
from nltk.corpus import stopwords

sw = set(stopwords.words("russian"))

def tokenize_words(text):
    tokens = word_tokenize(text.lower())
    return [t for t in tokens if t.isalnum() and t not in sw]
```

Файл `test_tokenize.py`:

```python
from tokenize_words import tokenize_words

def test_no_punct_and_has_content_word():
    tokens = tokenize_words("Привет, мир! Это урок.")
    assert "мир!" not in tokens
    assert "," not in tokens
    assert "урок" in tokens

def test_no_stopwords():
    tokens = tokenize_words("Я иду в школу на урок")
    for stop in ["и", "в", "на"]:
        assert stop not in tokens
```

Запуск: `pytest -q` → `2 passed`.

Что здесь происходит? `t.isalnum()` оставляет только токены из букв и цифр — запятые и восклицательные знаки отсекаются. `t not in sw` отбрасывает стоп-слова. В тестах мы проверяем именно контракт функции: отсутствие мусора и наличие содержательных слов. Кстати, стоп-слова мы удаляем до слияния с основным текстом — сравниваем уже нормализованный (нижний регистр) токен со списком стоп-слов, поэтому `"И"` и `"и"` не разойдутся.

### Разбор 3
Решение:

```python
import nltk
nltk.download("wordnet")

from nltk.stem import SnowballStemmer, WordNetLemmatizer

stemmer = SnowballStemmer("russian")
lemmatizer = WordNetLemmatizer()

def normalize(tokens, mode="stem"):
    if mode == "stem":
        return [stemmer.stem(t) for t in tokens]
    return [lemmatizer.lemmatize(t, pos="n") for t in tokens]

words = ["красивый", "красивая", "дома", "дом"]
print("stem:", normalize(words, "stem"))
print("lemma:", normalize(words, "lemma"))
```

Вывод:

```
stem: ['красив', 'красив', 'дом', 'дом']
lemma: ['красивый', 'красивая', 'дом', 'дом']
```

Что здесь происходит? Стемминг обрезает окончания бездумно: `красивый` и `красивая` оба становятся `красив`. Лемматизация с `pos="n"` ищет словарную форму — но для прилагательного `красивый` с `pos="n"` она ничего не делает (лемматизатор WordNet настроен на английские части речи, а русскую морфологию не знает). Зато существительные `дома` и `дом` оба сходятся в `дом`. Вывод: для русского стемминг надёжнее в `nltk`, а полноценная русская лемматизация доступна в spaCy — и мы познакомимся с ней в следующем уроке.

### Разбор 4
Решение:

```python
from collections import Counter
from nltk.probability import FreqDist
from clean_text import clean_text
from tokenize_words import tokenize_words

text = "Кофе в этом кафе отличный. Кофеварка на кухне старая, но кофе всё равно вкусный."

freq = FreqDist(tokens)
for word, count in freq.most_common(3):
    print(f"{word}: {count}")
```

Вывод (пример):

```
кофе: 2
кафе: 1
отличный: 1
```

Что здесь происходит? После очистки и токенизации без стоп-слов остаются `кофе, кафе, отличный, кофеварка, кухне, старая, вкусный`. `FreqDist.most_common(3)` возвращает три пары «слово → частота». «Кофе» встречается дважды — один раз из первого предложения, один раз из третьего — и уверенно занимает первое место. Остальные слова встречаются по одному разу; точный порядок среди них зависит от внутренней сортировки, поэтому в условии порядок внутри топа и не был важен.

### Разбор 5
Решение:

```python
from clean_text import clean_text
from tokenize_words import tokenize_words
from nltk.stem import WordNetLemmatizer

lemmatizer = WordNetLemmatizer()

def preprocess(text):
    tokens = tokenize_words(clean_text(text))
    return [lemmatizer.lemmatize(t, pos="n") for t in tokens]
```

Файл `test_preprocess.py`:

```python
from preprocess import preprocess

def test_lowercase():
    assert all(t == t.lower() for t in preprocess("Привет, МИР!"))

def test_no_punct_no_stopwords():
    tokens = preprocess("Я иду в школу, но дом далеко.")
    assert all(t.isalnum() for t in tokens)
    for stop in ["и", "в", "на", "но"]:
        assert stop not in tokens

def test_lemmas_present():
    tokens = preprocess("Они бежали и бежали, но дом был далеко.")
    assert "дом" in tokens
```

Запуск: `pytest -q` → `3 passed`.

Что здесь происходит? Функция компонует три прошлых шага. Тесты проверяют инварианты пайплайна: регистр, отсутствие мусора и стоп-слов, а также что лемматизация не «потеряла» ключевое слово. Обрати внимание: `"дом"` после лемматизации остаётся `"дом"` (форма совпадает с леммой), а вот `"бежали"` превратится в `"бежал"` при `pos="n"`? Нет — лемматизатор с `pos="n"` не трогает глаголы, поэтому строгая проверка формы глагола здесь не делается: мы проверяем лишь наличие существительного. Если захочешь нормализовать и глаголы — придётся писать свою логику или брать spaCy.
