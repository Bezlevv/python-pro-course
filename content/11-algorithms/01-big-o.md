Привет! Этот модуль посвящён алгоритмам и структурам данных. Наш первый урок — фундамент всего остального: умение оценивать, насколько быстро работает алгоритм. Без этого невозможно понять, почему одна сортировка лучше другой и почему один и тот же код «тормозит» на больших данных. Разберёмся, что такое сложность и как её записывают.

## Почему скорость алгоритма важна

Когда ты пишешь программу, первый вопрос обычно такой: работает ли она? Но второй вопрос не менее важен: а как она будет работать, когда данных станет много? Список из десяти чисел обработает любая программа — причём мгновенно. Но представь миллион элементов или миллиард. Здесь разница между алгоритмами становится огромной: один справится за доли секунды, другой будет работать часы или даже годы.

Время выполнения зависит от компьютера, языка и данных, поэтому сравнивать алгоритмы по секундам неудобно. Вместо этого программисты смотрят, **как растёт число операций** при увеличении размера входных данных. Именно это и называется алгоритмической сложностью.

## Как считать операции

Возьмём простую задачу — найти максимальный элемент списка:

```python
def find_max(items):
    current_max = items[0]        # 1 операция
    for value in items:           # n повторений
        if value > current_max:   # 1 сравнение на каждое
            current_max = value
    return current_max
```

Если в списке `n` элементов, цикл выполнится `n` раз. Общее число операций примерно `1 + 2*n`, но детали не так важны. Важно главное: **при удвоении списка число операций тоже удвоится**. Такой рост называют линейным и записывают как `O(n)`.

## Нотация O-большое

Нотация `O(...)` описывает, как растёт число операций при росте `n`. Читается как «O от эн». Правила простые:

- нас интересует только **порядок роста**, поэтому константы отбрасываем: `2n + 10` → `O(n)`;
- из нескольких слагаемых остаётся только **быстро растущее**: `n² + n` → `O(n²)`;
- обычно оценивают **худший случай**, хотя иногда говорят и о среднем.

Основные классы сложности:

| Нотация | Название | Пример |
|---|---|---|
| `O(1)` | константная | доступ к элементу по индексу |
| `O(log n)` | логарифмическая | бинарный поиск |
| `O(n)` | линейная | поиск максимума, линейный поиск |
| `O(n log n)` | линейно-логарифмическая | быстрые сортировки |
| `O(n²)` | квадратичная | вложенные циклы |

## O(1): константная сложность

Чтобы понять, что такое `O(1)`, вспомни список. Обращение по индексу не зависит от размера списка:

```python
def first_element(items):
    return items[0]   # одна операция, сколько бы ни было элементов

print(first_element([5, 10, 15, 20, 25]))  # 5
```

Работает ли эта функция за одно и то же время для списка из 5 элементов и из 5 миллионов? Да. Число операций постоянно — это `O(1)`. То же самое и с доступом к значению словаря по ключу: словарь устроен так, что поиск ключа в среднем занимает константное время.

## O(n): линейная сложность

Линейная сложность — самая частая. Один проход по данным:

```python
def contains(items, target):
    for value in items:
        if value == target:
            return True
    return False
```

В худшем случае нам придётся пройти весь список: чем длиннее список, тем больше сравнений. 100 элементов — до 100 сравнений, 1000 — до 1000. Рост пропорционален `n`, поэтому это `O(n)`.

## O(n²): квадратичная сложность

Квадратичная сложность появляется, когда внутри цикла находится ещё один цикл по тем же данным:

```python
def print_pairs(items):
    for i in range(len(items)):
        for j in range(len(items)):
            print(i, j)
```

Для `n` элементов внутренний цикл выполняется `n` раз для каждого из `n` внешних — итого `n * n = n²` операций. Если `n` удвоить, число операций вырастет в четыре раза. Для больших `n` такие алгоритмы становятся очень медленными.

## Эксперимент: считаем операции

Теория станет нагляднее, если просто посчитать операции. Напишем две функции-счётчика и запустим их для разных `n`:

```python
def count_ops_linear(n):
    ops = 0
    for _ in range(n):
        ops += 1
    return ops

def count_ops_quadratic(n):
    ops = 0
    for _ in range(n):
        for _ in range(n):
            ops += 1
    return ops

for n in (10, 100, 1000, 10000):
    print(n, count_ops_linear(n), count_ops_quadratic(n))
```

Результат:

```
10 10 100
100 100 10000
1000 1000 1000000
10000 10000 100000000
```

Посмотри на столбец квадратичной сложности: при `n = 10000` это уже 100 миллионов операций. А теперь представь миллион элементов — квадратичный алгоритм сделал бы триллион шагов. Вот почему выбор алгоритма важнее скорости компьютера.

## O(log n): логарифмическая сложность

Отдельно стоит упомянуть `O(log n)`. Такой рост у алгоритмов, которые на каждом шаге отбрасывают половину данных. Классический пример — бинарный поиск в отсортированном списке (мы разберём его в уроке про поиск). Чтобы найти элемент среди миллиона чисел, хватит примерно двадцати шагов: 2²⁰ ≈ миллион. При росте данных шаги прибавляются очень медленно — это отличная сложность.

## Итог урока

Мы узнали:

- сложность описывает, как растёт число операций при росте данных;
- константы и младшие слагаемые в нотации отбрасываются;
- `O(1)` — константно, `O(n)` — линейно, `O(n²)` — квадратично;
- квадратичные алгоритмы на больших данных практически непригодны;
- `O(log n)` — очень быстрый рост, почти как константа.

### Разбор 1
Решение:

```python
def linear_sum(numbers):
    total = 0
    additions = 0
    for number in numbers:
        total += number
        additions += 1
    return total, additions

total, additions = linear_sum([4, 8, 15, 16, 23, 42])
print(f"Сумма: {total}, сложений выполнено: {additions}")

# Сложность функции — O(n): мы проходим по списку один раз,
# и число операций растёт пропорционально количеству элементов.
```

Результат:

```
Сумма: 108, сложений выполнено: 6
```

Что здесь происходит? Мы проходим по списку ровно один раз и выполняем константное число операций для каждого элемента: сложение и увеличение счётчика. Если список удвоить, удвоится и число операций — это линейный рост, `O(n)`. Обрати внимание: функция возвращает кортеж из двух значений, и мы распаковываем его в две переменные. Это удобный приём, когда нужно вернуть сразу несколько результатов.

Именно поэтому обе функции — `O(1)` (то есть число операций не зависит от размера данных). Это лучший класс сложности, и к нему стоит стремиться.

### Разбор 3
Решение:

```python
def print_pairs(items):

    for i in range(len(items)):
        for j in range(len(items)):
            print(i, j)
            pairs += 1

# Для n = 3 всего 3 * 3 = 9 пар. Сложность — O(n²),
# потому что внутренний цикл выполняется n раз для каждого

```

Результат (первые строки и последняя):

```
0 0
0 1
0 2
1 0
...
2 2
Всего пар: 9
```

Что здесь происходит? Внешний цикл проходит по всем индексам, и для каждого из них внутренний цикл снова проходит по всем индексам. Получается `n * n = n²` пар, то есть `n²` операций. Если список удвоить, пар станет в четыре раза больше — это и есть квадратичный рост. Такие алгоритмы опасны на больших данных: для `n = 10_000` это уже 100 миллионов операций. Поэтому, замечая вложенные циклы, всегда спрашивай себя: нельзя ли обойтись одним проходом?

### Разбор 4
Решение:

```python
def has_duplicates_slow(items):
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                return True
    return False

def has_duplicates_fast(items):
    seen = set()
    for value in items:
        if value in seen:
            return True
        seen.add(value)
    return False

for items in ([1, 3, 5, 3, 7], [1, 2, 3, 4]):
    print(f"Оригинал: Есть повторы: {has_duplicates_slow(items)}")
    print(f"Оптимизированный: Есть повторы: {has_duplicates_fast(items)}")
```

Результат:

```
Оригинал: Есть повторы: True
Оптимизированный: Есть повторы: True
Оригинал: Есть повторы: False
Оптимизированный: Есть повторы: False
```

Что здесь происходит? Медленная версия сравнивает каждую пару элементов — таких пар `n*(n-1)/2`, и это `O(n²)`. Быстрая версия проходит по списку один раз и запоминает встреченные значения в множестве. Проверка `value in seen` в среднем занимает `O(1)`, значит, весь проход — `O(n)`. Это классический приём оптимизации: заменить вложенный цикл на одно множество. Сложность улучшилась с квадратичной до линейной — для больших списков разница в тысячи и миллионы раз.

### Разбор 5
Решение:

```python
def count_ops_linear(n):

    return ops

def count_ops_quadratic(n):

# 10000 против 100000000. Квадратичный алгоритм делает

```

```

n=100: линейно 100, квадратично 10000
n=1000: линейно 1000, квадратично 1000000
n=10000: линейно 10000, квадратично 100000000
```

Что здесь происходит? Мы буквально пересчитываем операции: линейная функция выполняет тело цикла `n` раз, квадратичная — `n*n` раз. При `n = 10000` это 10 тысяч против 100 миллионов — разница в 10 тысяч раз. Именно поэтому важно уметь определять сложность до написания кода: квадратичный алгоритм на больших данных просто не успеет отработать. Запомни порядок роста: `O(1) < O(log n) < O(n) < O(n log n) < O(n²)`.

* Правильный ответ: Бинарный поиск
Бинарный поиск — O(log n), а поиск максимума — O(n): на больших данных разница огромна.

Какая сложность у алгоритма, который на каждом шаге отбрасывает половину данных?
- O(1)
- O(log n)
- O(n)
* Правильный ответ: O(log n)
Отбрасывание половины данных на каждом шаге даёт логарифмический рост числа операций.
