Привет! В этом уроке ты освоишь две техники, которые превращают квадратичные переборы в линейные: **два указателя** и **скользящее окно**. Они простые, но невероятно мощные — на их основе строится много задач на собеседованиях и олимпиадах.

## Два указателя

Представь отсортированный массив и задачу найти пару чисел с суммой равной `target`. Тупой перебор — два вложенных цикла: O(n²). А теперь подумаем: поставим указатель `left` в начало, а `right` — в конец. Если сумма `nums[left] + nums[right]` слишком мала, нужно её увеличить — сдвигаем `left` вправо. Если слишком велика — сдвигаем `right` влево. Если равна — нашли.

```python
def two_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return left, right
        if s < target:
            left += 1
        else:
            right -= 1
    return None
```

Почему это работает? На каждом шаге мы отбрасываем ровно одну «бесполезную» пару: если сумма мала, то `nums[left]` со всеми элементами правее `right` тоже даст сумму меньше target (массив отсортирован!), значит, этот указатель можно смело двигать. Указатели сближаются, и всего проверяется O(n) пар.

## Скользящее окно фиксированной длины

Теперь другая задача: найти максимальную сумму подмассива длины ровно `k`. Перебор всех окон — O(n·k). Но заметим: при сдвиге окна на одну позицию вправо мы **убираем один элемент слева и добавляем один справа**. Сумму нового окна можно получить из старой за O(1):

```python
def max_sum_fixed(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best
```

Сначала считаем сумму первого окна, затем «скользим»: добавляем `nums[i]`, вычитаем `nums[i - k]`. Итого O(n) времени и O(1) памяти.

## Скользящее окно переменной длины

Ещё интереснее окна, размер которых меняется. Классика: найти длину самой длинной подстроки без повторяющихся символов. Держим два указателя: `left` — начало окна, `right` — его конец. Расширяем окно вправо, добавляя символы, а если символ уже есть в окне — сужаем окно слева, пока дубликат не исчезнет:

```python
def longest_unique(s):
    seen = {}
    left = 0
    best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1
        seen[ch] = right
        best = max(best, right - left + 1)
    return best
```

Словарь `seen` хранит последнюю позицию каждого символа. Если символ уже встречался в текущем окне (позиция ≥ `left`), двигаем `left` сразу за ту позицию. Каждый символ входит в окно и выходит из него не более одного раза — снова O(n).

## Когда это работает

- **Два указателя**: массив отсортирован или есть монотонность. Тогда отбрасывание пары безопасно.
- **Скользящее окно**: нужно что-то считать по непрерывным подмассивам/подстрокам. Инвариант окна (например, «все символы уникальны») поддерживается за O(1) на сдвиг.

Если задача позволяет — всегда пробуй свести O(n²) к O(n) такими техниками. Теперь закрепим на пяти задачах.

### Подсказка 1
Поставь `left = 0`, `right = n - 1`. Пока `left < right`, считай `s = nums[left] + nums[right]`. Если `s == target` — выведи пару. Если `s < target` — `left += 1`, иначе `right -= 1`. Массив отсортирован, поэтому сдвиг всегда безопасен.

### Подсказка 2
Сначала посчитай сумму первых `k` элементов: `window = sum(nums[:k])`. Затем в цикле от `k` до конца: `window += nums[i] - nums[i - k]` и обновляй максимум. Важно не вызывать `sum` заново для каждого окна.

### Подсказка 3
Словарь `seen` хранит последний индекс каждого символа. Когда встречаешь символ, который уже есть в окне, передвинь `left` на `seen[ch] + 1`. Длина окна — `right - left + 1`, обновляй максимум. Не забудь проверять `seen[ch] >= left`, чтобы не сжимать окно из-за старых позиций.

### Подсказка 4
Используй переменную `write_idx` — куда писать очередной уникальный элемент. Иди по массиву с `i = 1`: если `nums[i] != nums[i - 1]`, скопируй его в `nums[write_idx]` и увеличь `write_idx`. В конце `write_idx` — новая длина.

### Подсказка 5
Заведи `left = 0`, `right = n - 1` и считай площадь для каждой пары. Двигай тот указатель, у которого высота меньше (или любой при равенстве): меньшая стенка ограничивает объём, и трогать её дальше бессмысленно.

### Разбор 1
Решение:

```python
import sys

def main():
    data = sys.stdin.read().strip().splitlines()
    n, target = map(int, data[0].split())
    nums = list(map(int, data[1].split()))

    left, right = 0, n - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            print(nums[left], nums[right])
            return
        if s < target:
            left += 1
        else:
            right -= 1

    print("НЕТ")

if __name__ == "__main__":
    main()
```

Ключевое свойство, на котором всё держится, — отсортированность. Если сумма мала, то даже с самым большим возможным партнёром (`nums[right]`) текущий `nums[left]` не дотягивает до target, значит, этот элемент не может участвовать ни в одной подходящей паре — смело сдвигаем `left`. Аналогично, если сумма велика, `nums[right]` слишком велик для любого партнёра левее, сдвигаем `right`. Так мы за O(n) отбрасываем все бесполезные пары, не перебирая их. Для входа:

```
6 10
1 3 4 6 7 9
```

суммы: 1+9=10 — сразу попадание, вывод `1 9`. Если бы пары не было, указатели встретились бы, и мы напечатали бы `НЕТ`.

### Разбор 2
Решение:

```python
import sys

def main():
    data = sys.stdin.read().strip().splitlines()
    n, k = map(int, data[0].split())
    nums = list(map(int, data[1].split()))

    window = sum(nums[:k])
    best = window
    for i in range(k, n):
        window += nums[i] - nums[i - k]
        best = max(best, window)

    print(best)

if __name__ == "__main__":
    main()
```

Сначала считаем сумму первого окна из `k` элементов. Дальше каждое следующее окно отличается от предыдущего ровно на два элемента: добавляется `nums[i]` справа и убирается `nums[i - k]` слева. Обновление суммы — O(1), поэтому весь алгоритм — O(n) вместо O(n·k). Для входа:

```
7 3
2 1 5 1 3 2 8
```

суммы окон: 8, 7, 9, 6, 13 — максимум 13. Обрати внимание на границы: цикл идёт от `k` до `n - 1`, и `nums[i - k]` — это в точности элемент, выходящий из окна.

### Разбор 3
Решение:

```python
import sys

def main():
    s = sys.stdin.readline().strip()
    seen = {}
    left = 0
    best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1
        seen[ch] = right
        best = max(best, right - left + 1)
    print(best)

if __name__ == "__main__":
    main()
```

Окно `s[left:right+1]` всегда содержит только уникальные символы. Когда мы встречаем символ `ch`, который уже есть в окне, мы не просто удаляем его, а прыгаем `left` сразу за его прошлую позицию — так мы не тратим время на пошаговое сужение. Проверка `seen[ch] >= left` отличает «старые» вхождения (вне окна) от актуальных: если позиция символа левее `left`, он окну не мешает. После обновления записываем новую позицию и считаем длину. Для `abcabcbb` максимальная подстрока — `abc` (длина 3). Каждый символ обрабатывается константное число раз — итого O(|s|).

### Разбор 4
Решение:

```python
import sys

def main():
    data = sys.stdin.read().strip().splitlines()
    n = int(data[0])
    nums = list(map(int, data[1].split()))

    if n == 0:
        print(0)
        print()
        return

    write_idx = 1
    for i in range(1, n):
        if nums[i] != nums[i - 1]:
            nums[write_idx] = nums[i]
            write_idx += 1

    print(write_idx)
    print(*nums[:write_idx])

if __name__ == "__main__":
    main()
```

Первый элемент всегда уникален, поэтому `write_idx` стартует с 1. Указатель `i` читает исходный массив, а `write_idx` пишет в его начало — мы переиспользуем тот же список, не тратя память. Когда встречаем новый элемент (отличается от предыдущего), копируем его на позицию `write_idx` и двигаем оба указателя. После прохода первые `write_idx` элементов — ровно уникальная последовательность. Для входа:

```
8
1 1 2 2 3 3 3 4
```

массив превратится в `1 2 3 4`, новая длина — 4. Вывод: `4` и `1 2 3 4`. Сложность — O(n) времени и O(1) дополнительной памяти.

### Разбор 5
Решение:

```python
import sys

def main():
    data = sys.stdin.read().strip().splitlines()
    n = int(data[0])
    h = list(map(int, data[1].split()))

    left, right = 0, n - 1
    best = 0
    while left < right:
        area = min(h[left], h[right]) * (right - left)
        best = max(best, area)
        if h[left] < h[right]:
            left += 1
        else:
            right -= 1

    print(best)

if __name__ == "__main__":
    main()
```

Объём воды ограничен более низкой стенкой. Если `h[left] < h[right]`, то любая пара с текущей `left` и любой стенкой правее не даст больше текущей площади: расстояние меньше, а ограничивающая стенка не выше. Значит, `left` можно смело двигать вправо. Симметрично для `right`. Так мы проверяем все «перспективные» пары за один проход. Для входа:

```
9
1 8 6 2 5 4 8 3 7
```

максимум — 49: между стенками высотой 8 (индекс 1) и 7 (индекс 8), `min(8, 7) * 7 = 49`. Алгоритм работает за O(n) вместо O(n²) полного перебора.

Почему два указателя работают на отсортированном массиве?
- Потому что сдвиг указателя безопасно отбрасывает бесполезные пары
- Потому что отсортированный массив занимает меньше памяти
- Потому что Python быстрее работает с отсортированными данными
* Правильный ответ: Потому что сдвиг указателя безопасно отбрасывает бесполезные пары
Монотонность гарантирует: если сумма мала, левый элемент бесполезен, а если велика — правый.

Какова сложность поиска пары с заданной суммой двумя указателями?
- O(n²)
- O(n log n)
- O(n)
* Правильный ответ: O(n)
Каждый шаг сдвигает один указатель, и всего делается не более n шагов.

Что происходит с суммой скользящего окна при сдвиге на одну позицию?
- Она пересчитывается с нуля
- Добавляется новый элемент и вычитается вышедший
- Она удваивается
* Правильный ответ: Добавляется новый элемент и вычитается вышедший
Поэтому обновление суммы занимает O(1), а не O(k).
