Что делает git rebase main (находясь на ветке feature)?
- Создаёт merge-коммит
- Переносит коммиты feature поверх верхушки main
- Удаляет ветку main
- Копирует файлы из main в feature
* Правильный ответ: Переносит коммиты feature поверх верхушки main
Rebase срезает коммиты текущей ветки и применяет их заново поверх заданной базы, делая историю линейной.

Почему нельзя делать rebase уже опубликованных коммитов?
- Это медленно
- Другие участники получат расходящиеся истории и конфликты
- Git запрещает это навсегда
- Коммиты пропадут из reflog
* Правильный ответ: Другие участники получат расходящиеся истории и конфликты
Переписывание общих коммитов ломает историю у тех, кто их уже скачал.

Что нужно сделать с маркерами при разрешении конфликта?
- Оставить их в файле
- Удалить все три маркера и сохранить нужный вариант
- Превратить их в комментарии
- Переместить их в конец файла
* Правильный ответ: Удалить все три маркера и сохранить нужный вариант
Маркеры — служебная разметка: после выбора варианта их обязательно удаляют.

Что при git merge означает --theirs?
- Вариант текущей ветки, в которую вливаются изменения
- Вариант вливаемой ветки
- Вариант из индекса
- Вариант из stash
* Правильный ответ: Вариант вливаемой ветки
При merge ours — текущая ветка, theirs — вливаемя. При rebase роли меняются.

Что хранит git reflog?
- Только удалённые ветки
- Историю всех перемещений HEAD: коммиты, checkout, reset, merge, rebase
- Содержимое всех файлов
- Пароли и ключи доступа
* Правильный ответ: Историю всех перемещений HEAD: коммиты, checkout, reset, merge, rebase
Каждое изменение указателя HEAD фиксируется в reflog с меткой времени и описанием действия.

Что возвращает git fsck --lost-found?
- Список висячих (dangling) объектов, на которые никто не ссылается
- Список всех веток репозитория
- Список настроенных remote
- Список конфликтующих файлов
* Правильный ответ: Список висячих (dangling) объектов, на которые никто не ссылается
Коммиты без ссылок ищутся через fsck; их можно восстановить по хэшу.

Что делает хук pre-commit?
- Запускается перед созданием коммита и может его заблокировать
- Запускается после push
- Проверяет сообщение коммита
- Создаёт ветки
* Правильный ответ: Запускается перед созданием коммита и может его заблокировать
pre-commit выполняется до записи коммита; ненулевой код отменяет коммит.

Чем --force-with-lease отличается от --force?
- Он сначала проверяет, что remote-ветка не менялась с последнего fetch
- Он работает только с bare-репозиториями
- Он не позволяет переписывать историю вообще
- Он требует явного подтверждения
* Правильный ответ: Он сначала проверяет, что remote-ветка не менялась с последнего fetch
Если кто-то успел запушить, --force-with-lease откажется, а голый --force затрёт чужую работу.

Что создаёт git worktree add ../fix -b hotfix/fix?
- Новую рабочую копию на новой ветке
- Клон целого репозитория
- Bare-репозиторий
- Новый remote
* Правильный ответ: Новую рабочую копию на новой ветке
Worktree добавляет ещё одно рабочее дерево того же репозитория на указанной ветке.

Как правильно перенести фикс из hotfix в main и release?
- git cherry-pick <sha_fix> в обеих ветках
- git rebase hotfix
- git merge --no-ff main
- git reset --hard <sha_fix>
* Правильный ответ: git cherry-pick <sha_fix> в обеих ветках
cherry-pick применяет конкретный коммит в каждой ветке отдельно, не таща остальную историю.
