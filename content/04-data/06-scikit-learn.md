## Что такое scikit-learn

scikit-learn (или просто sklearn) — библиотека с единообразным API для машинного обучения: классификация, регрессия, кластеризация, предобработка, подбор моделей. Все модели работают одинаково: метод `fit()` обучает, `predict()` предсказывает, `score()` оценивает. Выучишь один интерфейс — сможешь пользоваться сотнями алгоритмов.

Установка: `pip install scikit-learn`.

## Разделение данных

Нельзя оценивать модель на тех же данных, на которых она училась — она их просто запомнит, и точность окажется обманчиво высокой. Поэтому данные режут на обучающую и тестовую части функцией `train_test_split`:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
print(X_train.shape, X_test.shape)
```

`test_size=0.25` означает, что четверть данных уйдёт в тест. `random_state` фиксирует генератор случайных чисел, чтобы эксперимент был воспроизводимым, `stratify=y` сохраняет пропорции классов в обеих частях.

## Предобработка

Алгоритмы чувствительны к масштабу признаков. `StandardScaler` приводит каждый признак к среднему 0 и стандартному отклонению 1:

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

Обрати внимание на важную деталь: `fit_transform` вызывается только на обучающей части, а на тестовой — лишь `transform`. Так мы не «подглядываем» в тестовые данные при калибровке преобразования.

Категориальные признаки кодируются числами через `OneHotEncoder`:

```python
from sklearn.preprocessing import OneHotEncoder
import numpy as np

cat = np.array([["Москва"], ["СПб"], ["Москва"]])
enc = OneHotEncoder(sparse_output=False)
print(enc.fit_transform(cat))
```

## Пайплайн Pipeline

Ручная цепочка шагов громоздка и в ней легко ошибиться: забыть применить scaler к тесту — и получишь чепуху. `Pipeline` собирает шаги в один объект:

```python
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(max_iter=2000)),
])
pipe.fit(X_train, y_train)
print(pipe.score(X_test, y_test))
```

Теперь `fit` прогоняет данные по всем шагам по очереди, и утечка данных становится невозможной. Плюс пайплайн можно сохранять целиком и переиспользовать на новых данных.

## Оценка качества

`accuracy_score` показывает долю правильных ответов, а `classification_report` — больше деталей: точность, полноту и F1-меру по каждому классу:

```python
from sklearn.metrics import accuracy_score, classification_report

y_pred = pipe.predict(X_test)
print(accuracy_score(y_test, y_pred))
print(classification_report(y_test, y_pred))
```

А `cross_val_score` прогоняет обучение на K частях данных, что даёт честную оценку устойчивости модели:

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(pipe, X, y, cv=5)
print(scores.mean().round(3), scores.std().round(3))
```

### Разбор 1
Полное решение:

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, classification_report

X, y = load_breast_cancer(return_X_y=True)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42
)

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(max_iter=2000)),
])

pipe.fit(X_train, y_train)

y_pred = pipe.predict(X_test)
print(accuracy_score(y_test, y_pred))
print(classification_report(y_test, y_pred))

scores = cross_val_score(pipe, X, y, cv=5)
print(scores.mean().round(3), scores.std().round(3))
```

Разбираем по шагам. `load_breast_cancer(return_X_y=True)` возвращает матрицу признаков `X` и вектор меток `y`: 569 наблюдений, 30 числовых признаков (размеры опухолей и т.п.), два класса — доброкачественная и злокачественная опухоль. `train_test_split` оставляет 25% данных для теста; благодаря `random_state=42` любой запуск даст одно и то же разбиение.

`Pipeline` объединяет масштабирование и модель. При вызове `fit` данные сначала проходят через `StandardScaler` (среднее 0, стандартное отклонение 1), затем `LogisticRegression` обучается на нормированных значениях. `max_iter=2000` увеличивает лимит итераций решателя, чтобы логистическая регрессия гарантированно сошлась. При `predict` конвейер автоматически применяет те же преобразования к новым данным — забыть про scaler невозможно.

`accuracy_score` — доля правильных ответов на тесте. `classification_report` показывает precision/recall/F1 по каждому классу — это важно, когда классы несбалансированы. Наконец, `cross_val_score` делит данные на 5 частей (`cv=5`), пять раз обучает модель на четырёх частях и проверяет на пятой. Среднее — ожидаемая точность на новых данных, стандартное отклонение — разброс по складкам. Так выглядит честная оценка любой модели перед тем, как отдавать её в эксплуатацию.

На типичном запуске получится примерно: `0.972...`, отчёт с F1 ≈ 0.99 для обоих классов, затем строка вида `0.97 0.01`.

```python
import numpy as np
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y

print(X_train.shape, X_test.shape)
print("Классы в train:", np.bincount(y_train))
print("Классы в test:", np.bincount(y_test))
```

Разберём по шагам. В датасете ирисов 150 наблюдений: по 50 на каждый из трёх видов, у каждого 4 признака (длина и ширина чашелистика и лепестка). `test_size=0.3` отправляет 30% данных в тест: 45 строк, остальные 105 остаются на обучение.

Параметр `stratify=y` — ключевая деталь: разбиение происходит так, чтобы пропорции классов в train и test совпадали с исходными. Без стратификации при малом датасете могло бы случиться, что в тест попадёт слишком много представителей одного вида и оценка исказится. `np.bincount` считает, сколько раз встречается каждая целая метка: в train получается по 35 экземпляров каждого вида (105 ÷ 3), в test — по 15 (45 ÷ 3).

Такая проверка — хорошая привычка: перед обучением всегда стоит убедиться, что разбиение корректно и все классы представлены в обеих частях, иначе модель может никогда не увидеть какой-то класс в процессе обучения.

### Разбор 3
Полное решение:

```python
import numpy as np
from sklearn.preprocessing import StandardScaler

data = np.array([[100, 2], [200, 4], [150, 6]])
scaler = StandardScaler()
scaled = scaler.fit_transform(data)

print(scaled.round(2))
print("Средние:", scaled.mean(axis=0).round(10))
print("Стандартные отклонения:", scaled.std(axis=0).round(10))
```

Разберём по шагам. `StandardScaler` для каждого столбца вычисляет среднее и стандартное отклонение, а затем заменяет каждое значение на z-оценку: `(x - mean) / std`.

Для первого столбца [100, 200, 150] среднее равно 150, отклонение — около 40.82. Значения превращаются в −1.22, 1.22 и 0. Для второго столбца [2, 4, 6] среднее равно 4, отклонение — около 1.63: получаются −1.22, 0 и 1.22. Обрати внимание, что после преобразования «центр» каждого столбца — это 0, а разброс — 1, то есть все признаки получают одинаковый масштаб.

Проверка `scaled.mean(axis=0)` подтверждает нулевые средние, а `scaled.std(axis=0)` — единичные стандартные отклонения. Округление до 10 знаков убирает погрешности плавающей точки. Именно так выглядит стандартизация — обязательный шаг перед обучением многих алгоритмов, например логистической регрессии или k-NN.

### Разбор 4
Полное решение:

```python
import numpy as np
from sklearn.preprocessing import OneHotEncoder

cities = np.array([["Москва"], ["СПб"], ["Москва"], ["Казань"]])
enc = OneHotEncoder(sparse_output=False)
encoded = enc.fit_transform(cities)

print(encoded)

```

Разберём по шагам. `OneHotEncoder` превращает категориальные значения в бинарные векторы: для каждой категории создаётся отдельный столбец, в котором стоит 1 у соответствующей строки и 0 у остальных. Категории упорядочиваются в алфавитном порядке: Казань, Москва, СПб — именно поэтому `enc.categories_[0]` показывает `['Казань' 'Москва' 'СПб']`, а не порядок исходного массива.

Каждая строка результата содержит ровно одну единицу: «Москва» → [0, 1, 0], «СПб» → [0, 0, 1], «Казань» → [1, 0, 0]. Параметр `sparse_output=False` заставляет вернуть обычный плотный массив, который удобно печатать и передавать в другие алгоритмы.

Важно понимать, зачем это нужно: алгоритмы машинного обучения работают только с числами, поэтому строковые категории необходимо кодировать. One-hot кодирование — самый распространённый способ, так как оно не вносит ложного порядка в категории (в отличие от кодирования числами 1, 2, 3).

### Разбор 5
Полное решение:

```python
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier

X = np.array([[1, 1], [2, 2], [3, 3], [10, 10], [11, 11], [12, 12]])
y = np.array([0, 0, 0, 1, 1, 1])

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.33, random_state=42, shuffle=False
)

knn = KNeighborsClassifier(n_neighbors=1)
knn.fit(X_train, y_train)
y_pred = knn.predict(X_test)

print("Предсказания:", y_pred)
print("Точность:", (y_pred == y_test).mean())
```

Разберём по шагам. В данных два кластера: точки с координатами около (1, 1) относятся к классу 0, а точки около (10, 10) — к классу 1. С `shuffle=False` тестовая выборка — это последние 33% строк: точки (11, 11) и (12, 12) с метками [1, 1].

`KNeighborsClassifier(n_neighbors=1)` — метод ближайших соседей: при предсказании он находит ближайшую точку обучающей выборки и возвращает её класс. Для обеих тестовых точек ближайшая — соседняя точка из того же кластера, поэтому предсказания [1, 1] полностью совпадают с истинными метками, и точность равна 1.0.

Обрати внимание: `shuffle=False` здесь используется только чтобы сделать пример детерминированным и наглядным. В реальной работе данные перемешивают (`shuffle=True` по умолчанию), иначе упорядоченные данные могут исказить обучение — например, если все примеры одного класса стоят в начале файла.

### Разбор 6
Полное решение:

```python
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

X = np.array([[1], [2], [3], [4], [5]])
y = np.array([2, 4, 6, 8, 10])

model = LinearRegression()
model.fit(X, y)

print(f"Коэффициент: {model.coef_[0]:.1f}, свободный член: {model.intercept_:.1f}")

X_new = np.array([[6]])
print("Предсказание для 6:", model.predict(X_new)[0])

mse = mean_squared_error(y, model.predict(X))
print("MSE:", mse)
```

Разберём по шагам. Задача регрессии отличается от классификации только целевой переменной: `y` здесь числа, а не метки классов, поэтому вместо `LogisticRegression` берём `LinearRegression`. Метод `fit` подбирает коэффициенты прямой `y = kx + b` так, чтобы сумма квадратов отклонений была минимальной — это метод наименьших квадратов. В наших данных зависимость ровно вдвое: k = 2.0, b = 0.0.

Обрати внимание на форму `X`: это матрица `(5, 1)`, а не вектор `(5,)`. scikit-learn всегда ожидает двумерный массив признаков — отсюда и `[[6]]` для предсказания. `model.predict(X_new)` возвращает массив предсказаний, поэтому берём `[0]`. Для точки 6 модель выдаёт 12.0 — точно по формуле.

`mean_squared_error(y, model.predict(X))` считает среднее квадратов ошибок: все отклонения равны нулю, поэтому MSE = 0.0. В реальных данных идеального совпадения не бывает, и MSE служит мерой качества: чем меньше, тем лучше, но её значение зависит от масштаба целевой переменной, поэтому иногда дополнительно смотрят на RMSE или MAE. Такой цикл «fit → predict → метрика» одинаков для регрессии, классификации и кластеризации.

### Разбор 7
Полное решение:

```python
import numpy as np
from sklearn.metrics import (
    confusion_matrix, precision_score, recall_score, f1_score, accuracy_score,
)

y_true = np.array([1, 0, 1, 1, 0, 0, 1, 0])
y_pred = np.array([1, 0, 1, 0, 0, 1, 1, 0])

# Строки — истинные классы (0, 1), столбцы — предсказанные
print("Матрица ошибок:")
print(confusion_matrix(y_true, y_pred))

print("Precision:", precision_score(y_true, y_pred))
print("Recall:", recall_score(y_true, y_pred))
print("F1:", f1_score(y_true, y_pred))
print("Accuracy:", accuracy_score(y_true, y_pred))
```

Разберём по шагам. Матрица ошибок читается так: строка — истинный класс, столбец — предсказанный. Для положительного класса (1) верно предсказаны 3 случая (TP), один раз модель сказала 0 вместо 1 (FN), и один раз — 1 вместо 0 (FP). Для класса 0: 3 верных (TN) и 1 ошибка. Отсюда матрица `[[3, 1], [1, 3]]`.

Теперь метрики. **Precision** = TP / (TP + FP) = 3/4 = 0.75 — из всех объектов, названных положительными, три четверти действительно положительные. **Recall** = TP / (TP + FN) = 3/4 = 0.75 — из всех настоящих положительных модель нашла три четверти. **F1** — гармоническое среднее precision и recall, здесь тоже 0.75, потому что они равны. **Accuracy** = (TP + TN) / всего = 6/8 = 0.75 — доля всех верных ответов.

Зачем нужны все четыре, если числа совпали? В реальных задачах они расходятся, и выбор метрики определяет поведение модели. В диагностике болезней важнее recall (не пропустить больного), в антиспаме — precision (не выбросить в спам важное письмо). Accuracy же обманчива при несбалансированных классах: модель, всегда отвечающая «нет», даст 99% точности, если больных всего 1%. Поэтому `classification_report` из теории показывает precision, recall и F1 сразу по каждому классу.

- Точность модели
