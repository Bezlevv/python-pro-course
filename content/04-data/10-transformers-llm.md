Привет! Мы подошли к вершине курса. Современные нейросети — трансформеры — умеют анализировать и генерировать текст. Библиотека Hugging Face Transformers даёт доступ к тысячам готовых моделей прямо из Python, а облачные LLM API позволяют вызвать мощную модель по сети, ничего не скачивая. Разберём оба пути.

## Установка и пайплайны

Установка: `pip install transformers`. Самое простое — функция `pipeline`: она сама загрузит модель, токенизатор и выполнит нужную задачу:

```python
from transformers import pipeline

classifier = pipeline("sentiment-analysis")
result = classifier("Сегодня отличный день, я много успел!")
print(result)
```

Ответ — список словарей: `[{'label': 'POSITIVE', 'score': 0.999...}]`. Полезные задачи: `"text-generation"`, `"summarization"`, `"zero-shot-classification"`, `"translation"`.

## Токенизация и модель вручную

Под капотом текст превращается в токены — кусочки слов, которые модель читает как числа:

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("distilgpt2")
model = AutoModelForCausalLM.from_pretrained("distilgpt2")

inputs = tokenizer("Python — это", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=20)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

`AutoTokenizer` и `AutoModelForCausalLM` сами подставляют правильный класс под имя модели. `distilgpt2` — маленькая модель (~350 МБ), которую реально запустить на CPU; большие модели требуют десятки гигабайт памяти и GPU. Модель скачается при первом запуске из Hugging Face Hub.

## Генерация текста

Метод `generate` дописывает новые токены к входу по одному, пока не упрётся в `max_new_tokens` или служебный токен конца. Ключевые параметры: `temperature` (случайность), `top_k` и `top_p` (разнообразие).

## LLM API

Если модель слишком большая для твоего компьютера — вызывай её через API. Многие провайдеры (OpenAI и совместимые с ним) предлагают единый формат запросов:

```python
import os
import requests

key = os.environ.get("OPENAI_API_KEY")
resp = requests.post(
    "https://api.openai.com/v1/chat/completions",
    headers={"Authorization": f"Bearer {key}"},
    json={
        "model": "gpt-4o-mini",
        "messages": [{"role": "user", "content": "Объясни, что такое Python"}],
    },
    timeout=30,
)
print(resp.json()["choices"][0]["message"]["content"])
```

Ключ хранится в переменной окружения, а не в коде — иначе он утечёт в репозиторий. Такой же формат поддерживают локальные серверы вроде Ollama (адрес `http://localhost:11434/v1/chat/completions`) — те же запросы, но без ключа и без отправки данных наружу.

## Что выбрать?

- Нужно быстро попробовать задачу → `pipeline`.
- Нужен контроль над токенизацией и генерацией → `AutoModel...`.
- Огромная модель или платное качество → API.
- Конфиденциальные данные → локальный сервер (Ollama и подобные).

### Разбор 1
Полное решение:

```python
import os
import requests
from transformers import pipeline

phrases = [
    "Я обожаю Python!",
    "Это приложение постоянно падает и тормозит.",
    "Погода сегодня нормальная.",
]

classifier = pipeline("sentiment-analysis")
for phrase in phrases:
    result = classifier(phrase)[0]
    print(f"Фраза: {result['label']} ({result['score']:.3f})")

key = os.environ.get("OPENAI_API_KEY")
if key:
    resp = requests.post(
        "https://api.openai.com/v1/chat/completions",
        headers={"Authorization": f"Bearer {key}"},
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "user", "content": phrases[0]}],
        },
        timeout=30,
    )
    data = resp.json()
    print("Ответ модели:", data["choices"][0]["message"]["content"])
else:
    print("API-ключ не задан, пропускаю вызов API")
```

Разбираем по шагам. `pipeline("sentiment-analysis")` загружает предобученную модель (по умолчанию `distilbert-base-uncased-finetuned-sst-2-english`), её токенизатор и обвязку. Для каждой фразы модель возвращает словарь с ключами `label` (POSITIVE/NEGATIVE) и `score` — уверенностью от 0 до 1. Формат вывода задаёт f-string: `{result['score']:.3f}` округляет уверенность до трёх знаков.

Затем `os.environ.get("OPENAI_API_KEY")` читает ключ из окружения — если он не задан, `get` вернёт `None`, и отработает ветка `else`. Ключ не должен лежать в коде: переменные окружения — стандартный способ для секретов.

Если ключ есть, `requests.post` шлёт запрос к совместимому с OpenAI API. В `json` передаются модель и сообщения: `role: "user"` — твоя реплика (здесь — первая фраза). Ответ приходит в JSON, где `data["choices"][0]["message"]["content"]` — текст модели. Тот же код работает с Ollama: поменяй адрес на `http://localhost:11434/v1/chat/completions` и убери заголовок Authorization.

Так выглядит современная работа с LLM: пайплайны — для лёгких задач локально, API — для мощных моделей в облаке.

from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("distilgpt2")
text = "Python is great"

ids = tokenizer(text)["input_ids"]
print("Токенов:", len(ids))

Разберём по шагам. `AutoTokenizer.from_pretrained("distilgpt2")` загружает токенизатор, соответствующий модели `distilgpt2` — он автоматически подбирает правильный класс под имя модели, поэтому нам не нужно знать внутреннее устройство конкретного токенизатора.

`tokenizer(text)` превращает строку в словарь, в котором `"input_ids"` — список числовых идентификаторов токенов. Токенизатор GPT-2 использует Byte-Pair Encoding (BPE): слова разбиваются на кусочки из обучающих данных. Фраза «Python is great» превращается в три токена — по одному на слово, что видно по `len(ids) == 3`.

`tokenizer.decode(ids)` выполняет обратное преобразование: из идентификаторов восстанавливает исходный текст. Это важно для генерации: модель работает с числами, а человек — с текстом, и токенизатор — мост между ними. Любая работа с трансформерами начинается и заканчивается токенизатором.

### Разбор 4
Полное решение:

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("distilgpt2")
model = AutoModelForCausalLM.from_pretrained("distilgpt2")

prompt = "Once upon a time"
inputs = tokenizer(prompt, return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=10, temperature=0.8, top_k=40)

continuation = out[0][inputs["input_ids"].shape[1]:]
text = tokenizer.decode(continuation, skip_special_tokens=True)
print("Продолжение:", text)
print("Новых токенов:", len(continuation))
```

Разберём по шагам. `tokenizer(prompt, return_tensors="pt")` превращает фразу в тензоры PyTorch (формат `pt`), которые модель ожидает на входе. `model.generate(**inputs, ...)` дописывает новые токены по одному: на каждом шаге модель вычисляет вероятность следующего токена и выбирает один из них.

`max_new_tokens=10` ограничивает длину продолжения десятью токенами. `temperature=0.8` управляет случайностью: значения ближе к 0 делают выбор почти детерминированным, выше 1 — хаотичным. `top_k=40` ограничивает выбор сорока самыми вероятными токенами, убирая редкие и странные варианты.

`out[0][inputs["input_ids"].shape[1]:]` — это срез: мы отбрасываем исходные токены (их количество равно длине входа) и оставляем только новосгенерированные. `tokenizer.decode(continuation, skip_special_tokens=True)` превращает их в текст, а `skip_special_tokens=True` убирает служебные токены вроде `<|endoftext|>`.

### Разбор 5
Полное решение:

```python
import os
import requests

def ask_llm(prompt):
    key = os.environ.get("OPENAI_API_KEY")
    if not key:
        return "API-ключ не задан, пропускаю вызов"

    resp = requests.post(
        "https://api.openai.com/v1/chat/completions",
        headers={"Authorization": f"Bearer {key}"},
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "user", "content": prompt}],
        },
        timeout=30,
    )
    data = resp.json()
    return data["choices"][0]["message"]["content"]

print(ask_llm("Поздоровайся коротко"))
```

Разберём по шагам. Функция `ask_llm` инкапсулирует весь цикл вызова LLM: получение ключа, формирование запроса и разбор ответа. Сначала `os.environ.get("OPENAI_API_KEY")` пробует прочитать ключ из переменной окружения. Если его нет — функция сразу возвращает сообщение о пропуске, не делая никаких сетевых вызовов.

Если ключ есть, `requests.post` отправляет запрос к API. Формат тела запроса стандартен: `model` — имя модели, `messages` — список реплик с ролями. Один элемент с ролью `user` — это запрос от пользователя; можно добавлять и историю диалога с ролями `assistant`. Ответ модели лежит в `data["choices"][0]["message"]["content"]` — именно его функция возвращает.

Такая обёртка — базовый строительный блок для создания приложений на LLM: чат-ботов, суммаризаторов, ассистентов. Вынеся вызов в функцию, ты можешь вызывать модель из любого места программы, не повторяя код.
