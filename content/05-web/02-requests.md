В прошлом уроке мы делали запросы встроенным модулем `urllib.request`. Он работает, но для серьёзной работы неудобен: многословный, с ним неудобно передавать параметры и JSON. Библиотека `requests` — стандарт де-факто для HTTP в Python. Ею пользуются миллионы разработчиков, и сейчас ты научишься ей пользоваться.

## Установка

Библиотека не входит в стандартную поставку Python — установи её командой:

```bash
pip install requests
```

Проверить установку можно так:

```python
import requests
print(requests.__version__)
```

## Первый GET-запрос

Всё начинается с функции `requests.get()`:

```python
import requests

r = requests.get("https://httpbin.org/get")
print(r.status_code)   # 200
print(r.text[:200])    # начало тела ответа
```

Ответ сохраняется в объекте Response. `r.status_code` — код статуса, `r.text` — тело ответа как текст.

## Параметры запроса

Чтобы добавить query-параметры, достаточно словаря в аргументе `params`:

```python
r = requests.get(
    "https://httpbin.org/get",
    params={"name": "Аня", "page": 2},
)
print(r.url)  # ...?name=Аня&page=2
```

`requests` сам собирает строку с `?` и `&`, а ещё корректно кодирует кириллицу.

## Ответ в формате JSON

Большинство современных API отдают JSON. Метод `.json()` сразу превращает ответ в Python-структуры:

```python
r = requests.get("https://api.github.com/users/python")
data = r.json()
print(data["public_repos"])  # число публичных репозиториев
```

GitHub API не требует ключа для простых запросов — отличная площадка для тренировки.

## POST и отправка данных

Для отправки данных используется `requests.post()`. Если передать `json=`, библиотека сама сделает JSON-сериализацию и выставит заголовок `Content-Type: application/json`:

```python
r = requests.post(
    "https://httpbin.org/post",
    json={"login": "anya", "age": 25},
)
print(r.json()["json"])  # {'login': 'anya', 'age': 25}
```

## Заголовки и тайм-ауты

Свои заголовки передаются через `headers=`. А `timeout` защищает программу от зависания, если сервер молчит:

```python
r = requests.get(
    "https://api.github.com/users/python",
    headers={"User-Agent": "my-app"},
    timeout=10,
)
```

## Обработка ошибок

Код статуса 4xx или 5xx не роняет программу автоматически — ответ просто считается неуспешным. Проверить результат помогает `raise_for_status()`:

```python
r = requests.get("https://httpbin.org/status/404")
print(r.status_code)      # 404
r.raise_for_status()      # бросит исключение
```

### Разбор 1

```python
import requests

print(requests.__version__)

r = requests.get("https://httpbin.org/get")
print(r.status_code)
print(r.headers.get("Content-Type"))
print(r.text[:200])
```

Разбор по шагам:

- `import requests` подключает установленную библиотеку. Если импорт падает — значит, `pip install requests` не был выполнен в этом окружении.
- `requests.__version__` — строковая константа с версией; её печать подтверждает, что библиотека активна и готова к работе.
- `requests.get(...)` отправляет GET-запрос и сразу возвращает готовый объект ответа `r`. В отличие от urllib, ничего читать и декодировать вручную не нужно — всё уже сделано внутри.
- `r.status_code` — код статуса. Для httpbin это 200.
- `r.headers` — словароподобный объект заголовков; `r.headers.get("Content-Type")` достаёт тип содержимого — `application/json`.
- `r.text` — тело ответа как строка. `[:200]` отрезает первые 200 символов, чтобы не вывалить на экран весь JSON. За декодирование байтов в строку отвечает сама библиотека.

### Разбор 2

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={"name": "Аня", "page": 2},
)
print(r.url)

data = r.json()
print("Имя:", data["args"]["name"])
print("Страница:", data["args"]["page"])
```

Разбор по шагам:

- Аргумент `params=` принимает словарь. `requests` сам собирает строку запроса: добавляет `?`, склеивает пары через `&` и процентно кодирует кириллицу.
- `r.url` показывает итоговый адрес — это удобно для отладки: ты всегда можешь убедиться, что параметры ушли так, как задумано.
- `r.json()` — ключевой метод: он разбирает JSON-тело прямо в Python-структуры (словари и списки). Проверять статус перед этим не обязательно, но при ошибках сервера разбор может провалиться.
- httpbin возвращает переданные параметры в поле `args`. Мы читаем `data["args"]["name"]` и `data["args"]["page"]`.
- Так устроены фильтры и пагинация на реальных сайтах: параметры едут в адресе, а сервер по ним формирует ответ.

### Разбор 3

```python
import requests

r = requests.get(
    "https://api.github.com/users/python",
    headers={"User-Agent": "my-app"},
    timeout=10,
)
data = r.json()

print("Логин:", data["login"])
print("Репозитории:", data["public_repos"])
print("Подписчики:", data["followers"])
```

Разбор по шагам:

- `requests.get(...)` — тот же принцип, что и в первом задании, но адрес другой. GitHub API отдаёт JSON-объект с десятками полей.
- `headers={"User-Agent": "my-app"}` — некоторые API (включая GitHub) отклоняют запросы без идентификации клиента. Передавая заголовок, мы играем по правилам сервиса.
- `timeout=10` — лимит ожидания. Если сервер не ответит за 10 секунд, requests бросит исключение, и программа не зависнет навсегда.
- `r.json()` превращает ответ в словарь. Поля `login`, `public_repos`, `followers` находятся на верхнем уровне — их и печатаем.
- Так выглядит настоящая интеграция с API: одна строка запроса — и данные готовы к использованию в программе.

### Разбор 4

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    json={"login": "anya", "age": 25},
)
print(r.status_code)
print(r.json()["json"])
```

Разбор по шагам:

- `requests.post(...)` отправляет POST-запрос — тот самый, которым клиенты передают данные на сервер.
- Аргумент `json={...}` делает две важные вещи автоматически: сериализует словарь в JSON-строку и выставляет заголовок `Content-Type: application/json`. Именно по этому заголовку сервер понимает, что получил JSON.
- `r.status_code` — код ответа; для успешного запроса это 200 (или 201, если API явно отдаёт «создано»).
- httpbin эхом возвращает принятые данные в поле `json`: `r.json()["json"]` даст тот же словарь `{'login': 'anya', 'age': 25}`.
- Обрати внимание на разницу с `data=`: тот вариант отправляет форму (`application/x-www-form-urlencoded`). Для API-общения почти всегда выбирают `json=`.

### Разбор 5

```python
import requests

r = requests.get("https://jsonplaceholder.typicode.com/todos")
todos = r.json()

completed = [todo for todo in todos if todo["completed"]]
for todo in completed:
    print(todo["title"])

print(f"Выполнено: {len(completed)} из {len(todos)}")
```

Разбор по шагам:

- `requests.get(...)` — обычный GET к учебному API. jsonplaceholder отдаёт большой список JSON-объектов.
- `r.json()` вернёт список словарей. У каждой задачи есть поля `title`, `completed`, `id`, `userId`.
- Генератор списка `[todo for todo in todos if todo["completed"]]` проходит по всем элементам и оставляет только те, где `completed` равен `True`. Это фильтрация на стороне клиента.
- Цикл `for` печатает заголовки выполненных задач — по одному на строку.
- Последняя строка — f-строка с количеством: `len(completed)` — сколько выполнено, `len(todos)` — сколько всего. Формат «N из M» позволяет сразу оценить прогресс.
- Программа ничего не сохраняет между запусками: каждый раз данные скачиваются заново — так работают большинство простых HTTP-клиентов.
