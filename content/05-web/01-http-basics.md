Привет! В этом модуле мы будем создавать настоящие веб-приложения на Python. Но прежде чем писать код, стоит понять, как вообще устроен веб — иначе многие ошибки будут казаться магией. Начнём с основ: клиентов, серверов и протокола HTTP.

## Клиент и сервер

Когда ты открываешь сайт, в игре две роли:

- **Клиент** — программа, которая посылает запрос. Это может быть браузер, а может быть и твоя Python-программа.
- **Сервер** — компьютер или программа, которая хранит сайт и отвечает на запросы.

Клиент отправляет **запрос** (request), сервер обрабатывает его и возвращает **ответ** (response). Весь этот обмен идёт по правилам протокола **HTTP** — он определяет формат сообщений, и по нему общаются миллионы программ в интернете.

## Из чего состоит URL

Каждый адрес страницы — URL — имеет структуру:

```
https://example.com:8080/blog/post?page=2#comment
```

- `https` — схема (протокол);
- `example.com` — имя хоста;
- `:8080` — порт (для https по умолчанию 443, поэтому он часто опускается);
- `/blog/post` — путь на сервере;
- `?page=2` — query-параметры (идут после знака вопроса);
- `#comment` — фрагмент (серверу не отправляется).

Разобрать URL прямо в коде помогает встроенный модуль `urllib.parse`:

```python
from urllib.parse import urlparse

url = urlparse("https://example.com/blog/post?page=2&tag=python")
print(url.scheme)  # https
print(url.path)     # /blog/post
print(url.query)    # page=2&tag=python
```

## Методы HTTP

Каждый запрос имеет метод — глагол, описывающий действие:

- `GET` — получить данные (например, открыть страницу);
- `POST` — отправить данные на сервер (форму, файл);
- `PUT` — полностью заменить существующий ресурс;
- `DELETE` — удалить ресурс.

Правило простое: GET — для чтения, POST — для записи. Не используй GET, чтобы менять данные на сервере.

## Коды ответа

Сервер отвечает числовым кодом статуса:

| Диапазон | Значение | Примеры |
|---|---|---|
| 2xx | Успех | 200 OK, 201 Created |
| 3xx | Перенаправление | 301 Moved Permanently |
| 4xx | Ошибка клиента | 404 Not Found, 403 Forbidden |
| 5xx | Ошибка сервера | 500 Internal Server Error |

404 значит «такой страницы нет», 500 — сломался сам сервер.

## Заголовки

Запрос и ответ несут ещё и **заголовки** — служебные поля. Самые важные: `Host` (кому адресовано), `User-Agent` (что за клиент), `Content-Type` (тип данных, например `application/json`).

## Первый запрос на Python

У Python есть встроенный модуль `urllib.request`. Сделаем настоящий GET-запрос:

```python
from urllib.request import urlopen

response = urlopen("https://httpbin.org/get")
print("Статус:", response.getcode())
print("Content-Type:", response.headers.get("Content-Type"))
data = response.read().decode("utf-8")
print(data[:300])
```

`httpbin.org` — бесплатный сервис для тренировки HTTP; он возвращает JSON с данными о запросе. Так же работает и браузер, только он ещё рисует страницу.

### Разбор 1

```python
from urllib.parse import urlparse, parse_qs

url = "https://example.com:8080/blog/post?page=2&tag=python#comments"
parts = urlparse(url)

print("scheme:", parts.scheme)
print("netloc:", parts.netloc)
print("path:", parts.path)
print("query:", parse_qs(parts.query))
```

Разбор по шагам:

- `urlparse(...)` разбирает строку адреса на составляющие. Обрати внимание: фрагмент `#comments` в печать не попадает — он остаётся в атрибуте `fragment` и на сервер не отправляется никогда.
- `parts.scheme` — схема (`https`), `parts.netloc` — имя хоста вместе с портом (`example.com:8080`), `parts.path` — путь на сервере (`/blog/post`).
- `parts.query` возвращает сырую строку параметров — `page=2&tag=python`. Её недостаточно разбить по `&`, потому что значения могут содержать символы, требующие декодирования. Поэтому строку передаём в `parse_qs`, которая возвращает словарь, где каждому имени соответствует список значений: `{'page': ['2'], 'tag': ['python']}`. Список, а не строка — потому что один параметр может встретиться в адресе несколько раз.
- Вывод программы — ровно четыре строки, соответствующие ожидаемому результату. Так выглядит «анатомия» любого URL.

### Разбор 2

```python
from urllib.request import urlopen

response = urlopen("https://httpbin.org/get")
print("Статус:", response.getcode())
print("Content-Type:", response.headers.get("Content-Type"))

body = response.read().decode("utf-8")
print(body[:300])
```

Разбор по шагам:

- `urlopen("https://httpbin.org/get")` выполняет GET-запрос и возвращает объект ответа. Пока мы не вызвали методы, мы не знаем, что именно пришло — всё нужное нужно запрашивать явно.
- `response.getcode()` возвращает числовой код статуса — для успешного запроса это 200.
- `response.headers` — объект, похожий на словарь, с заголовками ответа. Метод `.get("Content-Type")` достаёт нужный заголовок: httpbin отдаёт JSON, поэтому видим `application/json`.
- `response.read()` читает тело ответа как последовательность байтов. Байты нельзя печатать как обычный текст — сначала их нужно декодировать. `decode("utf-8")` превращает байты в строку.
- `body[:300]` — срез: первые 300 символов. Это начало JSON-ответа, который начинается с `{"args": {}...`. Печатать всё тело целиком было бы слишком шумно, поэтому берём только начало.
- Заметь порядок действий: сначала печатаем статус и заголовок, потом читаем тело. Повторное считывание вернёт пустые байты — тело читается один раз.

### Разбор 3

```python
from urllib.parse import urlencode
from urllib.request import urlopen
import json

params = urlencode({"name": "Аня", "page": 2})
url = "https://httpbin.org/get?" + params

response = urlopen(url)
data = json.loads(response.read().decode("utf-8"))

print("Имя:", data["args"]["name"])
print("Страница:", data["args"]["page"])
```

Разбор по шагам:

- `urlencode({"name": "Аня", "page": 2})` превращает словарь в готовую query-строку вида `name=%D0%90...&page=2`. Кириллица кодируется автоматически — это называется процентным кодированием, и делать его вручную не нужно.
- Мы склеиваем базовый адрес с параметрами через знак вопроса. Теперь запрос уходит вместе с параметрами.
- `json.loads(response.read().decode("utf-8"))` — три действия за раз: читаем байты, декодируем их в строку, затем разбираем JSON в словарь. Если пропустить любой из шагов, получим либо байты, либо простой текст вместо структуры данных.
- Сервис httpbin возвращает переданные параметры в поле `args`. Оттуда берём значения по ключам `name` и `page`.
- Так работают поисковые системы и фильтры: параметры едут в адресе, а сервер по ним формирует ответ.

### Разбор 4

```python
from urllib.request import urlopen
from urllib.error import HTTPError

try:
    urlopen("https://httpbin.org/status/404")
except HTTPError as e:
    print(e.code, e.reason)
```

Разбор по шагам:

- Адрес `/status/404` создан специально: httpbin всегда отвечает на него кодом 404.
- Удивительное поведение `urlopen`: при кодах 4xx и 5xx он не возвращает объект ответа, а бросает исключение `HTTPError`. Это не баг — так HTTP-клиент сообщает вызвающему коду, что запрос не удался.
- Поэтому мы заранее импортируем `HTTPError` из модуля `urllib.error` и оборачиваем вызов в `try/except`.
- В блоке `except` переменная `e` содержит детали ошибки. Атрибут `e.code` — числовой код (404), `e.reason` — текстовая причина (`Not Found`). Печатаем их одной строкой через пробел.
- Если бы мы не перехватили исключение, программа упала бы с трейсбеком. Перехват превращает ошибку в нормальное поведение: пользователь видит понятное сообщение, а не стек вызовов.

### Разбор 5

```python
from urllib.request import urlopen
from urllib.error import HTTPError


def fetch(url):
    try:
        response = urlopen(url)
        return response.getcode(), response.read().decode("utf-8")
    except HTTPError as e:
        return e.code, e.reason


code, body = fetch("https://httpbin.org/get")
print(code)
print(body[:100])

code, reason = fetch("https://httpbin.org/status/404")
print(code, reason)
```

Разбор по шагам:

- Функция `fetch(url)` инкапсулирует весь цикл «запрос — считывание — обработка ошибки». Она возвращает кортеж: при успехе — `(код, текст тела)`, при ошибке клиента или сервера — `(код, причина)`.
- Благодаря этому основная часть программы стала декларативной: мы просто вызываем `fetch` для каждого адреса и печатаем результат.
- Первый вызов: `fetch("https://httpbin.org/get")` вернёт `(200, "{...}")`. Печатаем код — строка `200` — а затем первые 100 символов тела: `body[:100]`.
- Второй вызов обращается к `/status/404`. Внутри `fetch` исключение `HTTPError` ловится, и наружу возвращается `(404, "Not Found")`. Печатаем оба значения через пробел — получаем `404 Not Found`.
- Так выглядит минимальный надёжный HTTP-клиент: с переиспользуемой логикой и аккуратным поведением при ошибках. Запускаем файл и видим ровно три строки ожидаемого результата.
