Метод Монте-Карло — это универсальный численный приём: вместо точной формулы мы многократно разыгрываем случайность и усредняем результат. Он спасает там, где аналитический вывод невозможен: сложные интегралы, модели рисков, физика частиц, финансы. Название отсылает к казино Монте-Карло — в основе метода лежит случайность.

## Идея: оценка как среднее

Пусть мы хотим оценить величину, которая является математическим ожиданием некоторой функции от случайной величины. Если мы умеем генерировать выборку X₁, …, X_N, то оценка — обычное среднее:

```
(1/N) · Σ f(Xᵢ)
```

По закону больших чисел среднее сходится к математическому ожиданию при N → ∞. Скорость сходимости — 1/√N: чтобы уменьшить ошибку вдвое, нужно увеличить число испытаний вчетверо.

## Оценка числа π

Классический пример: бросим точки в квадрат [0,1]² и посчитаем, какая доля попала в четверть круга. Площадь четверти круга — π/4, значит π ≈ 4 · (попадания / всего):

```python
import numpy as np

def estimate_pi(n, seed=0):
    rng = np.random.default_rng(seed)
    x = rng.uniform(0, 1, n)
    y = rng.uniform(0, 1, n)
    inside = (x**2 + y**2) <= 1
    return 4 * inside.mean()

print(estimate_pi(100_000))
```

В `x**2 + y**2 <= 1` — векторное сравнение: NumPy считает маску сразу для всех точек, а `inside.mean()` — доля единиц. Результат — около 3.14, и чем больше n, тем ближе к π.

## Монте-Карло интегрирование

Тот же приём считает любые интегралы. ∫₀^π sin(x) dx = 2. Случайная точка U из U(0, π), тогда оценка — среднее f(U)·(π − 0):

```python
def mc_integral_sin(n, seed=0):
    rng = np.random.default_rng(seed)
    u = rng.uniform(0, np.pi, n)
    return np.sin(u).mean() * np.pi

print(mc_integral_sin(100_000))  # ≈ 2.0
```

Домножение на длину интервала — ключевой шаг: среднее f(U) оценивает «среднюю высоту», а умножение на длину даёт площадь. Погрешность — порядка (b−a)·σ/√N.

## Сиды и воспроизводимость

Симуляции обязаны быть воспроизводимыми. `default_rng(seed)` даёт детерминированную последовательность: одинаковый сид → одинаковый результат. Это позволяет писать тесты: функции с фиксированным сидом возвращают одни и те же числа.

## Не только интегралы: вероятности событий

Монте-Карло оценивает и вероятности. Какова вероятность, что сумма двух кубиков равна 7? Теория говорит 6/36 = 1/6 ≈ 0.1667. Разыграем 10 000 пар:

```python
def prob_sum_seven(n, seed=0):
    rng = np.random.default_rng(seed)
    a = rng.integers(1, 7, n)
    b = rng.integers(1, 7, n)
    return ((a + b) == 7).mean()

print(prob_sum_seven(10_000))
```

`rng.integers(1, 7, n)` генерирует целые от 1 до 6 включительно (правый конец не входит). Оценка будет колебаться вокруг 1/6.

## Как повысить точность

Основной способ — больше испытаний, но есть и «бесплатные» приёмы:

- **Стратификация / латинские гиперкубы**: равномерно покрывать область вместо хаотичных бросаний;
- **Метод антитетических переменных**: использовать пары U и 1−U, уменьшающие разброс;
- **Выделение главной части**: вычесть из функции «почти интеграл», который считается аналитически.

На практике чаще всего достаточно просто увеличить N и следить за сидом.

## Оценка погрешности

Ошибку оценки Монте-Карло можно оценить экспериментально: она равна стандартному отклонению выборочного среднего, то есть σ_f/√N, где σ_f — стандартное отклонение значений f(X). Это даёт практическое правило: чтобы получить три значащие цифры, нужно около миллиона испытаний, а для шести — миллиард. Отсюда же — приём «сравни с теоретическим ответом»: если у тебя есть точное значение (как π или 2 для интеграла синуса), оценку всегда стоит сверять с ним. Если расхождение больше ожидаемой ошибки — ищи баг в симуляции, а не в математике.

Ещё одно полезное следствие: оценка Монте-Карло — сама случайная величина, поэтому её хорошо сопровождать доверительным интервалом (например, ±1.96·σ/√N). В задачах мы ограничимся точечной оценкой и проверкой по допускам, но в реальных проектах интервал — обязательная часть результата.

## Когда Монте-Карло незаменим

Есть задачи, где случайные испытания — единственный практический способ получить ответ. Назовём главные: интегралы высокой размерности (при 50 переменных сеточные методы требуют 50-мерных сеток — невозможны, а Монте-Карло не зависит от размерности); задачи с неопределённостью параметров (риски портфеля, надёжность конструкций); сложные стохастические системы (очереди, эпидемии, биржевые процессы). Во всех трёх случаях цена решения — только время счёта, которое растёт медленно, как 1/√N.

## Где применяется

Оценка рисков и Value-at-Risk в финансах, моделирование трафика в сетях, радиационная физика, оптимизация сложных систем. Общий рецепт один: вырази ответ как ожидание, разыграй случайность, усредни. Теперь попрактикуемся.

### Разбор 1
Файл `montecarlo.py`:

```python
import numpy as np

def estimate_pi(n, seed):
    rng = np.random.default_rng(seed)
    x = rng.uniform(0, 1, n)
    y = rng.uniform(0, 1, n)
    inside = (x**2 + y**2) <= 1
    return 4 * inside.mean()

print(estimate_pi(100_000, 42))
```

Результат (примерно):

```
3.14152
```

Что здесь происходит? Точка (x, y) в квадрате [0,1]² попадает в четверть круга, если x² + y² ≤ 1. Доля таких точек оценивает отношение площадей — π/4. Умножив на 4, получаем оценку π. При 100 000 точек ошибка порядка 0.005 — отсюда и допуск 3.13…3.15: он в разы шире реального разброса.

def mc_integral_sin(n, seed):

### Разбор 4
Файл `test_montecarlo.py`:

```python
from montecarlo import estimate_pi

def test_pi_in_range():
    assert 3.13 < estimate_pi(100_000, 42) < 3.15

def test_pi_reproducible():
    assert estimate_pi(50_000, 7) == estimate_pi(50_000, 7)
```

Результат: `2 passed`. Что здесь происходит? Первый тест проверяет содержательную точность: оценка π при 100 000 точках почти наверняка окажется между 3.13 и 3.15. Второй тест проверяет воспроизводимость: с фиксированным сидом второй вызов даёт побитово тот же результат. Без сида тест был бы недетерминированным — и это главный повод всегда фиксировать сид в симуляциях.

### Разбор 5
Дополни `test_montecarlo.py`:

```python
from montecarlo import mc_integral_sin, prob_sum_seven

def test_convergence():
    small = abs(mc_integral_sin(500, 1) - 2.0)
    large = abs(mc_integral_sin(50_000, 1) - 2.0)
    assert large < small

def test_dice_probability():
    assert abs(prob_sum_seven(50_000, 3) - 1/6) < 0.01
```

Результат: `4 passed`. Что здесь происходит? Тест сходимости показывает главное свойство метода: чем больше N, тем меньше ошибка. При 50 000 точек ошибка почти наверняка будет меньше, чем при 500. Тест вероятности суммы кубиков проверяет частотную оценку: при 50 000 испытаний отклонение от 1/6 практически никогда не превысит 0.01. Так симуляции превращаются в проверяемый код.
