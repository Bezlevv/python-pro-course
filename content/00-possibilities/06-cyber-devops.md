## Python управляет не только кодом, но и компьютерами

Когда программа выходит в свет, ей нужна «инфраструктура»: серверы, базы данных, автоматические проверки, резервные копии. Обслуживанием всего этого занимается инженер DevOps. И да, Python — главный язык этой профессии. Но это не всё: на Python пишут сетевые инструменты, средства защиты данных и даже программы для роботов. Давай пройдёмся по этим четырём мирам.

## DevOps: автоматизация инфраструктуры

DevOps (Development + Operations) — культура, в которой разработка и эксплуатация работают вместе, а всё рутинное автоматизируется. Чем занимается DevOps-инженер на Python:

- пишет скрипты для развёртывания сервисов (деплой);
- автоматизирует проверки кода и запуск тестов;
- собирает метрики: нагрузка на сервер, ошибки, скорость ответов;
- работает с облаками (AWS, Yandex Cloud) — Python всюду рядом.

Вот типичный «инфраструктурный» скрипт — он пишет логи в файл, чтобы можно было потом разобраться, что происходило:

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    filename="app.log",
    encoding="utf-8",
    format="%(asctime)s %(levelname)s %(message)s",
)

logging.info("Сервис запущен")
logging.warning("Памяти осталось мало")
logging.error("Не удалось подключиться к базе")
```

Модуль `logging` ведёт журнал событий. Это стандарт в любой промышленной системе: ничего не «теряется», всё записывается с временем и уровнем важности.

## Сеть: программы разговаривают по проводам

Любая сеть — это обмен сообщениями. Python даёт низкоуровневый инструмент — модуль `socket`, через который программы устанавливают соединения:

```python
import socket

# Узнаём IP-адрес сайта по его имени
ip = socket.gethostbyname("google.com")
print("IP-адрес google.com:", ip)
```

`socket.gethostbyname()` превращает доменное имя в IP-адрес — это шаг к пониманию того, как устроен интернет. На `socket` построены все сетевые библиотеки Python, от `urllib.request` до Telegram-ботов. А ещё Python отлично умеет «слушать порт» и превращаться в сервер, который принимает подключения.

## Безопасность: защита данных

Безопасность — это не только взломы из фильмов, но и повседневные вещи: пароли, шифрование, проверка целостности данных. Python помогает и защитникам, и (на законных основаниях) исследователям.

Главный инструмент — **хеширование**. Хеш — это «отпечаток» данных: по одному и тому же тексту всегда получается одна и та же короткая строка, а по разным — почти всегда разные:

```python
import hashlib

password = "супер-пароль"
hash_value = hashlib.sha256(password.encode()).hexdigest()
print("Хеш пароля:", hash_value)
```

Почему это важно? Настоящий пароль в базе данных не хранят — хранят его хеш. Если базу украдут, злоумышленник не узнает исходные пароли, ведь восстановить текст по хешу практически невозможно. `hashlib.sha256` — криптографический алгоритм, `encode()` превращает строку в байты, `hexdigest()` — в читаемую строку.

## Робототехника и IoT

Интернет вещей (IoT) — это когда умные устройства общаются между собой: лампочки, датчики, термостаты, камеры. И здесь Python тоже на месте:

- **Raspberry Pi** — мини-компьютер размером с банковскую карту, на котором работает Python: умный дом, метеостанции, роботы на колёсах.
- **MicroPython** — версия Python для микроконтроллеров (плат вроде ESP32, Arduino). Тот же синтаксис, только на маленьком «железе».
- **Робототехника** — от учебных роботов до промышленных манипуляторов: Python управляет моторами, считывает датчики, обрабатывает изображения с камер.

Пример для Raspberry Pi — мигание светодиодом:

```python
# Упрощённая схема (реально — на Raspberry Pi через GPIO)
import time

for i in range(5):
    print("LED вкл" if i % 2 == 0 else "LED выкл")
    time.sleep(0.5)
```

Главное, что стоит вынести: **Python работает везде — от серверного кластера до маленькой платы за триста рублей.**

### Разбор 1
Решение:

```python
import hashlib

h1 = hashlib.sha256("мой-секретный-пароль".encode()).hexdigest()
h2 = hashlib.sha256("мой-секретный-парол".encode()).hexdigest()

print("Хеш правильного пароля:", h1)
print("Длина хеша:", len(h1))
print("Хеш пароля с ошибкой:", h2)
```

Результат (сокращённо):

```
Хеш правильного пароля: 3f70b9c2...  (64 символа)
Длина хеша: 64
Хеш пароля с ошибкой: 8a1c5d70...  (совсем другой!)
```

Что здесь происходит? `"мой-секретный-пароль".encode()` превращает строку в последовательность байтов — хеш-функции работают именно с байтами. `hashlib.sha256(...)` создаёт объект хеша, `.hexdigest()` — строку из 64 шестнадцатеричных символов. Ключевое наблюдение: смена одного символа полностью меняет хеш. Именно благодаря этому свойству хеши используют для проверки целостности: изменился файл хоть на байт — хеш станет другим, и это сразу видно.

### Разбор 2
Решение:

```python
import hashlib

expected = "3f70b9c2..."  # сюда вставь свой хеш из задачи 1
user_input = input("Введи пароль: ")
actual = hashlib.sha256(user_input.encode()).hexdigest()

if actual == expected:
    print("Доступ разрешён")
else:
    print("Доступ запрещён")
```

Результат при правильном пароле:

```
Введи пароль: мой-секретный-пароль
Доступ разрешён
```

Что здесь происходит? Мы храним не пароль, а его хеш. При вводе пользователь считаем хеш введённой строки и сравниваем с эталонным. Если строки совпадают — совпадают и их хеши, значит пароль верен. Так устроена реальная аутентификация: база данных хранит хеши, и даже утечка базы не раскрывает пароли. Обрати внимание: если ввести пароль с ошибкой, хеш будет другим, и доступ закроется — это проверка лавинного эффекта хеша.

### Разбор 3
Решение:

```python
import socket

def resolve(domain):
    try:
        ip = socket.gethostbyname(domain)
        print(f"Домен: {domain} -> IP: {ip}")
    except socket.gaierror:
        print("Не удалось определить адрес:", domain)

resolve("python.org")
resolve("github.com")
resolve("такого-домена-нет.xyz")
```

Результат (примерно):

```
Домен: python.org -> IP: 151.101.0.223
Домен: github.com -> IP: 140.82.112.4
Не удалось определить адрес: такого-домена-нет.xyz
```

Что здесь происходит? `socket.gethostbyname(domain)` обращается к системе доменных имён (DNS) и получает IP-адрес. `try/except` с `socket.gaierror` ловит ситуацию, когда домен не существует (gaierror — «getaddrinfo error»). Так мы впервые напрямую пообщались с сетевой инфраструктурой интернета. Именно такие обращения происходят тысячи раз в секунду, когда ты просто открываешь сайт в браузере.

### Разбор 4
Решение:

```python
import logging
from pathlib import Path

logging.basicConfig(
    level=logging.INFO,
    filename="app.log",
    encoding="utf-8",
    format="%(asctime)s %(levelname)s %(message)s",
)

logging.info("Сервис запущен")
logging.warning("Памяти осталось мало")
logging.warning("Диск заполнен на 90%")
logging.warning("Соединение с БД медленное")
logging.error("Не удалось подключиться к базе")

print(Path("app.log").read_text(encoding="utf-8"))
```

Результат (примерно):

```
2026-11-01 12:00:00,123 INFO Сервис запущен
2026-11-01 12:00:00,124 WARNING Памяти осталось мало
...
```

Что здесь происходит? `basicConfig` настраивает логирование один раз: уровень INFO (пишутся все события этого уровня и выше), файл `app.log`, формат с временем и уровнем. Дальше каждое событие дописывается в файл с временной меткой. `Path("app.log").read_text()` читает лог обратно. В промышленных системах такие логи — основной способ понять, что происходило с сервисом: когда упал, что было перед этим, где искать причину.

### Разбор 5
Решение:

```python
import logging
import random
import time
from pathlib import Path

logging.basicConfig(
    level=logging.INFO,
    filename="monitor.log",
    encoding="utf-8",
    format="%(asctime)s %(levelname)s %(message)s",
)

for i in range(3):
    memory = random.randint(0, 100)
    logging.info(f"Проверка {i + 1}: свободно {memory}%")
    time.sleep(2)

print(Path("monitor.log").read_text(encoding="utf-8"))
```

Результат (примерно):

```
2026-11-01 12:05:00,112 INFO Проверка 1: свободно 67%
2026-11-01 12:05:02,119 INFO Проверка 2: свободно 42%
2026-11-01 12:05:04,125 INFO Проверка 3: свободно 88%
```

Что здесь происходит? Цикл выполняется три раза, каждое событие записывается в лог, а `time.sleep(2)` создаёт паузу между проверками — как настоящий агент мониторинга, который опрашивает систему раз в несколько секунд. f-строка подставляет номер проверки и процент свободной памяти. Это мини-модель реальных систем мониторинга вроде Zabbix или Prometheus: они точно так же собирают метрики и пишут их в журналы, только на большем масштабе.
