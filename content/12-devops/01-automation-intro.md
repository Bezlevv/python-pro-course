## Что такое автоматизация

DevOps-инженер отличается от обычного пользователя одним навыком: он не делает одно и то же руками дважды. Если операция повторяется — её нужно автоматизировать. Автоматизация — это превращение последовательности ручных действий в программу, которую можно запускать одной командой.

Зачем это нужно? Во-первых, это экономит время: то, что делается 10 минут, скрипт делает за секунду. Во-вторых, это надёжно: машина не устаёт и не пропускает шаги. В-третьих, это воспроизводимо: скрипт можно запустить снова, и результат будет одинаковым. Именно поэтому почти вся рутина в работе с серверами, базами данных и деплоем уже превращена в скрипты.

## Анатомия скрипта

Любой автоматизационный скрипт состоит из трёх частей:

1. **Разбор аргументов** — скрипт должен понимать, что от него хотят: какие файлы обработать, с какими параметрами работать.
2. **Основная логика** — сам «мотор» скрипта: циклы, условия, вызовы функций.
3. **Вывод результата** — понятный отчёт: что сделано, сколько файлов обработано, какие ошибки возникли.

Модуль `argparse` отвечает за первую часть, `pathlib` — за работу с файловой системой, а `subprocess` — за запуск любых внешних программ. Разберём каждый.

## Аргументы командной строки: argparse

Когда мы пишем `python greet.py --name Аня --times 3`, скрипт должен понять, что `--name` — это имя, а `--times` — количество повторов. Именно этим занимается `argparse`:

```python
import argparse

parser = argparse.ArgumentParser(description="Приветствие")
parser.add_argument("--name", default="мир", help="Кого приветствуем")
parser.add_argument("--times", type=int, default=1, help="Сколько раз")

args = parser.parse_args()

for _ in range(args.times):
    print(f"Привет, {args.name}!")
```

Запускаем:

```bash
python greet.py --name Аня --times 3
```

Результат:

```
Привет, Аня!
Привет, Аня!
Привет, Аня!
```

Обрати внимание: `type=int` превращает строку из командной строки в число, а `default` задаёт значение по умолчанию. Если пользователь ошибётся, `argparse` сам напечатает понятное сообщение об ошибке и завершит программу.

## Файлы и папки: pathlib

`pathlib` — это современный способ работать с путями файлов. Вместо строк с `os.path` мы работаем с объектами `Path`:

```python
from pathlib import Path

folder = Path("data")
if not folder.exists():
    folder.mkdir(parents=True)

for p in folder.glob("*.log"):
    print(p.name, p.stat().st_size, "байт")
```

Здесь `glob("*.log")` находит все файлы с расширением `.log` в папке `data`, `p.name` — имя файла, а `p.stat().st_size` — его размер в байтах. Объекты `Path` умеют всё: проверить существование, переименовать (`p.rename(new)`), скопировать, удалить и собрать путь из частей через `/`.

## Запуск внешних команд: subprocess

Часто автоматизация — это оркестрация чужих программ: сжать архивы, запустить сборку, проверить версию утилиты. Модуль `subprocess` позволяет запускать любые команды прямо из Python:

```python
import subprocess

result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True,
)
print("Код возврата:", result.returncode)
print("stdout:", result.stdout.strip())
```

`returncode` — это код возврата: `0` означает успех, любое другое число — ошибку. `capture_output=True` собирает вывод команды, а `text=True` возвращает его как строку, а не байты. Если команда не существует, `subprocess.run` бросит исключение `FileNotFoundError`, поэтому такие места оборачивают в `try/except`.

from pathlib import Path

if len(sys.argv) < 2:
    print("Использование: python list_files.py <каталог>")

### Разбор 3
Решение:

```python
from pathlib import Path

for p in Path(".").glob("*.txt"):
    if p.name.startswith("backup_"):
        continue
    new_name = Path(".") / ("backup_" + p.name)
    p.rename(new_name)
    print(f"{p.name} -> {new_name.name}")
```

Проверяем на файлах `a.txt`, `b.txt`, `c.txt`:

```
a.txt -> backup_a.txt
b.txt -> backup_b.txt
c.txt -> backup_c.txt
```

Что здесь происходит? `Path(".").glob("*.txt")` находит все текстовые файлы в текущем каталоге. Проверка `startswith("backup_")` защищает от повторного запуска: если файл уже переименован, мы его пропускаем (иначе получился бы `backup_backup_a.txt`). `Path(".") / ("backup_" + p.name)` собирает новый путь: оператор `/` в `pathlib` склеивает части пути. Наконец, `p.rename(new_name)` переименовывает файл, а `print` показывает, что изменилось.

### Разбор 4
Решение:

```python
import subprocess
import sys

command = " ".join(sys.argv[1:])
if not command:
    print("Использование: python run_cmd.py <команда>")
    sys.exit(2)

result = subprocess.run(command, shell=True, capture_output=True, text=True)

print("Код возврата:", result.returncode)
print("stdout:")
print(result.stdout)
print("stderr:")
print(result.stderr)

if result.returncode != 0:
    sys.exit(result.returncode)
```

Проверяем на реальной и ошибочной командах:

```bash
python run_cmd.py python --version
python run_cmd.py python not_a_file.py
```

Что здесь происходит? `sys.argv[1:]` — все аргументы после имени скрипта, а `" ".join(...)` собирает их в одну строку — команду. Параметр `shell=True` говорит, что строка — это полная команда, которую нужно выполнить через оболочку. `capture_output=True` сохраняет вывод в `result.stdout` и `result.stderr`, а `text=True` заставляет вернуть их как строки. Если команда завершилась с ошибкой (например, `python not_a_file.py` вернёт код `2`), мы выводим код и stderr, а затем завершаем программу с тем же кодом — это важно для CI: вызвавший скрипт поймёт, что произошла ошибка.

### Разбор 5
Решение:

```python
import argparse
from pathlib import Path

mapping = {".png": "images", ".jpg": "images",
           ".pdf": "docs", ".docx": "docs"}

parser = argparse.ArgumentParser(description="Разложить файлы по папкам")
parser.add_argument("--dry-run", action="store_true", help="Только показать действия")
args = parser.parse_args()

counts = {}
for p in Path(".").glob("*"):
    if not p.is_file():
        continue
    folder_name = mapping.get(p.suffix.lower(), "others")
    target = Path(".") / folder_name / p.name
    counts[folder_name] = counts.get(folder_name, 0) + 1
    if args.dry_run:
        print(f"[dry-run] {p.name} -> {folder_name}/")
    else:
        target.parent.mkdir(exist_ok=True)
        p.rename(target)
        print(f"{p.name} -> {folder_name}/")

print("Итог:", counts)
```

Что здесь происходит? `action="store_true"` создаёт флаг, который при передаче `--dry-run` становится `True`, а иначе — `False`. Словарь `mapping` сопоставляет расширение (нижний регистр через `p.suffix.lower()`) папке, а `.get(..., "others")` отправляет всё неизвестное в `others`. При `--dry-run` мы только печатаем планируемые действия и ничего не меняем — это безопасный способ проверить скрипт перед реальным запуском. В боевом режиме `mkdir(exist_ok=True)` создаёт папку, если её ещё нет, а `p.rename(target)` переносит файл. В конце мы показываем, сколько файлов попало в каждую папку, с помощью словаря `counts`.
