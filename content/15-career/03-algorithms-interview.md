Алгоритмические задачи — обязательная часть собеседований на позиции разработчика. Они проверяют не знание формул, а способность мыслить структурированно: разбивать задачу на части, оценивать эффективность и доводить решение до краевых случаев.

## Оценка сложности: O-большое

O-большое описывает, как растёт время выполнения (или память) при росте входных данных `n`:

- O(1) — константа: обращение к элементу списка по индексу;
- O(log n) — логарифм: бинарный поиск в отсортированном массиве;
- O(n) — линейное: один проход по массиву;
- O(n log n) — быстрые сортировки, `sorted()`;
- O(n²) — два вложенных цикла;
- O(2^n) — экспонента: перебор всех подмножеств.

Правило: игнорируй константы и младшие слагаемые: `3n + 100` — это O(n), а `n² + n` — O(n²). При выборе решения всегда называй сложность вслух — интервьюер ждёт этого.

## Ключевые паттерны

Большинство задач решается одним из ограниченного набора приёмов:

- **Хеш-таблица (dict)** — для поиска соответствий за O(1): «найти пару с суммой», «посчитать встречаемость».
- **Два указателя** — для работы с отсортированными массивами и строками: палиндромы, поиск пар, слияние.
- **Скользящее окно** — для подмассивов фиксированной или переменной длины: максимальная сумма, самый длинный отрезок без повторов.
- **Бинарный поиск** — для отсортированных данных: поиск элемента, поиск границы.
- **Рекурсия + мемоизация** — для задач, которые разбиваются на подзадачи: лестницы, пути, числа Фибоначчи.
- **BFS/DFS** — для графов и сеток.

## Стратегия решения

1. **Уточни** вход и выход: что на входе, что вернуть, что делать с пустым входом.
2. **Приведи пример** на маленьких данных и пройди его руками.
3. **Начни с грубой силы** — простое рабочее решение. Затем спроси: где узкое место? Что можно хранить в dict?
4. **Оптимизируй** по одной идее, называя новую сложность.
5. **Проверь краевые случаи**: пустой список, один элемент, дубликаты, отрицательные числа, очень большие значения.
6. **Доведи**: убедись, что код запускается без ошибок.

## Как тренироваться

Решай ежедневно по 1–2 задачи на LeetCode или аналогичных платформах. Разбирай чужие решения и переписывай их от руки, а не копируй. На самом интервью говори вслух: интервьюеру важно видеть твой ход мыслей, а не только финальный код.

### Подсказка 1
Проходя по списку, храни в словаре уже увиденные числа и их индексы. Для каждого числа `x` проверяй, есть ли в словаре значение `target - x`. Так ты найдёшь пару за один проход: сложность O(n), а не O(n²). Не забудь проверить, что индекс числа не совпадает с текущим.

### Подсказка 2
Сначала посчитай сумму первого окна: `current = sum(nums[:k])`. Затем в цикле от `k` до конца: `current += nums[i] - nums[i - k]` и обновляй максимум. Так сумма пересчитывается за O(1) на шаг, а весь алгоритм — O(n). Сравни с наивным вариантом, который считает сумму каждого окна с нуля.

### Подсказка 3
Заведи указатели `left = 0` и `right = len(arr) - 1`. Пока `left <= right`, бери середину `mid = (left + right) // 2`. Если `arr[mid] == target` — верни `mid`; если меньше — двигай `left = mid + 1`; если больше — `right = mid - 1`. После цикла верни -1.

### Подсказка 4
Заведи `left = 0` и `right = len(s) - 1`. Пока `left < right`: если символ слева не буква — сдвинь `left`; если не буква справа — сдвинь `right`; иначе сравни символы в нижнем регистре через `s[left].lower() == s[right].lower()`. Если не равны — верни `False`, иначе сдвинь оба указателя. Проверь на пустой строке: она является палиндромом.

### Подсказка 5

### Разбор 1
Решение:

```python
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]
        seen[x] = i

print(two_sum([2, 7, 11, 15], 9))  # [0, 1]
```

Что здесь происходит? Мы один раз проходим по списку. Для каждого числа `x` ищем в словаре его «дополнение» `target - x`. Если оно уже встречалось — мы нашли пару: индекс дополнения из словаря и текущий индекс. Если нет — сохраняем текущее число с его индексом. Сложность O(n) по времени и O(n) по памяти. Наивный вариант с двумя вложенными циклами имеет сложность O(n²): для каждого элемента мы заново просматривали бы весь список. Словарь превращает поиск дополнения из O(n) в O(1).

### Разбор 2
Решение:

```python
def max_sum_k(nums, k):
    if k > len(nums):
        return None
    current = sum(nums[:k])
    best = current
    for i in range(k, len(nums)):
        current += nums[i] - nums[i - k]
        best = max(best, current)
    return best

print(max_sum_k([1, 4, 2, 10, 23, 3, 1, 0, 20], 4))  # 39
```

Что здесь происходит? Сначала считаем сумму первого окна из `k` элементов. Затем двигаем окно на один шаг: `nums[i]` — новый элемент справа, `nums[i - k]` — уходящий элемент слева. Пересчёт суммы занимает O(1), поэтому весь алгоритм — O(n). Наивный подход пересчитывал бы каждое окно с нуля за O(k), и итог был бы O(n·k); Скользящее окно — один из самых частых паттернов, он отлично подходит для подмассивов фиксированной длины.

### Разбор 3
Решение:

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

print(binary_search([1, 3, 5, 7, 9, 11], 7))  # 3
print(binary_search([1, 3, 5, 7, 9, 11], 4))  # -1
```

Что здесь происходит? Бинарный поиск на каждом шаге отбрасывает половину массива: если элемент в середине меньше искомого, значит, искомый правее, и мы сдвигаем `left`; если больше — левее, сдвигаем `right`. После каждого сравнения интервал поиска уменьшается вдвое, поэтому число шагов — log2(n), а сложность O(log n). Для 1 000 000 элементов это около 20 сравнений вместо миллиона в линейном поиске. Условие `left <= right` гарантирует, что мы не пропустим элемент, когда интервал сужается до одной позиции.

### Разбор 4
Решение:

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalpha():
            left += 1
            continue
        if not s[right].isalpha():
            right -= 1
            continue
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True

print(is_palindrome("А роза упала на лапу Азора"))  # True
print(is_palindrome("Python"))                        # False
```

Что здесь происходит? Два указателя движутся навстречу друг другу. Если символ — не буква (пробел, знак препинания), мы пропускаем его и сдвигаем соответствующий указатель. Дойдя до двух букв, сравниваем их в нижнем регистре: `lower()` убирает различие между «А» и «а». Если буквы не совпали — возвращаем `False`. Если указатели встретились и ни одного несовпадения не было — перед нами палиндром. Краевые случаи: пустая строка и строка из одного символа вернут `True` — это стандартное ожидание, и о нём стоит сказать на интервью.

### Разбор 5
Решение:

```python
def climb_stairs(n):
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1

print(climb_stairs(3))  # 3
print(climb_stairs(4))  # 5
```

Что здесь происходит? На ступеньку `n` можно попасть только с `n-1` (шаг на 1) или с `n-2` (шаг на 2). Значит, количество способов `f(n) = f(n-1) + f(n-2)` — это последовательность Фибоначчи, сдвинутая на одну позицию: f(1)=1, f(2)=2, f(3)=3, f(4)=5. Вместо массива размером n мы храним всего две переменные: `prev2` — способов для `n-2`, `prev1` — для `n-1`. На каждом шаге обновляем пару. Сложность O(n) по времени и O(1) по памяти. Если бы мы не догадались до формулы, можно начать с рекурсии, но она дала бы O(2^n) — мемоизация или итеративный пересчёт решают эту проблему.
