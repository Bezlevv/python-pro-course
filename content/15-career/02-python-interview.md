Техническое интервью по Python обычно состоит из двух частей: вопросы по языку и код-задачи. В этом уроке разберём самые частые темы и научимся отвечать так, чтобы интервьюер видел понимание, а не заученные формулировки.

## Изменяемые и неизменяемые объекты

В Python есть изменяемые (`list`, `dict`, `set`) и неизменяемые (`int`, `str`, `tuple`, `frozenset`) объекты. Неизменяемый нельзя изменить «на месте»: любая операция создаёт новый объект. Это важно для безопасности данных и для передачи аргументов в функции.

```python
s = "abc"
# s[0] = "x"  # TypeError: 'str' object does not support item assignment
```

Новички часто путают `==` и `is`: `==` сравнивает значения, а `is` — является ли это одним и тем же объектом (тем же адресом в памяти). Для `int` и `str` Python иногда переиспользует объекты (интернирование), поэтому `x is y` может вернуть `True` для `256`, но `False` для `257`. Никогда не полагайся на `is` для сравнения значений.

## Опасный изменяемый дефолтный аргумент

```python
def add(item, result=[]):
    result.append(item)
    return result
```

Дефолтный список создаётся один раз при определении функции и живёт между вызовами. Классика интервью — объяснить баг и исправить его через `None`:

```python
def add(item, result=None):
    if result is None:
        result = []
    result.append(item)
    return result
```

## Декораторы

Декоратор — функция, которая принимает функцию и возвращает новую. Чаще всего — чтобы добавить обёртку: логирование, тайминг, проверку прав.

```python
import functools

def logged(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Вызов {func.__name__}")
        return func(*args, **kwargs)
    return wrapper
```

`functools.wraps` сохраняет имя и докстринг исходной функции — об этом часто спрашивают.

## Генераторы и итераторы

Итератор — объект с методом `__next__`. Генератор — функция с `yield`: она приостанавливается и возвращает по одному значению, поэтому не держит всё в памяти.

```python
def squares(n):
    for i in range(n):
        yield i * i
```

Тело генератора выполняется лениво, при переборе. Если спрашивают «что выведет print(gen)?» — правильный ответ: объект генератора, а не числа.

## GIL

GIL (Global Interpreter Lock) — глобальная блокировка интерпретатора: в один момент времени выполняется только один поток Python-кода. Поэтому потоки не ускоряют CPU-нагруженные задачи; для них используют `multiprocessing` или `asyncio` для I/O. Важно понимать последствия, а не просто назвать термин.

## Замыкания и nonlocal

Замыкание — функция, которая помнит переменные внешней области видимости даже после её завершения:

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc
```

Без `nonlocal` присваивание `count += 1` создало бы новую локальную переменную внутри `inc`.

## *args и **kwargs

`*args` собирает лишние позиционные аргументы в кортеж, `**kwargs` — именованные в словарь. Они также используются, чтобы передать параметры дальше, в другую функцию.

## Контекстные менеджеры

`with` открывает ресурс и гарантирует его закрытие даже при ошибке. Можно написать свой менеджер через класс с `__enter__`/`__exit__` или через `contextlib.contextmanager`.

### Разбор 1
Решение:

```python
import functools
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"Функция {func.__name__} заняла {elapsed:.2f} сек")
        return result
    return wrapper

@timer
def big_sum():
    return sum(range(1, 1_000_001))

print(big_sum())
```

Запускаем:

```bash
python timer_demo.py
```

Примерный вывод:

```
Функция big_sum заняла 0.04 сек
500000500000
```

Что здесь происходит? `wrapper` принимает любые аргументы через `*args, **kwargs` и передаёт их исходной функции. До вызова фиксируем время, после — находим разницу. `functools.wraps` сохраняет метаданные функции (имя, докстринг), чтобы декоратор был «прозрачным». Декоратор возвращает результат функции без изменений, поэтому `print(big_sum())` печатает сумму, а не `None`.

### Разбор 2
Решение:

```python
def fibonacci(n):
    a, b = 0, 1
    for _ in range(n):
        yield a
        a, b = b, a + b

for x in fibonacci(10):
    print(x)

print(fibonacci(5))
```

Вывод первых строк:

```
0
1
1
2
3
...
```

Что здесь происходит? Ключевое слово `yield` превращает функцию в генератор. При каждом `next()` или шаге цикла выполнение приостанавливается на `yield` и отдаёт текущее значение, а при следующем вызове продолжается с этого места. Поэтому `fibonacci(5)` — объект генератора (вывод вроде `<generator object fibonacci at 0x...>`), а не список. Если бы мы строили список целиком, память росла бы линейно с `n`, а генератор хранит только две переменные — это выигрыш при больших `n`.

### Разбор 3
Исправленная версия:

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags

print(add_tag("python"))   # ['python']
print(add_tag("sql"))      # ['sql']
print(add_tag("flask"))    # ['flask']
```

Что здесь происходит? В исходном коде список `tags=[]` создавался один раз при определении функции и жил между вызовами: второй вызов добавил бы тег в тот же список, что и первый. Это классическая ловушка изменяемых дефолтных аргументов. В исправленной версии дефолт — неизменяемый `None`, а новый список создаётся при каждом вызове, где аргумент не передан. Результат: каждый вызов независим. Этот вопрос очень часто задают на интервью — будь готов объяснить оба поведения.

### Разбор 4
Решение:

```python
def make_counter():
    count = 0
    def inc():
        nonlocal count
        count += 1
        return count
    return inc

c1 = make_counter()
c2 = make_counter()
print(c1())  # 1
print(c1())  # 2
print(c2())  # 1
```

Что здесь происходит? Внутренняя функция `inc` «замыкает» переменную `count` из внешней области видимости. Без `nonlocal` оператор `count += 1` создал бы новую локальную переменную внутри `inc`, и счётчик всегда возвращал бы 1. Благодаря `nonlocal` мы говорим Python: изменяй переменную из внешней функции. Каждый вызов `make_counter()` создаёт своё замыкание со своей `count`, поэтому `c1` и `c2` независимы. Такие фабрики счётчиков — частый вопрос про замыкания.

### Разбор 5
Решение:

```python
from contextlib import contextmanager
import time

@contextmanager
def time_block():
    start = time.perf_counter()
    try:
        yield
    finally:
        elapsed = time.perf_counter() - start
        print(f"Время выполнения: {elapsed:.2f} сек")

with time_block():
    time.sleep(0.5)
```

Запускаем:

```bash
python time_block_demo.py
```

Вывод:

```
Время выполнения: 0.50 сек
```

Что здесь происходит? `@contextmanager` — декоратор из модуля `contextlib`, который превращает генератор в контекстный менеджер. Код до `yield` выполняется при входе в `with` (вход в блок), код после — при выходе. `try`/`finally` гарантирует, что замер времени произойдёт даже при исключении внутри блока. Такой менеджер удобно использовать в тестах и при профилировании кода — и это хороший ответ на вопрос «как написать свой контекстный менеджер».
