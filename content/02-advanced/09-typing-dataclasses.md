Python — язык с динамической типизацией: переменная может хранить сначала число, потом строку. Это удобно, но в больших проектах теряется понятность. Аннотации типов частично решают эту проблему.

## Аннотации функций

После имени параметра через двоеточие ставится тип, а после стрелки `->` — тип возвращаемого значения:

```python
def greet(name: str) -> str:
    return f"Привет, {name}!"

print(greet("Аня"))  # Привет, Аня!
```

Интерпретатор игнорирует аннотации при выполнении, но их читают редакторы, IDE и инструменты вроде mypy — они подсветят ошибку, если ты передашь неправильный тип.

## Аннотации переменных и коллекций

```python
age: int = 25
score: float = 4.7
tags: list[str] = ["python", "курс"]
stats: dict[str, int] = {"постов": 5}
```

Для коллекций в Python 3.9+ можно использовать встроенные `list[str]`, `dict[str, int]` и т. п. Для более старых версий — `typing.List[str]`, `typing.Dict[str, int]`.

## Модуль typing и Optional

Не всегда тип известен точно. `Optional[str]` означает «строка или None», `Union[int, float]` — «число любого из этих типов»:

```python
from typing import Optional

def search(query: str, limit: Optional[int] = None) -> list[str]:
    if limit is None:
        limit = 10
    # ...
    return []
```

Это помогает описывать реальные ситуации «значение может отсутствовать».

## Dataclasses: классы-данных без шаблонного кода

Обычно класс-хранилище данных требует много кода: `__init__`, `__repr__`, `__eq__`... Декоратор `@dataclass` генерирует их автоматически:

```python
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    author: str
    pages: int

b1 = Book("Мастер и Маргарита", "Булгаков", 480)
print(b1)  # Book(title='Мастер и Маргарита', author='Булгаков', pages=480)
```

А сравнение экземпляров тоже работает автоматически:

```python
b2 = Book("Мастер и Маргарита", "Булгаков", 480)
print(b1 == b2)  # True
```

## Значения по умолчанию и field

Поля с дефолтом должны идти после полей без него. Для изменяемых значений по умолчанию (список, словарь) используют `field(default_factory=...)`:

```python
from dataclasses import dataclass, field

@dataclass
class Library:
    name: str
    books: list[Book] = field(default_factory=list)
```

## Опция frozen=True

`frozen=True` делает экземпляры неизменяемыми, как кортежи, — защита от случайных изменений.

### Разбор 1
Решение:

```python
from dataclasses import dataclass

@dataclass
class Movie:
    title: str
    year: int
    rating: float

def best_movie(movies: list[Movie]) -> Movie:
    return max(movies, key=lambda m: m.rating)

movies = [
    Movie("Побег из Шоушенка", 1994, 9.3),
    Movie("Крёстный отец", 1972, 9.2),
    Movie("Тёмный рыцарь", 2008, 9.0),
]

winner = best_movie(movies)
print(f"Лучший фильм: {winner.title} ({winner.year}), рейтинг {winner.rating}")
```

Что здесь происходит? `@dataclass` сам генерирует конструктор, принимающий три аргумента в порядке полей, поэтому `Movie("Побег из Шоушенка", 1994, 9.3)` работает сразу. Функция `best_movie` получает весь список и возвращает результат `max(..., key=lambda m: m.rating)` — элемент с наибольшим значением `rating`. Затем мы подставляем поля объекта в f-строку и печатаем.

Вывод:

```
Лучший фильм: Побег из Шоушенка (1994), рейтинг 9.3
```

Обрати внимание: благодаря аннотациям IDE подскажет тип параметра и результат функции, а опечатку в имени поля заметит быстрее. Dataclasses дают всю эту ясность почти без шаблонного кода.

### Разбор 2
Решение:

```python
def rectangle_area(width: float, height: float = 1.0) -> float:
    return width * height

print(rectangle_area(3.5, 2))
print(rectangle_area(4))
```

Разберём. Сигнатура `def rectangle_area(width: float, height: float = 1.0) -> float` говорит: оба параметра должны быть числами с плавающей точкой, причём `height` можно опустить — тогда он станет 1.0, а функция вернёт `float`. Это не влияет на выполнение, но любой инструмент проверки типов (mypy, pyright) и редактор сразу предупредят, если вызвать функцию со строкой. Первый вызов считает `3.5 * 2 = 7.0`, второй — `4 * 1.0 = 4.0`.

Вывод:

```
7.0
4.0
```

Аннотации — это в первую очередь документация для разработчика и инструментов, а не runtime-проверка: Python не станет выбрасывать ошибку при передаче строки, но статический анализ её заметит.

### Разбор 3
Решение:

```python
from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    group: str
    grades: list[float] = field(default_factory=list)

    def average(self) -> float:
        if not self.grades:
            return 0.0
        return sum(self.grades) / len(self.grades)

anya = Student("Аня", "П-21", [4.0, 5.0])
borya = Student("Боря", "П-22")

print(f"{anya.name}: {anya.average()}")
print(f"{borya.name}: {borya.average()}")
```

Ключевой момент — `field(default_factory=list)`. Если написать `grades: list[float] = []`, то значение по умолчанию создастся один раз на весь класс, и все студенты разделят один и тот же список — это классическая ловушка. `default_factory` же вызывает `list()` заново для каждого экземпляра. Метод `average` проверяет, пуст ли список, иначе деление на ноль упало бы с `ZeroDivisionError`. У Ани среднее `(4.0 + 5.0) / 2 = 4.5`, у Бор ос оценок нет — вернётся 0.0.

Вывод:

```
Аня: 4.5
Боря: 0.0
```

Методы внутри датакласса — обычные методы: они работают так же, как в любом классе, и имеют доступ к полям через `self`.

### Разбор 4
Решение:

```python
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True)
class Point:
    x: int
    y: int

p = Point(3, 4)
try:
    p.x = 10
except FrozenInstanceError:
    print("Нельзя менять точку")
```

`frozen=True` заставляет сгенерированный `__setattr__` запрещать изменения полей: любая попытка присвоить значение существующему полю вызывает `FrozenInstanceError`. Мы перехватываем это исключение в `try/except` и печатаем своё сообщение, поэтому программа не падает. При этом читать поля по-прежнему можно: `print(p.x)` выведет 3. Неизменяемые объекты удобны для передачи в функции: можно не бояться, что кто-то случайно их испортит, и они безопасно используются как ключи словарей (если добавить `frozen=True`, генерируется и `__hash__`).

Вывод:

```
Нельзя менять точку
```

Если бы мы не поймали исключение, Python прервал бы программу трейсбеком — именно поэтому важно оборачивать рискованные операции.

### Разбор 5
Решение:

```python
def count_words(text: str) -> dict[str, int]:
    counter: dict[str, int] = {}
    for word in text.split():
        counter[word] = counter.get(word, 0) + 1
    return counter

print(count_words("кот и пёс и кот"))
```

Как это работает? `text.split()` разбивает строку по пробелам на список слов: `["кот", "и", "пёс", "и", "кот"]`. Затем цикл идёт по словам. Выражение `counter.get(word, 0)` возвращает текущий счётчик слова, а если его ещё нет — 0. Прибавляем 1 и записываем обратно. Так построение словаря частот занимает одну строку вместо ветвления `if/else`. Аннотация `counter: dict[str, int]` фиксирует тип локальной переменной, а `-> dict[str, int]` — тип результата функции.

Вывод:

```
{'кот': 2, 'и': 2, 'пёс': 1}
```

Подсчёт частот — универсальная задача анализа текста: тэги, топ слов, статистика логов. А аннотации делают такую функцию самодокументируемой.
