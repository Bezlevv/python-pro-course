Наверняка ты уже видел такой код:

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("Привет!")
```

Это контекстный менеджер. Почему `with` — это хорошо, и как делать свои контекстные менеджеры — тема этого урока.

## Проблема: ресурсы нужно освобождать

Открытый файл занимает системный ресурс (файловый дескриптор). Если не закрыть файл, другие программы могут не получить к нему доступ, а при долгой работе — закончиться дескрипторы. Без `with` приходится следить за закрытием вручную:

```python
f = open("notes.txt", "w", encoding="utf-8")
f.write("Привет!")
f.close()
```

Но если между открытием и закрытием случится ошибка, `f.close()` не выполнится, и файл «утечёт». Раньше это чинили блоком `try/finally`:

```python
f = open("notes.txt", "w", encoding="utf-8")
try:
    f.write("Привет!")
finally:
    f.close()
```

Согласись, громоздко. Контекстный менеджер делает то же самое, но компактно и гарантированно:

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("Привет!")
```

Даже если внутри блока произойдёт ошибка, файл будет закрыт.

## Как устроен with

Контекстный менеджер — это объект с двумя методами:

- `__enter__(self)` — выполняется при входе в блок `with`, возвращает объект, который попадает в переменную после `as`;
- `__exit__(self, exc_type, exc_value, traceback)` — выполняется при выходе из блока (в том числе при ошибке).

Если внутри блока возникла ошибка, `__exit__` получает её тип, значение и трейсбек. Если ошибки нет — все три параметра равны `None`. Возвращая из `__exit__` `False` (или ничего), мы говорим: «ошибку не съедаем, пусть продолжится». Вернув `True`, ошибку подавляем.

## Пишем свой контекстный менеджер

Сделаем класс, который отмечает время выполнения блока:

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        elapsed = time.perf_counter() - self.start
        print(f"Блок выполнялся {elapsed:.4f} сек")

with Timer():
    total = sum(range(10_000_000))
# Блок выполнялся 0.3521 сек
```

`__enter__` запоминает момент старта и возвращает `self` — но нам даже не обязательно писать `as`, если объект не нужен внутри блока.

## Упрощённый путь: contextlib.contextmanager

Писать класс ради двух методов бывает избыточно. Модуль `contextlib` предлагает декоратор `@contextmanager`, который из функции-генератора делает контекстный менеджер:

```python
from contextlib import contextmanager

@contextmanager
def opened(filename, mode="r"):
    f = open(filename, mode, encoding="utf-8")
    try:
        yield f          # здесь выполняется тело with
    finally:
        f.close()

with opened("notes.txt", "w") as f:
    f.write("Привет вам!")
```

Всё, что написано до `yield`, — это «вход», после `yield` — «выход». Конструкция `try/finally` гарантирует закрытие даже при ошибке.

## Реальный сценарий: соединение с базой данных

Контекстные менеджеры идеальны для работы с ресурсами:

```python
@contextmanager
def db_connection(url):
    conn = connect_to_db(url)   # условный код
    try:
        yield conn
    finally:
        conn.close()
```

Независимо от того, завершился запрос успешно или упал, соединение закроется.

## Итог

Контекстный менеджер автоматизирует «вход» и «выход» из блока: открыл — закрыл, начал — завершил. Через `__enter__/__exit__` делается полноценный класс, через `@contextmanager` — компактная функция. Главное правило: всё, что открывается, должно закрываться, и `with` — самый надёжный способ этого добиться.

### Разбор 1
Одно из возможных решений:

```python
class Suppress:
    def __init__(self, error_type):
        self.error_type = error_type

    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        if exc_type is not None and issubclass(exc_type, self.error_type):
            print(f"Исключение подавлено: {exc_value}")
            return True
        return False

with Suppress(ZeroDivisionError):
    result = 1 / 0
    print(result)  # не выполнится

print("Программа продолжает работу")
```

Результат:

```
Исключение подавлено: division by zero
Программа продолжает работу
```

Что здесь происходит? Конструктор сохраняет класс исключения, который мы хотим подавлять. В `__enter__` мы просто возвращаем `self` — объект внутри блока не нужен, но «правильный» контекстный менеджер всё равно должен вернуть что-то.

Ключевая логика — в `__exit__`. Параметр `exc_type` содержит тип случившегося исключения (или `None`, если всё прошло хорошо). `issubclass(exc_type, self.error_type)` проверяет, является ли случившееся исключение нашим целевым (или его наследником) — благодаря этому, например, подавится и `ZeroDivisionError`, и любой его подкласс.

Если условие истинно, мы печатаем сообщение и возвращаем `True` — это сигнал Python'у: «ошибку я обработал, дальше её не бросай». Поэтому после блока выполняется следующая команда. Если бы мы вернули `False`, ошибка продолжила бы распространяться и программа упала.

Такой приём полезен, когда нужно продолжить выполнение несмотря на некоторые ошибки, но скрывать их совсем нельзя — про них стоит хотя бы сообщить.

### Разбор 2
Решение:

```python
class Banner:
    def __enter__(self):
        print("=== Начало блока ===")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("=== Конец блока ===")

with Banner():
    print("Работаем...")
```

Результат:

```
=== Начало блока ===
Работаем...
=== Конец блока ===
```

Порядок вывода демонстрирует жизненный цикл контекстного менеджра. Сначала Python вызывает `__enter__` — он печатает верхний разделитель и возвращает `self`. Затем выполняется тело блока `with` — печатается `Работаем...`. Наконец, после выхода из блока автоматически вызывается `__exit__` — он печатает нижний разделитель.

`__exit__` здесь не возвращает ничего (то есть `None`), что эквивалентно `False`: ошибки не подавляются. Если бы внутри блока возникло исключение, `__exit__` всё равно был бы вызван — и нижний разделитель появился бы независимо от ошибки. Это главное свойство контекстных менеджеров: код из `__exit__` выполняется гарантированно, как `finally`.

### Разбор 3
Решение:

```python
import time
from contextlib import contextmanager

@contextmanager
def timed():
    start = time.perf_counter()
    try:
        yield
    finally:
        elapsed = time.perf_counter() - start
        print(f"Блок выполнялся {elapsed:.4f} сек")

with timed():
    total = sum(range(10_000_000))
```

Результат (время может отличаться):

```
Блок выполнялся 0.3521 сек
```

Декоратор `@contextmanager` превращает функцию-генератор в контекстный менеджер. Всё, что написано до `yield`, выполняется при входе в блок `with`: здесь мы запоминаем момент старта в `start`. Оператор `yield` — точка «разрыва»: в этот момент выполняется тело блока `with` (вычисление суммы). После того как тело завершилось, выполнение продолжается со строки после `yield` — в блоке `finally` мы считаем прошедшее время и печатаем его.

Конструкция `try/finally` важна: даже если внутри `with` случится ошибка, код в `finally` всё равно выполнится, и время будет напечатано. Такой менеджер экономно пишется одной функцией, без класса с двумя методами. Погрешность измерения есть всегда, поэтому вывод будет чуть-чуть различаться от запуска к запуску — это нормально.

### Разбор 4
Решение:

```python
class ExpectError:
    def __init__(self, error_type):
        self.error_type = error_type

    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        if exc_type is None:
            print("Ошибки не было")
            return False
        if issubclass(exc_type, self.error_type):
            print(f"Ошибка поймана: {exc_value}")
            return True
        return False

with ExpectError(ValueError):
    number = int("abc")
```

Результат:

```
Ошибка поймана: invalid literal for int() with base 10: 'abc'
```

В `__exit__` три ветки. Первая: `exc_type is None` — ошибки не было; печатаем `Ошибки не было` и возвращаем `False` (делать нечего). Вторая: ошибка есть и является экземпляром ожидаемого типа — проверка `issubclass(exc_type, self.error_type)` истинна; печатаем сообщение с текстом ошибки (`exc_value`) и возвращаем `True`, подавляя исключение. Третья: ошибка есть, но другого типа — возвращаем `False`, и исключение спокойно распространяется дальше.

`int("abc")` действительно бросает `ValueError` — именно его мы ожидаем, поэтому блок не падает, а печатает сообщение. Такой менеджер полезен в тестах и при обработке ожидаемых сбоев: он явно показывает, что ошибка возникла и была обработана.

### Разбор 5
Решение:

```python
class Transaction:
    def __init__(self, start_balance):
        self.balance = start_balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        self.balance -= amount

    def __enter__(self):
        self.start_balance = self.balance
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        if exc_type is None:
            print(f"Коммит: баланс {self.balance}")
            return False
        self.balance = self.start_balance
        print(f"Откат: баланс {self.balance}")
        return False

t = Transaction(100)
try:
    with t as tr:
        tr.deposit(50)
        raise ValueError("сбой")
except ValueError:
    pass

print(t.balance)
```

Результат:

```
Откат: баланс 100
100
```

Это паттерн «транзакция»: изменения применяются, только если блок завершился без ошибок. `__enter__` запоминает стартовый баланс в `self.start_balance`. Внутри блока мы кладём 50 (баланс становится 150), а затем бросаем `ValueError`. При выходе `__exit__` видит `exc_type`, не равный `None`, — значит, произошла ошибка. Восстанавливаем баланс (`self.balance = self.start_balance` — снова 100), печатаем `Откат...` и возвращаем `False`, чтобы исключение распространилось наружу, где мы его перехватываем.

Если бы ошибки не было, `__exit__` напечатал бы `Коммит: баланс 150` и оставил изменения. Такой приём используется в базах данных (ROLLBACK при ошибке), в работе с файлами и в любых операциях, где нужна атомарность: либо всё применяется, либо всё откатывается.
