В прошлом уроке мы научились создавать классы. Но что делать, когда у нескольких классов много общего? Например, и `Dog`, и `Cat` умеют есть и спать, но говорят по-разному. Дублировать код не хочется — здесь на помощь приходит **наследование**.

## Базовый и дочерний класс

Наследование позволяет создать новый класс на основе существующего. Новый класс (дочерний) получает все атрибуты и методы базового (родительского) класса и может добавить свои.

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(f"{self.name} ест.")

    def sleep(self):
        print(f"{self.name} спит.")

class Dog(Animal):
    def bark(self):
        print(f"{self.name} лает!")

dog = Dog("Рекс")
dog.eat()     # Рекс ест. (метод из Animal)
dog.sleep()    # Рекс спит. (метод из Animal)
dog.bark()     # Рекс лает! (свой метод)
```

Чтобы указать родителя, напиши его имя в скобках после имени класса: `class Dog(Animal)`. Теперь у объекта `dog` есть всё, что есть у `Animal`, плюс собственный метод `bark`.

## Переопределение методов

Дочерний класс может заменить поведение родительского метода, просто объявив метод с тем же именем:

```python
class Dog(Animal):
    def sleep(self):
        print(f"{self.name} не спит — охраняет дом!")
```

Теперь `dog.sleep()` выведет другую фразу. Это называется **переопределением метода** (override).

## Вызов родительского кода: super()

Часто в дочернем конструкторе нужно повторить логику родительского и добавить свою. Для этого используется функция `super()`:

```python
class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)   # вызовем конструктор Animal
        self.breed = breed

dog = Dog("Рекс", "овчарка")
print(dog.name, dog.breed)  # Рекс овчарка
```

`super().__init__(name)` — это «обратись к родительскому классу и вызови его `__init__`». Так мы не дублируем строку `self.name = name`.

Лучше всего мыслить так: `super()` — это ссылка на родителя, через которую ты можешь дёрнуть любой его метод.

## Полиморфизм

**Полиморфизм** — это способность разных объектов реагировать на один и тот же вызов по-своему. Допустим, в списке `animals` фактически лежат объекты разных классов, и каждый выполняет свой вариант метода:

```python
class Cat(Animal):
    def speak(self):
        print(f"{self.name} говорит: Мяу!")

class Dog(Animal):
    def speak(self):
        print(f"{self.name} говорит: Гав!")

animals = [Dog("Рекс"), Cat("Барсик")]
for animal in animals:
    animal.speak()
# Рекс говорит: Гав!
# Барсик говорит: Мяу!
```

Цикл не знает, кто именно лежит в списке, — он просто вызывает `speak()`, а каждый класс сам решает, что делать. Это и есть полиморфизм: один интерфейс, разные реализации.

Ещё один родственный механизм — **утиная типизация**: Python не требует, чтобы объект был наследником конкретного класса, ему важны методы. Если объект крякает как утка — значит, утка. Поэтому код вроде `for item in sequence` работает с любым объектом, который умеет итерироваться.

## Проверка типа: isinstance()

Иногда нужно проверить, является ли объект экземпляром класса:

```python
print(isinstance(dog, Dog))     # True
print(isinstance(dog, Animal))  # True — Dog наследник Animal
print(isinstance(dog, Cat))     # False
```

Обрати внимание: `isinstance` возвращает `True` и для родительских классов.

## Итог

Наследование помогает переиспользовать код и строить иерархии, переопределение меняет поведение, а `super()` позволяет аккуратно расширять родительские методы. Полиморфизм делает код гибким: один и тот же вызов работает для разных объектов.

### Разбор 1
Одно из возможных решений:

```python
import math

class Shape:
    def area(self):
        return 0

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return math.pi * self.radius ** 2

shapes = [Rectangle(4, 5), Circle(3)]
for shape in shapes:
    print(shape.area())
```

Результат:

```
20
28.274333882308138
```

Что здесь происходит? Базовый класс `Shape` задаёт общий контракт: у каждой фигуры есть метод `area()`. Его реализация по умолчанию возвращает 0 — это заглушка. Класс `Rectangle` хранит ширину и высоту и переопределяет `area()`, возвращая произведение. Класс `Circle` хранит радиус и считает площадь по формуле, используя `math.pi` из стандартного модуля.

Цикл работает благодаря полиморфизму: ему всё равно, какой конкретно класс лежит в списке — он вызывает `area()`, а каждый класс сам считает свою площадь. Если бы мы забыли переопределить `area()` в дочернем классе, вернулся бы 0 из базового класса — поэтому полезно задавать такой «контракт».

Заметь: результат второй строки отличается от ожидаемых 28.27 — это нормально, `math.pi` более точный, чем 3.14159. При желании можно округлить: `round(shape.area(), 2)`.

### Разбор 2
Решение:

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"Животное {self.name} издаёт звук.")

class Dog(Animal):

```

Результат:

```

Рекс лает!
```

Конструктор `Dog` принимает два аргумента, но атрибут `name` он не присваивает сам — он делегирует эту работу родителю через `super().__init__(name)`. Это устраняет дублирование: логика «сохранить имя» живёт в одном месте, в `Animal`. Порода — специфическая для собаки деталь, поэтому она сохраняется в дочернем классе уже после вызова родителя.

Метод `speak()` переопределён: у `Animal` он печатает общую фразу, а у `Dog` — свою. При вызове `dog.speak()` Python находит метод сначала в классе `Dog` и выполняет именно его; метод родителя при этом не вызывается. Именно так и работает переопределение: одно имя метода — разное поведение в разных классах.

### Разбор 3
Решение:

```python
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def annual_salary(self):
        return self.salary * 12

    def describe(self):
        print(f"{self.name} зарабатывает {self.salary} руб. в месяц")

class Manager(Employee):
    def __init__(self, name, salary, team_size):
        super().__init__(name, salary)
        self.team_size = team_size

    def describe(self):
        super().describe()
        print(f"Управляет командой из {self.team_size} человек")

m = Manager("Аня", 60000, 5)
m.describe()
print(m.annual_salary())
```

Результат:

```
Аня зарабатывает 60000 руб. в месяц
Управляет командой из 5 человек
720000
```

Конструктор `Manager` вызывает `super().__init__(name, salary)`, поэтому атрибуты `name` и `salary` появляются у менеджера без повторения кода, а `team_size` — дополнительный атрибут дочернего класса.

Отдельного внимания заслуживает `describe()`. Здесь используется расширение родительского метода, а не замена: сначала `super().describe()` выполняет оригинальную версию из `Employee` — печатает первую строку. Затем продолжает свой код и печатает вторую. Такой приём называют «расширением метода»: мы сохраняем поведение родителя и добавляем к нему своё. Метод `annual_salary()` вообще не переопределялся — он наследуется в готовом виде и возвращает 60000 × 12 = 720000.

### Разбор 4
Решение:

```python
class Shape:
    def area(self):
        return 0

class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2

class Triangle(Shape):
    def __init__(self, base, height):
        self.base = base
        self.height = height

    def area(self):
        return 0.5 * self.base * self.height

def print_area(shape):
    print(shape.area())

shapes = [Square(4), Triangle(6, 4)]
for shape in shapes:
    print_area(shape)
```

Результат:

```
16
12.0
```

Это классический пример полиморфизма. Функция `print_area(shape)` ничего не знает о конкретных классах — она лишь вызывает `shape.area()` и печатает результат. При этом для квадрата сработает переопределённый `area()` из `Square` (4² = 16), а для треугольника — из `Triangle` (0.5 × 6 × 4 = 12.0). Одна функция обслуживает любые фигуры, которым не нужно отдельное ветвление `if isinstance(...)`.

Если бы кто-то добавил новый класс `Polygon(Shape)` — `print_area` продолжила бы работать без изменений. В этом практический смысл полиморфизма: код, написанный против общего интерфейса, автоматически поддерживает новые реализации. Базовый класс обеспечивает контракт (метод `area()` существует у всех наследников) и безопасное поведение по умолчанию.

### Разбор 5
Решение:

```python
class Vehicle:
    def __init__(self, speed):
        self.speed = speed

    def move(self):
        print(f"Транспорт движется со скоростью {self.speed} км/ч")

class Car(Vehicle):
    def move(self):
        print(f"Машина едет — {self.speed} км/ч")

class Bicycle(Vehicle):
    def move(self):
        print(f"Велосипед едет — {self.speed} км/ч")

car = Car(120)
bike = Bicycle(25)
print(isinstance(car, Vehicle))
print(isinstance(bike, Vehicle))
car.move()
bike.move()
```

Результат:

```
True
True
Машина едет — 120 км/ч
Велосипед едет — 25 км/ч
```

У классов `Car` и `Bicycle` нет собственных конструкторов — они наследуют `__init__` от `Vehicle`, поэтому автоматически получают атрибут `speed`. Это экономит код: общая часть («транспорт имеет скорость») описана один раз.

`isinstance(car, Vehicle)` возвращает `True`, потому что `Car` — наследник `Vehicle`; проверка учитывает всю цепочку наследования. Метод `move()` переопределён в обоих дочерних классах: одинаковый вызов `car.move()` и `bike.move()` даёт разные сообщения, подставляя свою скорость. Это ещё одна иллюстрация полиморфизма: общий интерфейс `move()`, разные реализации. Такой код легко расширять — например, добавить `Truck(Vehicle)` с собственным `move()`.
