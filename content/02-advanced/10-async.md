Когда программа ждёт ответа от сети или чтения диска, процессор простаивает. Асинхронность позволяет во время такого ожидания заниматься другими задачами.

## Корутины

Функция, объявленная через `async def`, называется корутиной. При вызове она не выполняет тело, а возвращает объект корутины:

```python
import asyncio

async def hello():
    print("Начали")
    await asyncio.sleep(1)
    print("Готово")

asyncio.run(hello())
```

`await` — знак «передай управление циклу событий, пока ждём». `asyncio.run()` запускает главную корутину и управляет циклом событий. Именно он должен быть точкой входа.

## Последовательно или конкурентно?

Представь, что нужно «загрузить» три страницы, каждая по секунде. Если вызывать их по очереди через `await`, суммарно выйдет 3 секунды:

```python
async def download(name: str) -> str:
    await asyncio.sleep(1)
    return f"{name}: готово"
```

Но если объединить вызовы в `asyncio.gather`, загрузки стартуют практически одновременно, и общее время останется около 1 секунды:

```python
async def main():
    results = await asyncio.gather(
        download("страница 1"),
        download("страница 2"),
        download("страница 3"),
    )
    for r in results:
        print(r)

asyncio.run(main())
```

## Задачи: asyncio.create_task

Иногда удобнее запустить корутину «в фоне» и продолжить основную работу. Для этого служат задачи:

```python
async def main():
    task = asyncio.create_task(download("страница 1"))
    print("Делаю что-то ещё, пока грузится...")
    result = await task
    print(result)
```

Важно: `await task` дожидается завершения задачи.

## Чего делать нельзя

Внутри корутины нельзя блокировать цикл обычным `time.sleep()` — тогда всё «замрёт». Используй `asyncio.sleep()` или асинхронные библиотеки (aiohttp, asyncpg и др.) для реальных I/O операций.

## Когда это пригодится

Веб-серверы (FastAPI, aiohttp), парсеры, боты, клиенты API — везде, где много сетевых запросов, асинхронность даёт прирост скорости при очень простом написании кода.

## Итог урока

Мы узнали:

- корутины (`async def`) и `await`;
- `asyncio.run()` для запуска;
- `asyncio.gather()` для конкурентного выполнения;
- `asyncio.create_task()` для фоновых задач;
- отличие `asyncio.sleep` от блокирующего `time.sleep`.

### Разбор 1
Решение:

```python
import asyncio
import time

async def load(name: str, delay: int) -> str:
    print(f"Начинаю загрузку: {name}")
    await asyncio.sleep(delay)
    print(f"Завершил: {name}")
    return f"{name}: готово"

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(
        load("страница 1", 1),
        load("страница 2", 2),
        load("страница 3", 3),
    )
    elapsed = time.perf_counter() - start
    for r in results:
        print(r)
    print(f"Общее время: {elapsed:.2f} сек")

asyncio.run(main())
```

Как это работает? Все три корутины передаются в `asyncio.gather` одновременно. Цикл событий начинает первую, доходит до `await asyncio.sleep(1)` и «запоминает», что нужно вернуться через секунду, а сам переходит ко второй корутине — так он переключается между всеми тремя. Когда все таймеры срабатывают, печатаются сообщения о завершении, а `gather` собирает результаты в список в том же порядке, в котором были переданы аргументы.

Пример полез вывода:

```
Начинаю загрузку: страница 1
Начинаю загрузку: страница 2
Начинаю загрузку: страница 3
Завершил: страница 1
Завершил: страница 2
Завершил: страница 3
страница 1: готово
страница 2: готово
страница 3: готово
Общее время: 3.00 сек
```

Если бы код был последовательным, время составило бы 6 секунд: асинхронность позволила выполнить задержки параллельно, поэтому уложились в 3 секунды — это и есть главная выгода.

### Разбор 2
Решение:

```python
import asyncio
import time

async def download(name: str) -> str:
    await asyncio.sleep(1)
    return f"{name}: готово"

async def main():
    start = time.perf_counter()
    r1 = await download("страница 1")
    r2 = await download("страница 2")
    r3 = await download("страница 3")
    sequential = time.perf_counter() - start

    start = time.perf_counter()
    results = await asyncio.gather(
        download("страница 1"),
        download("страница 2"),
        download("страница 3"),
    )
    concurrent = time.perf_counter() - start

    print(f"Последовательно: {sequential:.2f} сек")
    print(f"Конкурентно: {concurrent:.2f} сек")

asyncio.run(main())
```

В последовательном варианте каждый `await download(...)` полностью дожидается одной секунды, прежде чем выполнится следующая строка: получается 3 секунды суммарно. В конкурентном варианте все три корутины создаются и планируются сразу, их `sleep` идут параллельно, поэтому время около 1 секунды. Замеры через `time.perf_counter()` до и после каждого способа наглядно показывают разницу: примерно 3.00 и 1.00 секунды. Вывод будет примерно таким:

```
Последовательно: 3.00 сек
Конкурентно: 1.01 сек
```

Это и есть суть асинхронности: ожидание не простаивает, а используется другими задачами.

### Разбор 3
Решение:

```python
import asyncio

async def load(name: str, delay: int) -> str:
    print(f"{name}: началась")
    await asyncio.sleep(delay)
    print(f"{name}: завершилась")
    return "данные: готово"

async def main():
    task = asyncio.create_task(load("загрузка", 2))
    print("Основная работа идёт...")
    result = await task
    print(result)

asyncio.run(main())
```

`asyncio.create_task(load("загрузка", 2))` не ждёт завершения корутины: она планируется на выполнение, а управление сразу возвращается в `main`. Поэтому следующая строка `print("Основная работа идёт...")` выполняется немедленно — в этот момент загрузка ещё «идёт» в фоне. Затем `await task` приостанавливает `main`, пока задача не закончится, и возвращает её результат. Порядок вывода: сначала основная работа, потом сообщения загрузки, потом результат.

Вывод:

```
Основная работа идёт...
загрузка: началась
загрузка: завершилась
данные: готово
```

Задачи удобны, когда нужно запустить несколько длительных операций и заниматься своими делами, пока они выполняются.

### Разбор 4
Решение:

```python
import asyncio

async def risky(name: str, delay: int, fail: bool = False) -> str:
    await asyncio.sleep(delay)
    if fail:
        raise ValueError(f"{name} упал")
    return f"{name}: ок"

async def main():
    results = await asyncio.gather(
        risky("страница 1", 1),
        risky("страница 2", 2, fail=True),
        risky("страница 3", 3),
        return_exceptions=True,
    )
    for r in results:
        if isinstance(r, Exception):
            print("Сбой: ValueError")
        else:
            print(r)

asyncio.run(main())
```

По умолчанию `gather` при первой же ошибке прерывает выполнение и пробрасывает исключение наружу. Флаг `return_exceptions=True` меняет поведение: вместо прерывания в список результатов кладётся сам объект исключения, и остальные корутины успешно завершаются. В цикле мы проверяем `isinstance(r, Exception)` — если да, значит, это не результат, а сбой (у нас `ValueError`), и печатаем сообщение; иначе выводим строку результата.

Вывод:

```
страница 1: ок
Сбой: ValueError
страница 3: ок
```

Такой паттерн незаменим при массовых сетевых запросах, где одна неудача не должна губить всю пачку.

### Разбор 5
Решение:

```python
import asyncio

async def slow_work() -> str:
    await asyncio.sleep(5)
    return "готово"

async def main():
    try:
        async with asyncio.timeout(2):
            result = await slow_work()
            print(result)
    except TimeoutError:
        print("Не уложились в 2 секунды")

asyncio.run(main())
```

`asyncio.timeout(2)` — контекстный менеджер: если код внутри `async with` не завершится за 2 секунды, ожидающая корутина будет отменена, а из блока вылетит `TimeoutError` (в Python 3.11+). Мы ловим его в `except TimeoutError` и печатаем своё сообщение. `slow_work` спит 5 секунд, что больше лимита, поэтому тайм-аут сработает, строка `print(result)` не выполнится.

Вывод:

```
Не уложились в 2 секунды
```

Тайм-ауты — обязательная защита в реальных программах: сетевой запрос может зависнуть, и лучше вернуть ошибку через пару секунд, чем ждать вечно.
