В этом уроке ты научишься писать HTML так, чтобы и браузер, и поисковые системы, и скринридеры (программы озвучивания для незрячих людей) одинаково хорошо понимали твою страницу. Это называется **семантической вёрсткой**, и это первый шаг к профессиональному фронтенду.

## Почему семантика важна

Браузер не «читает» страницу, как человек. Он разбирает DOM-дерево, и от того, какие теги ты используешь, зависит очень многое:

- **SEO.** Поисковые системы лучше ранжируют страницы, где заголовки, списки и основное содержимое размечены правильно.
- **Доступность (a11y).** Скринридер объявляет `header`, `nav`, `article` особым образом: пользователь может перепрыгивать между секциями.
- **Надёжность.** Семантический код легче поддерживать, а тесты на него писать проще — об этом мы поговорим в задачах.

## Каркас документа

Каждая страница начинается с каркаса. Обрати внимание на атрибут `lang` — он обязателен для доступности, ведь скринридер по нему выбирает произношение:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Мой блог</title>
</head>
<body>
    <!-- содержимое -->
</body>
</html>
```

`<meta name="viewport">` нужен для корректного отображения на телефонах, а `charset="UTF-8"` — для русского текста.

## Основные семантические теги

Главное правило: **тег выбирается по смыслу, а не по внешнему виду**.

- `<header>` — шапка страницы или секции: логотип, название, меню.
- `<nav>` — главная навигация по сайту (если меню одно — оно обычно одно и в `header`).
- `<main>` — основное содержимое страницы. Он должен быть **единственным** на странице.
- `<section>` — логическая секция с собственным заголовком (`<h2>` и ниже).
- `<article>` — самостоятельный законченный блок: запись блога, комментарий, карточка товара.
- `<aside>` — боковая панель: дополнительная информация, ссылки, реклама.
- `<footer>` — подвал: копирайт, контакты, ссылки.
- `<figure>` и `<figcaption>` — иллюстрация и её подпись.
- `<time datetime="...">` — дата в машиночитаемом виде.
- `<address>` — контактная информация.
- `<details>` / `<summary>` — раскрывающийся блок.
- `<mark>` — выделенный фрагмент текста.

Вот минимальный пример семантического каркаса сайта:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Портфолио</title>
</head>
<body>
    <header>
        <nav aria-label="Главное меню">
            <ul>
                <li><a href="#about">Обо мне</a></li>
                <li><a href="#works">Работы</a></li>
                <li><a href="#contacts">Контакты</a></li>
            </ul>
        </nav>
    </header>

    <main>
        <section id="about">
            <h1>Аня</h1>
            <p>Я веб-разработчица.</p>
        </section>

        <section id="works">
            <h2>Мои работы</h2>
            <article>
                <h3>Интернет-магазин</h3>
                <p>Обложка проекта...</p>
            </article>
        </section>
    </main>

    <aside>
        <h2>Навыки</h2>
        <ul>
            <li>HTML/CSS</li>
            <li>Python</li>
        </ul>
    </aside>

    <footer>
        <address>Москва, ул. Примерная, 1</address>
    </footer>
</body>
</html>
```

Заметь: `<h1>` в документе один, и он в `<main>`. Заголовки образуют иерархию: `h1` → `h2` → `h3`.

## Доступность: начало

Доступность — это про то, чтобы сайтом могли пользоваться все: например, незрячие люди через скринридер или люди, которые управляют компьютером только с клавиатуры. Базовый минимум:

- **`alt` у изображений.** Он читается скринридером вместо картинки. Декоративные картинки получают `alt=""` (пустой — скринридер просто пропустит её).
- **`<label>` у полей форм.** Текст подписи должен быть связан с полем через `for` и `id`.
- **Логичный порядок фокуса.** Клавиатурная навигация идёт по порядку элементов в DOM, поэтому семантическая структура важна не только «для вида».
- **Ссылка «Перейти к содержимому» (skip-link).** Первая ссылка на странице ведёт к `<main>` и видна только при фокусе.

## ARIA

ARIA (Accessible Rich Internet Applications) — это атрибуты, которые дополняют семантику, когда стандартных тегов не хватает. Наиболее частые:

- `role` — роль элемента, например `role="navigation"`, `role="alert"`.
- `aria-label` — доступное имя элемента, если видимого текста нет (например, у кнопки-иконки).
- `aria-hidden="true"` — скрыть элемент от скринридера (например, декоративную иконку).
- `aria-live="polite"` — область, где появляются динамические сообщения, чтобы скринридер озвучил их.

Важно: **не дублируй то, что уже есть в теге**. Если ты используешь `<nav>`, добавлять ему `role="navigation"` не нужно — роль уже встроена. ARIA нужен там, где семантика тегов недостаточна:

```html
<header>
    <nav>
        <ul>
            <li><a href="#home" aria-current="page">Главная</a></li>
            <li><a href="#blog">Блог</a></li>
        </ul>
    </nav>
</header>

<button aria-label="Открыть меню">☰</button>

<img src="decor.svg" alt="">
<p aria-live="polite" role="status">Товар добавлен в корзину</p>
```

## Проверка своей страницы

Два простых способа проверить доступность и валидность:

- [W3C Validator](https://validator.w3.org/) — проверяет синтаксис HTML.
- Расширение **axe DevTools** или Lighthouse в инструментах разработчика Chrome — автоматические проверки доступности.

Хорошая привычка: перед сдачей работы проходиться по странице клавишами `Tab` — весь контент должен быть доступен без мыши.

### Разбор 2
Тест `test_semantics.py`:

```python
import pytest
from bs4 import BeautifulSoup


@pytest.fixture
def soup():
    with open("semantic.html", encoding="utf-8") as f:
        return BeautifulSoup(f.read(), "html.parser")


def test_one_main_header_footer(soup):
    assert len(soup.find_all("main")) == 1
    assert len(soup.find_all("header")) == 1
    assert len(soup.find_all("footer")) == 1


def test_nav_has_two_links(soup):
    nav = soup.find("nav")
    assert nav is not None
    assert len(nav.find_all("a")) == 2


def test_single_h1_inside_main(soup):
    main = soup.find("main")
    h1s_in_main = main.find_all("h1")
    assert len(h1s_in_main) == 1
    assert len(soup.find_all("h1")) == 1


def test_page_mentions_name(soup):
    assert "Аня" in soup.get_text()
```

Что здесь происходит? Через `BeautifulSoup` мы разбираем HTML в дерево. `find_all("main")` возвращает список всех `<main>` — их должно быть ровно по одному. Для навигации мы сначала находим сам `<nav>`, а внутри него считаем ссылки. Тест `test_single_h1_inside_main` проверяет сразу два факта: `h1` есть внутри `main` и он единственный на всей странице. `soup.get_text()` возвращает весь видимый текст без тегов, поэтому проверка имени работает даже если «Аня» находится в разных частях разметки. Запуск: `python -m pytest test_semantics.py`.

### Разбор 4
Тест `test_accessibility.py`:

```python
from bs4 import BeautifulSoup


def load_html():
    with open("semantic.html", encoding="utf-8") as f:
        return BeautifulSoup(f.read(), "html.parser")


def test_html_has_lang():
    soup = load_html()
    assert soup.html.get("lang") == "ru"


def test_skip_link_is_first():
    soup = load_html()
    body_children = list(soup.body.children)
    first_tag = next(el for el in body_children if getattr(el, "name", None))
    assert first_tag.get("class") == ["skip-link"]


def test_nav_has_aria_label():
    soup = load_html()
    assert soup.find("nav").get("aria-label") == "Главное меню"


def test_label_connected_to_input():
    soup = load_html()
    label = soup.find("label", attrs={"for": "search"})
    field = soup.find(id="search")
    assert label is not None and field is not None


def test_aria_hidden_exists():
    soup = load_html()
    assert soup.find(attrs={"aria-hidden": "true"}) is not None
```

Что здесь происходит? В `test_skip_link_is_first` мы перебираем прямых потомков `<body>` и берём первый элемент-тег (у текстовых узлов нет атрибута `name`). Это честнее, чем просто искать ссылку: мы проверяем именно её позицию. Тест подписи убеждается, что и `<label for="search">`, и `<input id="search">` существуют — значит, связь не порвана. `soup.find(attrs={"aria-hidden": "true"})` ищет любой элемент с этим атрибутом. Все пять тестов должны пройти после выполнения задачи 3.


Что здесь происходит? `<article>` оборачивает законченную новость целиком: её можно вынести из страницы, не потеряв смысл. `<time>` содержит человекочитаемую дату и машиночитаемую — в `datetime` (формат ГГГГ-ММ-ДД). `<figure>` связывает картинку с подписью `<figcaption>`: скринридер прочитает подпись, а в `alt` — описание самой картинки. `<details>/<summary>` создаёт раскрывающийся блок без единой строчки JavaScript. `<address>` содержит контактную информацию. `<mark>` выделяет важное слово. Такой блок одинаково хорошо читают и люди, и автоматические парсеры.

Сколько тегов h1 рекомендуется иметь на странице?
- Один
- Сколько угодно
- Не больше трёх
* Правильный ответ: Один
Один h1 на страницу — требование семантики и SEO.

Что делает атрибут aria-hidden="true"?
- Невидимым в браузере
- Скрывает элемент от скринридера
- Отключает элемент
* Правильный ответ: Скрывает элемент от скринридера
aria-hidden убирает элемент из дерева доступности — скринридер его не зачитает.

Внутри какого тега логично разместить список ссылок главного меню?
- div

- Пустую строку alt=""
- Описание картинки
- Ничего не указывать
* Правильный ответ: Пустую строку alt=""
Пустой alt говорит скринридеру пропустить картинку — она не несёт информации.

Какой атрибут обязателен у тега html для доступности?
- lang

* Правильный ответ: lang

- Для создания таблицы

figure объединяет медиа-контент и figcaption — подпись к нему.

- Ссылка в шапку сайта
