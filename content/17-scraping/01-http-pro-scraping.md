В предыдущем модуле ты уже освоил библиотеку `requests`. Но парсинг предъявляет к HTTP-клиенту особые требования: многие сайты защищаются от скриптов, отдают разный контент разным клиентам и не любят, когда по ним долбят с одной скоростью. В этом уроке мы соберём «боевой» HTTP-клиент: с сессиями, правильными заголовками, тайм-аутами, ретраями и прокси. Это фундамент любого парсера — без него даже красивая работа с HTML не принесёт данных.

## Сессии: почему один requests.get() мало

Каждый `requests.get()` — это независимый визит. Сервер не помнит тебя между запросами, если ты сам не сохранишь его «метки» — куки. Куки — это маленькие кусочки данных (обычно строка вида `sessionid=abc123`), которые сервер выдаёт при первом визите и потом проверяет. Именно так работают логин, корзины и «запомнить меня».

Чтобы куки сохранялись автоматически, используй объект `requests.Session()`:

```python
import requests

s = requests.Session()
# сервер выдаст две куки
s.get("https://httpbin.org/cookies/set?name=anya&role=student")
# проверяем, что они сохранились
print(s.get("https://httpbin.org/cookies").json())
```

Сессия — это «контейнер», в котором живут куки, заголовки по умолчанию и даже настройки прокси. Если создать новую сессию, она начнёт с чистого листа.

## Заголовки: представляемся правильно

Сервер видит не только URL, но и заголовки запроса. Самый важный — `User-Agent`: в нём клиент сообщает, кто он такой (браузер, мобильное приложение, скрипт). Некоторые сайты блокируют пустой `User-Agent` или отдают «урезанную» версию страницы скриптам:

```python
headers = {
    "User-Agent": "MyCourseScraper/1.0 (student@example.com)",
    "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
    "Accept-Language": "ru-RU,ru;q=0.9,en;q=0.7",
}
r = requests.get("https://httpbin.org/headers", headers=headers, timeout=10)
print(r.json()["headers"]["User-Agent"])
```

Важно: цель заголовков — вежливо идентифицировать себя, а не притворяться настоящим браузером, чтобы обмануть сайт. Заголовок `Accept` сообщает, какие форматы ответа ты готов принять, а `Accept-Language` — какой язык предпочитаешь.

## Тайм-ауты: чтобы не зависнуть навсегда

Парсер, который работает вечно, хуже парсера, который падает. Если сервер молчит, `requests` без `timeout` будет ждать бесконечно. Всегда передавай `timeout` — это число секунд ожидания ответа:

```python
r = requests.get("https://httpbin.org/delay/2", timeout=5)
```

Если сервер не успеет, поднимется исключение `requests.Timeout`. Лови его и решай, что делать: попробовать ещё раз или пропустить страницу.

## Ретраи: когда ошибка временная

Коды `500`, `502`, `503`, `504` означают, что серверу временно плохо, и повторный запрос через секунду-другую может пройти. Вручную писать циклы с `time.sleep` можно, но `requests` предлагает элегантный способ — `HTTPAdapter` вместе с `Retry` из `urllib3`:

```python
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

s = requests.Session()
retry = Retry(total=3, backoff_factor=0.5,
              status_forcelist=[500, 502, 503, 504])
s.mount("https://", HTTPAdapter(max_retries=retry))
```

`total=3` — сколько попыток максимум, `backoff_factor=0.5` — пауза между попытками растёт (0.5 с, 1 с, 2 с...), `status_forcelist` — какие коды считать временными. Теперь `s.get()` сам переспросит сервер при 502-х ошибках.

## Прокси: выходим через другую дверь

Прокси — это промежуточный сервер, через который уходит твой запрос. С точки зрения сайта, трафик придёт с IP прокси, а не с твоего. Это нужно для распределения нагрузки, обхода блокировок по IP и тестирования гео-доступности:

```python
proxies = {
    "http": "http://user:pass@127.0.0.1:8080",
    "https": "http://user:pass@127.0.0.1:8080",
}
r = requests.get("https://httpbin.org/ip", proxies=proxies, timeout=10)
print(r.json())
```

Прокси задаётся словарём: отдельно для `http` и `https`. Учти: прокси не делает тебя анонимным «по волшебству» — при HTTPS сайт всё равно видит конечный адрес, а данные в канале шифруются.

## Итог

Боевой HTTP-клиент для парсинга выглядит так: `Session()` для куки, осмысленные заголовки, `timeout` у каждого запроса, `HTTPAdapter` с `Retry` для временных сбоев и `proxies` для смены IP. Запомни эти четыре кита — они будут в каждом твоём парсере. Закрепим навыки на реальных сервисах.

### Подсказка 1

Объект `Session` хранит куки между запросами внутри одной и той же сессии. После `s.get("https://httpbin.org/cookies/set?name=anya&role=student")` куки `name` и `role` осядут в сессии. Ответ `/cookies` в поле `json` содержит словарь `cookies`. Новая сессия не знает о куках первой — поэтому её ответ будет `{"cookies": {}}`.

### Подсказка 2

Заголовки передаются аргументом `headers=` в `requests.get()`. Сервер httpbin возвращает в ответе поле `headers` — словарь со всеми заголовками, которые он получил. Бери значения по ключам `accept`, `accept-language`, `user-agent`. Обрати внимание: в ответе ключи в нижнем регистре, даже если ты отправил их иначе.

### Подсказка 3

`Retry` из `urllib3` управляет повторами. `status_forcelist` — коды, на которые надо реагировать повтором. Когда попытки закончатся, `requests` бросит `ConnectionError` (внутри — `MaxRetryError`). Поймай общее `requests.RequestException`, чтобы накрыть и тайм-ауты, и сбои соединения.

### Подсказка 4

`timeout` — это лимит ожидания ответа. `httpbin.org/delay/5` отвечает через 5 секунд, поэтому `timeout=2` не успеет и поднимет `requests.Timeout`. Лови именно `requests.Timeout` (или общее `requests.RequestException`). При `timeout=10` ответ успеет, и ты увидишь `200`.

### Разбор 1

```python
import requests

# Первая сессия: получаем куки
s1 = requests.Session()
s1.get("https://httpbin.org/cookies/set?name=anya&role=student")

r = s1.get("https://httpbin.org/cookies")
print("Статус:", r.status_code)
print("Куки в сессии 1:", r.json()["cookies"])

# Вторая, новая сессия
s2 = requests.Session()
r2 = s2.get("https://httpbin.org/cookies")
print("Куки в сессии 2:", r2.json()["cookies"])
```

Разбор по шагам:

- `requests.Session()` создаёт контейнер, в котором `requests` автоматически сохраняет куки из каждого ответа и подставляет их в последующие запросы.
- Адрес `/cookies/set?name=anya&role=student` — это специальный эндпоинт httpbin: он «выдаёт» куки, перечисленные в query-параметрах, и перенаправляет. Куки оседают в сессии.
- `s1.get("https://httpbin.org/cookies")` возвращает JSON, в котором поле `cookies` — словарь с куки сессии. Мы увидим `{'name': 'anya', 'role': 'student'}`.
- `s2` — совершенно новая сессия. У неё нет кук, поэтому ответ будет `{'cookies': {}}`. Это наглядно показывает, зачем нужна сессия: без неё каждый `requests.get()` был бы такой же «пустой» визит, как у `s2`, и логин не работал бы.
- Комментарий в задаче должен объяснить именно это: куки живут внутри сессии и не передаются между разными сессиями.

### Разбор 2

```python
import requests

def make_headers():
    return {
        "User-Agent": "MyCourseScraper/1.0 (student@example.com)",
        "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8",
        "Accept-Language": "ru-RU,ru;q=0.9,en;q=0.7",
    }

r = requests.get("https://httpbin.org/headers", headers=make_headers(), timeout=10)
headers_seen = r.json()["headers"]
print("accept:", headers_seen["Accept"])
print("accept-language:", headers_seen["Accept-Language"])
print("user-agent:", headers_seen["User-Agent"])
```

Разбор по шагам:

- Функция `make_headers()` возвращает словарь — единое место, где определяются заголовки. Это удобно переиспользовать во всех запросах парсера.
- `headers=make_headers()` передаёт их в запрос; `timeout=10` страхует от зависания.
- `httpbin.org/headers` отвечает JSON, в котором поле `headers` — это ровно те заголовки, которые сервер реально получил. Сравнивая их с тем, что ты отправил, ты видишь, что ничего не потерялось и не исказилось.
- Обрати внимание: в ответе ключи написаны с заглавной буквы (`Accept`, `User-Agent`), хотя в словаре ты их писал так же. Если бы ты передал `accept` в другом регистре — сервер всё равно увидел бы `Accept`, потому что заголовки HTTP нечувствительны к регистру, но для чистоты лучше сразу писать канонический вариант.
- Такой трюк с «эхо» заголовков — отличный способ отладить свой клиент перед работой с настоящим сайтом.

### Разбор 3

```python
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry
import requests

s = requests.Session()
retry = Retry(total=2, backoff_factor=0.5,
              status_forcelist=[500, 502, 503, 504])
s.mount("https://", HTTPAdapter(max_retries=retry))

try:
    r = s.get("https://httpbin.org/status/503", timeout=10)
    print(r.status_code)
except requests.RequestException as e:
    print("Тип исключения:", type(e).__name__)
    print("Текст:", e)
```

Разбор по шагам:

- `Retry(total=2, ...)` говорит: в сумме сделай до трёх попыток (первая + два повтора). `backoff_factor=0.5` задаёт растущую паузу: 0.5 с, затем 1 с. Так клиент не долбит сервер без пауз.
- `status_forcelist=[500, 502, 503, 504]` — это коды «серверу временно плохо». При `503` urllib3 повторяет запрос сам, без нашего кода.
- Но `httpbin.org/status/503` всегда отвечает 503, поэтому после трёх попыток у нас закончатся повторы, и `requests` бросит `ConnectionError` (внутри неё — `MaxRetryError` с полезным текстом).
- Мы ловим общее `requests.RequestException` — родительский класс для всех ошибок `requests`, включая тайм-ауты и проблемы соединения. Это надёжнее, чем ловить конкретный тип.
- Здесь `code` 503 — это временная ошибка: сервер жив, но перегружен. Именно поэтому ретраи уместны. А вот для 404 или 403 повторять запросы бессмысленно — ресурс не найден или доступ запрещён насовсем. Поэтому в `Retry` включают только 5xx.

### Разбор 4

```python
import requests

try:
    r = requests.get("https://httpbin.org/delay/5", timeout=2)
    print(r.status_code)
except requests.Timeout:
    print("Тайм-аут: сервер не ответил за 2 с")

```

Разбор по шагам:

- `httpbin.org/delay/5` — учебный эндпоинт, который специально ждёт 5 секунд перед ответом.
- `timeout=2` меньше этой задержки, поэтому через 2 секунды `requests` прерывает ожидание и бросает `requests.Timeout`.
- Блок `except requests.Timeout` ловит именно этот случай и печатает понятное сообщение. Хороший парсер на месте `print` решил бы: пропустить страницу, подождать и повторить или записать в журнал ошибок.
- Второй запрос с `timeout=10` успевает дождаться ответа, и мы видим `200`.
- Запомни: тайм-аут — обязательный параметр в любом парсере. Без него одна зависшая страница остановит весь сбор данных навсегда.

### Разбор 5

```python
import requests

def fetch_page(url, session=None, timeout=15):
    if session is None:
        session = requests.Session()
        session.headers.update({
            "User-Agent": "MyCourseScraper/1.0 (student@example.com)",
            "Accept-Language": "ru-RU,ru;q=0.9,en;q=0.7",
        })
    r = session.get(url, timeout=timeout)
    return r.status_code, r.headers.get("Content-Type"), len(r.text)

for url in (
    "https://quotes.toscrape.com/page/1/",
    "https://books.toscrape.com/",
):
    status, ctype, length = fetch_page(url)
    print(f"{url} -> {status}, {ctype}, {length}")
```

Разбор по шагам:

- Функция `fetch_page()` инкапсулирует весь «ритуал» запроса: создание сессии, заголовки, тайм-аут. Парсеру остаётся только вызывать её и получать данные.
- Если `session` не передан, создаётся новая сессия, и в `session.headers` кладутся заголовки по умолчанию. Они теперь будут у каждого запроса этой сессии — не нужно передавать `headers=` каждый раз.
- Возвращается кортеж `(status_code, content_type, length)`. `r.headers.get("Content-Type")` достаёт тип содержимого (например `text/html; charset=utf-8`), `len(r.text)` — размер текста ответа в символах.
- Оба сайта — учебные полигоны для парсинга: `quotes.toscrape.com` (цитаты) и `books.toscrape.com` (книги). Они отдают обычный HTML, поэтому `Content-Type` будет `text/html`, а длина — несколько десятков тысяч символов.
- Такая обёртка — первый шаг к конвейеру сбора: она отделяет «сетевую» часть от логики извлечения данных, которой займёшься в следующих уроках.

- Потому что каждая сессия хранит свои куки независимо

* Правильный ответ: Потому что каждая сессия хранит свои куки независимо
