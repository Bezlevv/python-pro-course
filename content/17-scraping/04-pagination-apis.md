Редкий сайт отдаёт все данные одной страницей. Обычно их делят на страницы — это называется **пагинацией**. Парсер должен уметь пройти по всем страницам до конца и не застрять в бесконечном цикле. В этом уроке разберём три вида пагинации: по номеру страницы, через ссылку «Next» и через курсор — и заодно научимся брать данные прямо из API, минуя HTML.

## Пагинация по номеру страницы

Самый простой вид — параметр страницы в адресе: `?page=2`, `?page=3`. Так работают многие сайты и API:

```python
import requests

for page in range(1, 4):
    r = requests.get(
        "https://jsonplaceholder.typicode.com/todos",
        params={"_page": page, "_limit": 10},
        timeout=10,
    )
    items = r.json()
    if not items:
        break  # пустая страница — значит, конец
    print(f"Страница {page}: {len(items)} задач")
```

Ключевая идея: **стоп-условие**. Цикл идёт, пока страница не пуста. Пустой ответ — сигнал, что данные закончились. Если этого не проверять, цикл уйдёт в бесконечность или будет долбить сервер сотнями пустых запросов.

## Пагинация через ссылку «Next»

На HTML-сайтах часто нет нумерации в URL — есть только кнопка «Следующая страница». Проход по таким страницам мы уже подсматривали: берём ссылку, идём по ней, пока она есть:

```python
import requests
from bs4 import BeautifulSoup

base = "https://quotes.toscrape.com"
url = "/page/1/"
authors = set()

while url:
    r = requests.get(base + url, timeout=10)
    soup = BeautifulSoup(r.text, "lxml")
    for small in soup.select("small.author"):
        authors.add(small.get_text())

    next_link = soup.select_one("li.next a")
    url = next_link["href"] if next_link else None

print("Уникальных авторов:", len(authors))
```

Здесь цикл `while url:` идёт, пока есть следующая страница. `None` на месте ссылки завершает обход. Это второй стоп-условие.

## Пагинация в API: заголовок Link

API часто не показывают общее число страниц, а возвращают специальный заголовок `Link` — перечень ссылок на следующую/предыдущую/последнюю страницу:

```python
r = requests.get(
    "https://api.github.com/users/python/repos",
    params={"per_page": 5, "page": 1},
    headers={"User-Agent": "my-app"},
    timeout=10,
)
print(r.headers.get("Link"))
```

Ответ выглядит примерно так: `<https://api.github.com/user/...?page=2&per_page=5>; rel="next", ...`. Парсер заголовка разбирает его на отдельные ссылки и переходит по `rel="next"`. Это курсорная пагинация, о которой дальше.

## Курсорная пагинация

Курсор — это «закладка»: сервер не говорит «дай страницу 5», а даёт токен-курсор, который определяет позицию после последней выданной записи. Это удобно, когда данные постоянно меняются: вставка новой записи не сдвигает страницы. Пример — GitHub API с параметром `since` при перечислении репозиториев. Принцип один: запрашиваешь с курсором, получаешь порцию данных и новый курсор, повторяешь, пока порция не опустеет.

## Почему API лучше HTML

Если у сайта есть официальное API — используй его. Это быстрее (чистый JSON без HTML-мусора), стабильнее (разметка меняется, API — реже) и вежливее (сайт сам ожидает таких запросов). JSON превращается в Python-структуры одним вызовом `r.json()`:

```python
data = r.json()
print(data[0]["title"])  # заголовок первой задачи
```

## Защита от бесконечных циклов

Любой обход страниц должен иметь минимум две защиты:

1. **Естественный стоп** — пустая страница, отсутствие ссылки «Next», курсор-`None`.
2. **Искусственный лимит** — максимум страниц, например `max_pages=50`. Даже если на сайте что-то сломалось, программа остановится.

```python
MAX_PAGES = 50
for page in range(1, MAX_PAGES + 1):
    ...
```

### Разбор 1

```python
import requests

total = 0
all_items = []

for page in range(1, 100):
    r = requests.get(
        "https://jsonplaceholder.typicode.com/todos",
        params={"_page": page, "_limit": 10},
        timeout=10,
    )
    items = r.json()
    if not items:
        break
    all_items.extend(items)
    total += len(items)

print("Всего задач:", total)
for item in all_items[:3]:
    print("-", item["title"])
```

Разбор по шагам:

- `range(1, 100)` — защитная рамка: если что-то пойдёт не так (сервер перестанет отдавать пустые страницы), цикл всё равно остановится на 99-й странице.
- `params={"_page": page, "_limit": 10}` — JSONPlaceholder поддерживает пагинацию параметрами `_page` и `_limit`. Это имитация настоящих API.
- `r.json()` превращает ответ в список словарей. `if not items: break` — стоп-условие: пустой список значит, что данные закончились.
- `all_items.extend(items)` копит все задачи в одном списке; `total += len(items)` параллельно считает количество.
- JSONPlaceholder содержит 200 задач. По 10 на страницу — 20 страниц, последняя вернёт 10 задач, а 21-я — пустой список, и цикл завершится.
- Итог: `Всего задач: 200`, затем три первых заголовка. Так выглядит стандартный обход «страницы по номеру».

- `r.raise_for_status()` превращает ошибки HTTP в исключения — если API вернёт 403 или 404, мы сразу узнаем, а не будем разбирать пустой JSON.
- `if not batch: break` — пустая порция означает конец. Дополнительный признак: если `len(batch) < 100` — это последняя страница, но пустой список надёжнее.
- `repos.extend(batch)` собирает словари репозиториев; `repo["name"]` — имя (например `Python-2.x`, `python-docs-zh-tw`...).
- GitHub API без токена допускает ~60 запросов в час на IP. Наш обход тратит 2 запроса — в лимит укладываемся легко. Уважай лимиты: их обсуждаем в следующем уроке.

- На сайте 10 страниц, ~100 цитат и несколько десятков уникальных авторов. Множество отлично справляется с повторами.
- Это универсальный алгоритм обхода сайтов: «иди по Next, пока есть». Он не зависит от нумерации страниц в URL.

### Разбор 4

```python
import requests
from bs4 import BeautifulSoup

def collect_authors(max_pages=3):
    authors = set()
    for page in range(1, max_pages + 1):
        r = requests.get(f"https://quotes.toscrape.com/page/{page}/", timeout=10)
        soup = BeautifulSoup(r.text, "lxml")
        for small in soup.select("small.author"):
            authors.add(small.get_text())
        next_link = soup.select_one("li.next a")
        if next_link is None:
            break
        print(f"Обработана страница {page}")
    return authors

authors = collect_authors(max_pages=3)
print("Собрано авторов:", len(authors))
```

Разбор по шагам:

- `for page in range(1, max_pages + 1)` — жёсткий лимит итераций: параметр `max_pages` ограничивает глубину обхода.
- Внутри цикла после сбора данных проверяется ссылка «Next»: если её нет (`None`) — `break`, мы дошли до конца раньше лимита.
- Функция возвращает множество авторов. Вызов с `max_pages=3` обработает ровно три страницы, даже если сайт позволяет идти дальше.
- Зачем нужен искусственный лимит? Если на сайте сломается разметка (ссылка «Next» будет указывать сама на себя) или появится бесконечная лента, цикл без лимита будет работать вечно и положит сервер. Лимит — это предохранитель.
- Такая функция — переиспользуемый кирпичик: `collect_authors(3)` — быстрый сбор, `collect_authors(100)` — полный обход.

### Разбор 5

```python
import requests

def parse_link_header(header):
    result = {}
    if not header:
        return result
    for part in header.split(","):
        section = part.split(";")
        url = section[0].strip().strip("<>")
        rel = section[1].split("=")[1].strip('"')
        result[rel] = url
    return result

repos = []
page_url = "https://api.github.com/users/python/repos?per_page=5&page=1"
pages = 0

while page_url:
    r = requests.get(page_url, headers={"User-Agent": "my-app"}, timeout=10)
    r.raise_for_status()
    repos.extend(r.json())
    pages += 1
    links = parse_link_header(r.headers.get("Link"))
    page_url = links.get("next")

print("Пройдено страниц:", pages)
print("Собрано репозиториев:", len(repos))
```

Разбор по шагам:

- `parse_link_header()` разбирает заголовок `Link`. Каждая часть, разделённая запятой, выглядит так: `<https://...?page=2&per_page=5>; rel="next"`. `split(";")` делит её на URL и параметр `rel`, затем `strip("<>")` и `strip('"')` убирают обрамление.
- Результат — словарь `{"next": "...", "prev": "..."}`. Это стандарт RFC 5988, его используют GitHub, GitLab и многие другие API.
- `while page_url:` — переходим по `next`, пока он есть. GitHub отдаст ссылку на последнюю страницу без `next` — и цикл корректно завершится.
- `repos.extend(r.json())` копит репозитории. С `per_page=5` у `python` (~150 репозиториев) потребуется ~30 запросов — поэтому в реальном сборе лучше `per_page=100`.
- Так работает курсорная пагинация: клиент не угадывает номера страниц, а следует за ссылками, которые даёт сервер. Это самый надёжный способ в API.
