Чем образ (image) Docker отличается от контейнера (container)?
- Это синонимы
- Образ — неизменяемый шаблон, контейнер — запущенный экземпляр образа
- Контейнер — шаблон, а образ — запущенный процесс
- Образ существует только в Docker Hub
* Правильный ответ: Образ — неизменяемый шаблон, контейнер — запущенный экземпляр образа
Из одного образа можно запустить много контейнеров; контейнер — это работающий процесс со своим окружением.

Какая инструкция Dockerfile задаёт команду по умолчанию при запуске контейнера?
- RUN
- EXPOSE
- CMD
- COPY
* Правильный ответ: CMD
CMD определяет команду по умолчанию. RUN выполняет команды на этапе сборки, а EXPOSE лишь декларирует порт.

Зачем в docker-compose.yml нужен том (volumes) pgdata?
- Чтобы увеличить скорость сборки образа
- Чтобы данные базы данных сохранялись между перезапусками и пересозданиями контейнеров
- Чтобы скрыть пароли из конфига
- Чтобы ограничить доступ к сети
* Правильный ответ: Чтобы данные базы данных сохранялись между перезапусками и пересозданиями контейнеров
Том хранит данные вне файловой системы контейнера — они не исчезают при пересоздании контейнера.

В какой папке должны лежать workflow-файлы GitHub Actions?
- В корне репозитория
- В папке .github/workflows/
- В папке scripts/
- В папке config/
* Правильный ответ: В папке .github/workflows/
GitHub ищет workflow именно в .github/workflows/ — файлы из других папок игнорируются.

Что определяет блок on в workflow GitHub Actions?
- Тип машины для выполнения
- События (push, pull_request и другие), которые запускают workflow
- Список секретов
- Название workflow
* Правильный ответ: События (push, pull_request и другие), которые запускают workflow
Блок on перечисляет триггеры, по которым GitHub запускает конвейер.

Что гарантирует needs: test в job docker?
- Job docker выполнится до тестов
- Job docker запустится только после успешного выполнения job test
- Job docker получит доступ к секретам
- Job test запустится на той же машине, что и docker
* Правильный ответ: Job docker запустится только после успешного выполнения job test
needs задаёт зависимости между job: публикация образа произойдёт только при зелёных тестах.

Почему встроенный сервер Flask не подходит для продакшена?
- Он нарушает лицензию Python
- Он не рассчитан на высокие нагрузки и предназначен для разработки
- Он не умеет обрабатывать HTTP
- Он работает только на Windows
* Правильный ответ: Он не рассчитан на высокие нагрузки и предназначен для разработки
Встроенный сервер создан для удобства разработки; в продакшене приложение запускают через отдельный WSGI-сервер вроде Gunicorn.

Что делает флаг -w 4 в команде gunicorn?
- Задаёт тайм-аут запросов
- Запускает четыре рабочих процесса (воркера)
- Включает режим отладки
- Указывает количество соединений в очереди
* Правильный ответ: Запускает четыре рабочих процесса (воркера)
Воркеры обрабатывают запросы параллельно, что повышает пропускную способность приложения.

Зачем ставить Nginx перед Gunicorn?
- Чтобы заменить Gunicorn
- Чтобы отдавать статику, завершать SSL/TLS, балансировать нагрузку и передавать заголовки клиента
- Чтобы хранить базу данных
- Чтобы автоматически перезапускать приложение
* Правильный ответ: Чтобы отдавать статику, завершать SSL/TLS, балансировать нагрузку и передавать заголовки клиента
Nginx раздаёт статику напрямую с диска и проксирует динамические запросы на Gunicorn — Python не нагружается лишней работой.

Почему файл .env нельзя коммитить в git?
- Потому что он слишком большой
- Потому что в нём лежат секреты: пароли, ключи, токены
- Потому что git не поддерживает этот формат
- Потому что он мешает сборке образа
* Правильный ответ: Потому что в нём лежат секреты: пароли, ключи, токены
Публикация .env раскрывает секреты. В git кладут только шаблон .env.example с пустыми значениями.
